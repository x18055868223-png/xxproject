## 发布前

1. 核对目标为 xxproject 工作分支。备份当前代码、静态页、原卡、评审、尝试状态、预算、投影及现有缓存。
2. 安装打包的标准库模块、`run_astra_joint_shadow.sh` 和已封存的模型 JSON。服务器不得安装训练依赖。
3. 建立独立的 `/var/lib/astra-joint/v1.1` 研究目录并赋予运行用户权限；按 `joint.env.example` 配置 `/etc/signal-audit/joint.env`。不沿用 v1 的前向窗口、预测或模型；原 v1 目录保留。`JSONL_SOURCE` 使用原服务已经核验的生产原卡路径；不复制密钥。
4. 明确启动时点后，执行 `python3 astra_joint_shadow.py start-window --folder "$ASTRA_JOINT_ROOT"`。该操作持久保存固定 90 日终点，重复执行不重置。不要将本地演示目录或历史回放账本复制为前向账本。
5. 安装本目录 service/timer，核对路径与内存限制后才启用。首次手工运行检查请求账本、缓存、影子 manifest、原服务状态。第 30 日只查资料质量；第 90 日按冻结协议结案，不自动延长。

## 调用和资料边界

每市场每分钟最多一次请求，请求额度先落库再发出；自然卡统计复用缓存，不另抓行情，不增加 LLM 请求。参考报价保留原响应、深度、时间差和费用。没有报价只比较赔付，不能宣称净收益优势。

独立研究页通过 `?research=joint` 打开。自然卡统计在原单次 LLM 前可得时才进入该次解释；迟到资料只供显示。D–S、原权限、原响应与哈希不覆盖。

## 回退

停止并禁用新增影子 timer/service，移走或注释 `/etc/signal-audit/joint.env` 中的可选接入变量，再成套恢复旧代码和静态投影。保留新研究目录、请求状态、预测和到期结果；禁止删除失败或重置 90 日窗口。原卡及旧 LLM 额度无须迁移或清零。

## v1.1 验收口径

主要验收对象是自然 NR 接管卡；新价格事件继续独立记录，不消费自然卡共同截面模型。统计与联合意见先冻结，再收集一次共同四腿报价；迟到统计不补成当时已使用，不重跑 LLM。统计仅比较参考结构的赔付，期望赔付与 D–S 等级不合并。
