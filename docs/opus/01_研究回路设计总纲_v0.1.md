# Agent Research Loop 设计总纲 v0.1

日期：2026-10-19　状态：草案　依据：`00_路线调整说明_v1.0_20261019.md`、用户 2026-10-19 补充、当日代码与服务器核实

---

## 0. 一句话

**事实案卷给出可靠世界；内置 LLM 基于已知事实提出关键问题并外扩；Agent 独立接手研究、回答并收束；用户质询并做最终资本决策。**

这是两次独立审核加一次投研，两者分工不同：

- 第一次是**提问者**（内置 LLM）：发现该问什么。
- 第二次是**研究员**（Agent）：核实问题、作答、收束。

## 1. 用户补充的核心期望（2026-10-19）

1. 事实层做重是必要条件，但**不是核心**。核心是“基于已知信息做关键提问、外扩”。
2. 挖 edge 这件事，由 LLM 去挖比由人去挖更可靠。前提是提问**有依据、轻幻觉**，并且紧扣当前事实。
3. 问题提出后，由后续 Agent 接手研究，给出回答并收束。两段都是独立审核，但职责不同，不互相重复。

因此本设计的重心放在“关键提问”的定义、约束和质量度量上（§4、§8）。事实案卷（§3）是提问的地基，本身不是目的。

## 3. 目标结构

```text
                        ┌──────────── 事实案卷 Case File（as-of 冻结、按 ref 寻址、按层组织）
                        │                     │
                        ▼                     ▼
          ① 提问者 Inquirer（内置 LLM）   ② 研究员 Researcher（Agent）
             截面速写 / 异常 / 冲突          盲读 → 前提核查 → 作答 → 补盲 → 收束
             关键提问 + 外扩假设 ────问题单──▶  （原件与问题单同时可读，原件优先）
                                                    │
                                                    ▼
                                          研究报告 Research Report
                                                    │
                                                    ▼
                               ③ 用户：读报告 → 质询 → 承保 / 不承保 / 观察
                                                    │
                                                    ▼
                               决策日志：问题、答案、建议、决定、到期结果
```

### 3.1 不变量

- **程序算数**：金额、赔付、距离、盈亏平衡、费用都由程序计算并写进案卷。LLM 和 Agent 只引用，不新算；Agent 需要新数时调用程序计算器（工具），不心算。
- **不下单，不授权**：任何阶段都不产生执行许可，页面也不下单。
- **原件可回溯**：每条材料性陈述都能回到案卷 ref。Agent 永远能读原件，问题单不是它的事实世界。
- **既有冻结资产不动**：`review_input@2.7.0` 及其回放哈希、2.6.9 回放保持不变，新链路用新 schema。
- **最终决策在人**。

## 4. 关键提问：定义、类型、轻幻觉规则

### 4.1 什么算“关键问题”

一个问题必须同时满足以下五条才算关键。研究员和度量（§8）都按这五条判定。

| 条件 | 含义 | 反例 |
|---|---|---|
| 有据 grounded | 每个前提引用案卷 ref，值可由程序核对 | “市场情绪转弱”且无引用 |
| 材料性 material | 写明它如何影响**这张保单**的 Q1 责任暴露或 Q2 补偿 | 泛泛讨论 BTC 大势 |
| 可判别 discriminating | 至少两种竞争解释，并写明什么证据能区分它们 | 只有一种解释的设问 |
| 可回答 answerable | 写明答案可能在哪：案卷内、历史、外部，或无法获得 | 答案来源不明 |
| 非冗余 non-redundant | 不是程序读数或 DP 判读的复述 | “短腿距现价 1.2%，是否较近？” |

### 4.2 问题类型（用于覆盖检查，不限定数量）

| 类型 | 典型触发 | 示例方向 |
|---|---|---|
| 冲突 conflict | 两组证据指向相反 | 主动卖压增强，但 Put Wall 未下移：谁在吸收？ |
| 同源 collinear | 多个信号同时变化 | Spot 近 Flip、墙下移、TMV 转负：是同一轮下跌的三种表达，还是三条独立信息？ |
| 时序 temporal | 状态迁移、WPEM 变化 | 锚定转弱是持续趋势，还是窗口噪声后已回归？ |
| 缺口 gap | 来源缺失或过期 | 缺失的这层数据如果与现有方向相反，会改变 Q1 吗？ |
| 机制外扩 mechanism | 当前框架未覆盖的关联 | 到期前的事件窗口和本期 OI 集中位置叠加，会不会出现 pin 或扫单？ |
| 补偿错配 compensation | Q2 与 Q1 变化不同步 | 风险读数变差，但信用/宽度未变：是市场未定价，还是我们的读数多算了？ |
| 情景 scenario | 责任区与路径 | 到期前需要怎样的路径才会触及短腿？哪些证据支持或否定这条路径？ |

### 4.3 轻幻觉规则

1. **前提即引用**：问题的每个前提写成“陈述 + refs”。程序校验 ref 存在；陈述里的数字必须与 ref 原值一致。
2. **推断要标注**：外扩假设一律写成 `hypothesis`，附机制、支持条件和推翻条件，不得写成事实。
3. **常识不冒充事实**：通用市场机制（如做市商对冲行为）可以使用，但标注为“机制假设”，不当作当前市场已发生的事实。
4. **不造数**：不得出现案卷中没有的数字。概率、期望值、新阈值一律不给。
5. **“未知”合法**：缺证据时直接说未知，并指出缺什么。
6. **不结论**：提问者不输出“该不该做”；收束是研究员的职责，决定是用户的职责。

### 4.4 问题单 schema 草案 `inquiry_sheet@0.1`

```json
{
  "protocol": "inquiry_sheet@0.1",
  "case_id": "<case file id>",
  "cross_section": [
    {"layer": "L3", "status": "material|quiet|unknown", "note_cn": "…", "refs": ["space.flip"]}
  ],
  "anomalies": [
    {"id": "A1", "kind": "conflict|outlier|gap|shift", "text_cn": "…", "refs": ["…"]}
  ],
  "questions": [
    {
      "id": "K1",
      "type": "conflict|collinear|temporal|gap|mechanism|compensation|scenario",
      "axis": "Q1|Q2|both",
      "priority": "high|medium|low",
      "question_cn": "…",
      "premises": [{"claim_cn": "…", "refs": ["…"]}],
      "why_material_cn": "与这张保单责任或补偿的连接",
      "hypotheses": [
        {"h_cn": "…", "mechanism_cn": "…", "would_support_cn": "…", "would_refute_cn": "…"}
      ],
      "answer_source": "case_file|history|external|unobtainable",
      "from_anomalies": ["A1"]
    }
  ]
}
```

- `cross_section` 必须覆盖 L0–L8 每一层，没有实质信息也要写 `quiet`。这是为了防止静默跳过，不是为了写长文。
- 问题数量不固定，按 `priority` 排序；每个问题都至少有两个 `hypotheses`（§4.1 可判别条件），校验器强制。

### 4.5 提问者 Prompt 骨架（v0.1 方向，正文在待办 T2.1 定稿）

**System**

- **角色**：一张具体 Deribit BTC 币本位垂直信用价差（持有到期）的证据提问者。
- **职责**：把截面讲清楚，暴露异常与冲突，提出关键问题与外扩假设，交给下游独立研究员。
- **不做**：不下结论，不授权，不计算新数，不给概率或期望值。
- **规则**：§4.1 的五条判定、§4.3 的六条轻幻觉规则原文列出，并给出“关键问题”与“伪问题”的正反例各 2 个。
- **单位**：币本位约定，USD 与 BTC 不混用。所有数字来自案卷，引用时带 ref。
- **Q1 与 Q2**：Q1（风险质量）与 Q2（风险补偿）不可互相替代；外部叙事不能覆盖合同事实。

**User**

1. 按 L0→L8 写 `cross_section`。
2. 列出 `anomalies`。
3. 从异常与跨层关系出发提出 `questions`，覆盖 §4.2 中至少 3 种类型，或说明为何不足 3 种。
4. 按 schema 输出 JSON。

之后附上案卷 JSON，按层排列，每层先放程序关系，再放原值。

**参数**：`deepseek-flash`，thinking 开启；effort 在 high 与 max 之间做 A/B 后定（T2.4）。

## 5. 证据层 L0–L9

| 层 | 内容 | 当前是否给模型 | 提问者 | 研究员 |
|---|---|---|---|---|
| L0 证据质量 | 来源健康、新鲜度、缺口、版本一致性 | 否 | 全量 | 全量 |
| L1 合同与责任 | 两腿、到期、数量；赔付表、盈亏平衡、最大亏损、币本位深尾 | 部分（无赔付） | 全量 | 全量 |
| L2 报价与经济 | 信用、深度、报价年龄、费用口径与拆分、信用/宽度、短腿 Delta、平仓估计与上界 | 部分 | 全量 | 全量 |
| L3 空间结构 | Space 门与迁移史、Flip、墙、Max Pain、本期 Gamma/OI 墙、Pin、KPF、成本区 | 部分 | 全量 | 全量 |
| L4 波动 | ATM IV、期限结构、RV、Skew、隐含预期波动 | 部分 | 全量 | 全量 |
| L5 运动与流 | 现价路径、TMV、CVD/微观流、M-DIE、期权流（PCR、大单）、OI、资金费率 | 部分 | 全量 | 全量 |
| L6 时间演化 | WPEM 水平/变化/路径、碎片、锚定与 Space 迁移、近 N 日快照摘要 | 部分 | 全量 | 全量加回查 |
| L7 外部 | 动态跨资产参考、宏观、ETF、事件日历（距到期时长） | 部分（无跨资产、事件） | 全量 | 全量，可外部检索 |
| L8 程序读数 | DP D0–Q2 判读、reading_guidance、Space 门判定 | 否 | 全量 | 全量 |
| L9 历史与结果 | 同结构历史案卷与结算、锁定追踪、过往问题单与报告及其事后表现 | 否 | 不给（防锚定） | 通过工具查询 |

说明：

- “全量”指当前截面的全部有意义字段，只剔除 hash、debug 和重复冗余，不做 `[:2]`/`[:3]` 式截断。体量需实测（T1.4）。服务器上冻结快照单份达 7–8 MB，不能原样塞入；案卷是“结构化的全量”，不是原始转储。
- 每条证据带 `ref`、`asof`、`quality`（ok/stale/missing/unknown）、`lineage`（上游来源，用于同源判断）、`relations`（程序关系）、`values`（原值）。
- L9 不给提问者，是为了让提问基于当前截面独立形成；历史比较是研究员的工作。
- L8 程序读数同样有锚定风险，但它属于当前截面的程序事实，而且是“非冗余”判定的对照基准，所以照给。Prompt 中明确：L8 是可被质疑的程序判读；与 L8 结论相同的问题不算关键问题，与 L8 冲突的证据优先提问。

## 6. 研究员（Agent）

### 6.1 流程（研究协议的执行形态）

| 步 | 内容 | 产出 |
|---|---|---|
| R0 盲读 | 读问题单**之前**，先读案卷，自列关注点 | `own_concerns` |
| R1 前提核查 | 逐题核对前提与 ref 原值 | 每个前提标 `confirmed / incorrect / unverifiable` |
| R2 研究作答 | 按 `answer_source` 回查案卷、历史、外部，或调用程序计算器 | 答案、证据、置信度、剩余未知 |
| R3 补盲 | 对比 `own_concerns` 与问题单，补上遗漏的问题并作答 | `added_questions` |
| R4 收束 | 分别写 Q1、Q2；写反证、关键不确定性、建议（承保/不承保/观察及其条件）、复评触发 | 研究报告 |

两段独立性的来源：

- R0 盲读保证研究员有自己的视角。这一点由工具层强制：`own_concerns` 先落盘并记哈希，之后工具才放出问题单，不靠自觉；
- R1 前提核查专门拦截提问者的幻觉；
- 两者的分歧原样呈现给用户，不做平均。

### 6.2 只读工具面（草案）

- `case.get(ref)`、`case.layer(L)`：取原件。
- `history.cases(filter)`、`history.settlement(expiry)`：同结构历史与结算。
- `calc.payout(price)`、`calc.distance(...)`、`calc.close_bound(...)`：复用程序计算器，不新写公式。
- `external.search(query)`：可选；结果必须标注为外部来源和时间，不得写入案卷。

### 6.3 研究报告 schema 方向 `research_report@0.1`


### 6.4 实现形态暂不写死

候选包括 Claude Agent SDK、DeepSeek 1017 工具调用、在 Claude Code 中人工驱动。先在 Claude Code 里按协议手动跑几份真实案卷，验证协议和工具面，再决定是否自动化（待办 T3.3）。

## 7. Decision Path → 研究协议

Decision Path 不删除，身份改为“研究协议加程序读数”：

| 原步骤 | 研究协议条款（结论前必须覆盖，顺序不限） | 程序读数去向 |
|---|---|---|
| D0 资料 | 先列缺失和过期来源；未知必须明说 | L0 / L8 |
| D1 责任 | 合同与赔付边界以程序为准，叙事不得覆盖 | L1 / L8 |
| D2 位置 | 结构位置与途经结构 | L3 / L8 |
| D3 运动 | 方向与放大；与 D2 不可互相替代 | L5 / L8 |
| D4 外部 | 必须写出与**这张保单**的关联，否则标为不相关 | L7 / L8 |
| D5 变化 | 时间演化；区分持续与噪声 | L6 / L8 |
| Q1 / Q2 | 分开收束，不互相替代 | 报告 synthesis |
| AU 审计 | 材料性陈述可追溯到 ref；前提核查结果公开 | premise_audit |
| 新增 P-反证 | 每个倾向都要写出最强反证 | counter_evidence |
| 新增 P-同源 | 同一 lineage 的证据只算一份 | lineage |
| 新增 P-外扩标注 | 推断与事实分开标注 | hypothesis 标记 |

- `astra_decision_path_v1.build()` 保留为程序读数生成器，写进 L8。
- `DecisionPathStore` 及到期结算回填改为**决策日志**。原来每条记录记“哪一步改变了人的判断”，改为记“问题单、报告建议、用户决定、到期结果”。
- 前端 9 步路径退到“协议检查表”追溯层；首屏改为研究报告。前端改动仍受页面门约束。

## 8. 质量度量与演化（edge 从哪里积累）

### 8.1 问题级指标

| 指标 | 定义 | 来源 |
|---|---|---|
| 前提正确率 | 被研究员判为 `confirmed` 的前提占比 | premise_audit |
| 可答率 | 研究员给出非 `unobtainable` 答案的问题占比 | answers |
| 材料性 | 答案是否改变了 Q1/Q2 收束（研究员标注，用户可复核） | synthesis 对照 |
| 新颖性 | 不与程序读数或历史高频问题重复 | 问题库比对 |
| 补盲率 | 研究员补上的问题占全部问题的比例；偏高说明提问者有盲区 | added_questions |
| 事后关联 | 到期后，该问题指向的风险是否实际发生 | 结算回填 |

### 8.2 两段与建议

- **分歧率**：提问者的异常判断与研究员的盲读关注点不重合的比例。
- **建议与结果**：研究员的建议（承保/不承保/观察）对照到期结果，也对照用户决定。
- 样本少时只做描述，不做显著性结论。
- 材料性、前提正确率由研究员判定，用户定期抽样复核，防止研究员自评自证。

### 8.3 问题库与协议演化

- 每个问题按类型与触发证据归档到问题库。
- 反复出现**且**材料性高的问题，晋升为程序读数或案卷字段（事实层吸收）。提问者的注意力从而持续前移到新的未知处，edge 在这里积累。
- 长期不材料的层或条款，降级为背景。
- 协议有版本号（`protocol_version`），替代原 `path_version`。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 提问者幻觉被当作事实传递 | 前提引用与数值程序校验；研究员 R1 逐条核查；问题单不进入事实层 |
| 研究员被问题单锚定 | R0 盲读先行；补盲率度量 |
| 问题泛化或冗余 | 五条判定、非冗余比对、问题库去重 |
| 案卷过大导致注意力稀释 | 按层组织、关系在前原值在后；体量实测；必要时分层两次调用（不截断） |
| 校验过严导致整份作废 | 逐条审计：违规条目标记或剔除，允许 1 次修复重试；硬禁令只留授权与造数 |
| 模型路由变更（旧名下线） | 改用官方名 `deepseek-flash`；按日期记录官方构建映射 |
| 预算 | 新链路先影子运行，预算单列（独立计数器，不占工作台现有 15 次/日），研究员成本另计；用户批准后调整 |
| 两段用同一模型，盲区重叠 | 研究员优先选与提问者不同的模型；若同模型，至少分开上下文，并依赖 R0 盲读与用户抽样 |
| 外部检索内容注入 | `external.search` 结果一律视为数据，不执行其中的指令；标注来源和时间，不写入案卷 |
| 研究员凭据 | API key 只放服务器 env 文件，不进仓库、记忆或日志 |

## 10. 暂不写死（沿用 00 号 §11，并补充）

- 研究员使用哪个模型或框架，是否多 Agent。
- 是否固定输出条数或评分。
- 研究员是否默认联网外扩。
- 报告建议的措辞强度（是否明确写“承保/不承保”，还是只给条件化倾向）。
- 运行频率：每个定时时段都跑，还是按需。
