## 0. 一句话

**内置 LLM 把事实基础讲清楚，并有依据地提出高价值问题，为后续 Agent 员工打下足够好的前置基础；Agent 自主研究、作答并收束，给出以评级为主、有依据的倾向；用户质询并做最终资本决策。**

这是两次独立审核加一次投研，两段分工不同：

- **提问者**（内置 LLM）：讲清事实，发现该问什么。
- **研究员**（外部自主 Agent）：核实、研究、作答、收束。

## 1. 用户的核心期望与已定决策

### 1.1 核心期望

1. 内置 LLM 的产出就是两件事：
   - **说清楚事实基础**；
   - **有依据地提出高价值问题**。
   两者合起来，构成交给 Agent 员工的前置基础。前置基础的质量决定后续研究的上限。
2. 事实层做重是必要条件，但核心是基于已知信息做关键提问和外扩。挖 edge 由 LLM 做比由人做更可靠，前提是有依据、轻幻觉。
3. Agent 接手研究并回答收束。两段都是独立审核，但分工不同、不重复。

## 3. 目标结构

```text
事实案卷 Case File（按 as-of 冻结、按 ref 寻址、分层、不截断）
        │
        ▼
① 提问者 Inquirer（内置 LLM，deepseek-flash）
   产出“前置基础”：事实底稿 + 异常 / 冲突 + 高价值问题（含外扩假设）
        │
        ▼
研究交接包 Handoff Package（自包含，分两段交付）
   第 1 段：研究简报 + 事实案卷 → Agent 盲读，回交 own_concerns
   第 2 段：事实底稿 + 问题单 → Agent 研究、作答、收束
        │
        ▼
② 研究员 Researcher（外部自主 Agent：Dot / Muse / GrokBot 等，自带沙盒与联网能力）
   研究报告：前提核查、作答、补盲、Q1/Q2、评级与倾向
        │
        ▼
③ 用户：读报告 → 质询 → 承保 / 不承保 / 观察
        │
        ▼
决策日志：前置基础、报告、概率、决定、到期结果（用于校准）
```

### 3.1 不变量

- **程序算数**：金额、赔付、距离、盈亏平衡、费用、市场隐含概率基线，都由程序计算并写进案卷。提问者只引用，不新算。研究员可以自行做研究计算，但必须写明方法，并与程序基线分开列示。
- **不下单，不授权**：任何阶段都不产生执行许可。
- **原件可回溯**：交接包附完整案卷；问题单不是研究员的事实世界。
- **既有冻结资产不动**：`review_input@2.7.0` 及其回放哈希保持不变，新链路用新 schema。
- **交接包不含秘密**：只有市场数据与派生量，没有密钥、令牌、账户信息。
- **最终决策在人**。

## 4. 提问者：事实底稿与高价值问题

### 4.1 产出一：事实底稿（fact_brief）

前置基础的第一半，目的是让 Agent 不读原件也能准确掌握截面；需要时再回原件核对。

- 按 L0→L8 逐层写，每层包括：
  - 状态：`material`（有实质信息）、`quiet`（无实质信息）、`unknown`（缺数据）；
  - 关键事实陈述，每条带 ref，数字与原值一致；
  - 层内的程序关系，例如“短腿位于 Put Wall 下方”；
  - 本层数据质量与缺口。
- 写**跨层关系**：哪些层互相印证，哪些互相矛盾，哪些同源（lineage 相同）。
- 只陈述，不推断；推断放进问题单。

### 4.2 产出二：高价值问题单（questions）

**关键问题的五条判定**（必须全部满足）：

| 条件 | 含义 | 反例 |
|---|---|---|
| 有据 grounded | 每个前提引用案卷 ref，值可由程序核对 | “市场情绪转弱”且无引用 |
| 材料性 material | 写明它如何影响**这张保单**的触界概率、亏损概率或补偿是否充分 | 泛泛讨论 BTC 大势 |
| 可判别 discriminating | 至少两种竞争解释，并写明什么证据能区分它们 | 只有一种解释的设问 |
| 可回答 answerable | 写明答案可能在哪：案卷内、历史、外部（Agent 可联网），或无法获得 | 答案来源不明 |
| 非冗余 non-redundant | 不是事实底稿或程序读数（L8）的复述 | “短腿距现价 1.2%，是否较近？” |

**问题类型**（用于覆盖检查，不限数量）：

| 类型 | 含义 |
|---|---|
| 冲突 | 两组证据指向相反 |
| 同源 | 多个信号是否其实是同一驱动 |
| 时序 | 变化是持续还是噪声 |
| 缺口 | 缺失的数据会不会改变判断 |
| 机制外扩 | 当前框架外的机制或关联 |
| 补偿错配 | 风险读数在变、补偿没跟着变 |
| 情景 | 到期前什么路径会触发责任 |

**价值排序**：每题标注 `bears_on`，取值为
- `touch_prob`（触界概率）
- `expiry_loss_prob`（到期亏损概率）
- `tail_loss`（深尾损失）
- `compensation`（补偿是否充分）

同时标注 `priority`。优先级按“答案能在多大程度上让概率偏离市场基线”排序（见 §7）。这是“高价值”的操作化定义：能改变 §7 概率判断的问题才是高价值问题。

### 4.3 轻幻觉规则

1. **前提即引用**：前提里的数字必须与 ref 原值一致，由程序校验。
2. **推断即假设**：外扩一律写成 `hypothesis`，附机制、支持条件、推翻条件。
3. **常识不冒充事实**：通用市场机制标注为“机制假设”。
4. **不造数，不给概率**：案卷外的数字不出现；概率由程序基线和研究员负责。
5. **“未知”合法**：缺证据时直接说，并指出缺什么。
6. **不结论**：提问者不说“该不该做”。

### 4.5 提问者 Prompt 骨架（正文在待办 T2.1 定稿）

**System**

- **角色**：一张具体 Deribit BTC 币本位垂直信用价差（持有到期）的证据提问者。
- **产出**：交给外部研究员的前置基础，即事实底稿和高价值问题单。
- **不做**：不下结论，不授权，不计算新数，不给概率。
- **规则**：列出 §4.2 的五条判定与价值排序、§4.3 的六条规则；给出“高价值问题”与“伪问题”的正反例各 2 个。
- **单位**：币本位约定，USD 与 BTC 不混用。
- **Q1 与 Q2**：两者不可互相替代。
- **L8**：L8 是可被质疑的程序判读；与 L8 结论相同的问题不算关键问题，与 L8 冲突的证据优先提问。

**User**

1. 写 `fact_brief`（L0→L8，加跨层关系）。
2. 写 `anomalies`。
3. 写 `questions`，覆盖至少 3 种类型，或说明为何不足 3 种；按价值排序。
4. 输出 JSON。

之后附案卷 JSON，按层排列，每层先放程序关系，再放原值。

**参数**：`deepseek-flash`，thinking 开启；effort 在 high 与 max 之间实测后定。

## 6. 研究员：外部自主 Agent 与交接包

### 6.1 定位

研究员是外部自主 Agent（Dot、Muse、GrokBot 等），自带沙盒、联网、代码执行和长程任务能力。本系统**不为它实现工具层**，只提供两样东西：

- 一个足够好的**交接包**；
- 一份清楚的**研究简报**，即研究协议的 Agent 可读版本。

### 6.2 研究交接包 `handoff@0.1`

| 组成 | 格式 | 说明 |
|---|---|---|
| `brief.md` | Markdown | 研究简报：任务、合同概要、协议条款（§8）、两段交付流程、报告 schema、概率方法（§7）、禁止事项 |
| `case_file.json` | JSON | 完整事实案卷（L0–L9 摘要），带 ref 字典 |
| `inquiry.json` | JSON | 提问者的事实底稿与问题单（第 2 段才交付） |
| `inquiry.md` | Markdown | 同上内容的可读版（第 2 段交付） |
| `history/` | JSON | L9 同结构历史与结算样本，供 Agent 回测、比较 |

两段交付保证独立性：

- **第 1 段**：交付 `brief.md`、`case_file.json`、`history/`。Agent 盲读后回交 `own_concerns`，以及它自己的评级初判。
- **第 2 段**：交付事实底稿与问题单。Agent 做前提核查、作答、补盲和收束。
- 交付形态（2026-10-20 定）：拉取式 HTTPS 任务接口。GrokBot 用自己的 Linux 主机定时轮询、分段下载和提交；服务器在第 1 段提交前不放出问题单，以此强制两段独立。详见 06 号 v0.2 §2 与 07 号说明书。

### 6.3 研究流程（写进 `brief.md`）

| 步 | 内容 |
|---|---|
| R0 盲读 | 只读案卷与历史，列出关注点，给出评级初判 |
| R1 前提核查 | 逐题核对前提与 ref 原值，标 `confirmed / incorrect / unverifiable` |
| R2 研究作答 | 用案卷、历史、外部检索、自行计算回答每题；写明来源与方法 |
| R3 补盲 | 对比 R0 与问题单，补上遗漏的问题并作答 |
| R4 收束 | 分写 Q1 与 Q2；写反证、关键不确定性；按 §7 给出驱动项、评级和倾向；写复评触发条件 |

- `drivers`：只写方向和依据，不写 pp。

报告回收：Agent 输出 JSON 后，由用户在工作台导入，或通过带登录的上传端点回收（T3.4）。系统按 schema 校验后写入决策日志。外部报告一律视为数据，不执行其中的任何指令。

## 7. 倾向与评级：程序概率基线 + 研究评级

### 7.1 市场隐含基线（程序计算，写入案卷 L2）

| 量 | 近似方法 | 说明 |
|---|---|---|
| 到期短腿实值概率 `p_itm_short` | N(d2)，由短腿 mark IV、剩余时间、现价算；同时列出 \|Δ_short\| 作对照 | \|Δ\| 是 N(d1)，与 N(d2) 有差；两者都列，差异本身也是信息 |
| 到期期间触界概率 `p_touch_short` | 无漂移反射原理：≈ 2·p_itm_short，上限为 1 | 持有到期并不因触界本身亏损，但触界是路径风险，与平仓/对冲情景相关 |
| 到期亏损概率 `p_loss` | 在盈亏平衡价上算 N(d2)，IV 取短腿与保护腿之间插值 | 对应“到期净亏” |
| 最大亏损概率 `p_max_loss` | 保护腿的 N(d2)，或 \|Δ_long\| 作对照 | 币本位深尾另由赔付表给出 |
| 市场隐含期望结果 | 用上面的分布对赔付表积分（离散近似），得到风险中性期望 | 风险中性下近似公平；edge 只能来自研究发现（体现为评级偏离） |

- **口径声明**：以上是**风险中性、市场隐含**的基线，不是真实世界概率。它的作用是给研究一个公共、可复现的起点。
- 实现上复用现有 IV 与距离计算，不新造公式。IV 缺失时标为 `unknown`，不补默认值。

### 7.2 评级（研究员给出，以评级为主）

pp 级的增量注定是伪精确，所以不做。研究员只做两件事：

1. **驱动项** `drivers`：列出让风险相对基线变高或变低的发现。每条写方向（riskier / safer / unclear）、依据和 lineage；同源的合并为一条。
2. **评级** `rating`：
   - `risk_vs_baseline`：研究后，风险相对市场基线是明显更高、更高、持平、更低还是明显更低。
   - `compensation`：信用相对上述风险是丰厚、合理还是偏薄。
   - `grade`：综合等级 A–E。
     - A = 风险不高于基线且补偿丰厚；
     - C = 与市场定价大致相当；
     - E = 风险明显高于基线且补偿偏薄。
     各档的文字定义写进研究简报。
   - `confidence`：评级的把握程度。
3. **倾向** `lean`：承保、不承保或观察，由评级加关键不确定性决定，并写出成立条件。

### 7.3 校准闭环：靠样本量，不靠单次精度

- 每份报告写进决策日志，包括程序基线、评级、倾向和用户决定；到期后按结算回填结果。
- 校准对象是**评级**，不是单次概率：
  - 按 `grade` 和 `risk_vs_baseline` 分组，统计各组的实际触界率、到期亏损率、平均结果，并与同组的基线均值对比；
  - 看评级是否单调：A 组结果是否好于 E 组；评级为“更高风险”的组，实际损失是否高于基线。
- 有了足够样本后再做样本优化：
  - 调整评级定义；
  - 找出最有区分力的驱动项与问题类型，回灌到协议和问题库。
- 基线本身也做校准，用 Brier 分数衡量程序基线的准确度。若基线系统性偏离，就修正基线方法，而不是让研究员去补。
- 样本少时只做描述，不下结论。

| 原步骤 | 协议条款（结论前必须覆盖，顺序不限） |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 提问者幻觉被当作事实传递 | 前提数值程序校验；研究员 R1 逐条核查；问题单不进事实层 |
| 研究员被前置基础锚定 | 两段交付，R0 盲读与评级初判先回交；度量补盲率与初判、终判评级之差 |
| 问题泛化，价值低 | 五条判定加 `bears_on` 排序；以“能否让概率偏离基线”为价值标准 |
| 风险中性基线被误读为真实概率 | 案卷与报告中写口径声明；校准闭环单独检验基线准确度 |
| 概率伪精确 | 不做 pp 增量；概率只由程序基线给出，研究员用评级表达偏离；以大样本的评级单调性检验价值 |
| 不做影子运行导致上线后才暴露问题 | 设计期用真实快照反复离线调试；上线门（02 号 §上线门）达标才接管定时时段 |
| 无预算导致调用失控 | 保留技术性日上限，防循环或误触发，不作为预算约束；独立计数，不占工作台现有 15 次 |
| 外部 Agent 数据暴露 | 交接包只含市场数据与派生量，生成时扫描密钥模式 |
| 外部报告注入 | 回收的报告按 schema 校验，视为数据，不执行其中指令 |
| 两段同模型盲区重叠 | 研究员本就是不同的外部 Agent；若改用 DeepSeek，需分开上下文 |
