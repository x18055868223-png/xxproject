# 最小决策链、不适合做提醒与锁定快照补全 v0.1

日期：2026-10-27　作者：Claude　状态：用户 10-27 同意按建议实施（不加“默认不做”字样；对确实不适合做的情况提醒要更好；锁定快照补齐市场背景并加入本期 Pin 等价位）。本地预览待用户确认。

## 1. 第一性：决定做不做的是什么

不是补偿高低。权利金高，要么因为前方波动大（公允成本同步变高，差额不变），要么因为对面有知情买方（差额为负）。补偿水平和优势没有可靠的因果联系。

决定做不做的是：**我实际能成交的价格，减去这份风险此刻的公允成本，是否为正；且这个差额不是因为对手知道我不知道的东西。**

- 研究约束：平均看市场价格接近公允，扣费前优势约等于费用加点差（16、17 号）；前 14 张案卷按买卖价成交的净信用只有两腿标记价差的 69–86%，每次都低于市场估价。
- 因此能控制的只有两件事：哪天不做（避开逆向选择），以什么价格做（成交价回到公允以上）。

## 2. 最小决策链（核验路径 dp-2026-10-27.1）

| 步 | 问题 | 内容 | 来自旧步 |
|---|---|---|---|
| V 否决 | 有没有不适合做的理由？ | 否决项与提醒，每条带数字、为什么、解除条件；一行“检查项”列出全部检查及状态 | D0、Q1、T 的否决层、D2 的窄/已进入 |
| R 风险 | 要扛多少、什么时候来？ | 合约一行；缓冲；时段与窗口；事件；方向读数进背景 | D1、D2、T、D4、D3 |
| P 价格 | 什么价格才值得做？ | 保留价 = 两腿标记价差 + 费用；对比按买价可得与两腿中间价 | Q2 |
| PL 预案 | 被触及时你会怎么做？ | 持有到期 / 触及即平仓 / 平一半 / 这段时间盯不了 | H |
| AU 审计 | 不变 | | AU |

- 旧步骤仍在读数里计算（案卷、旧会话、q1_items 都不受影响）；新会话只显示五步。旧会话按自己的步骤显示，行为不变。
- 结论“锁定追踪”可以填挂单价（两腿合计信用，BTC，默认填保留价向上取整）和有效时长；低于保留价时提示“即使成交，净收也低于市场估价”。挂单价只是记录，页面不下单。
- 选“低于保留价也愿意做”需要写理由，相当于旧 Q2 的“有更好的理由”。
- 锁定详情显示“核验时的承诺”：挂单价、保留价、有效期，以及按 1 分钟采样判断市场买价（短腿买价 − 保护腿卖价）是否在有效期内达到挂单价。达到为“可确认成交”；未达到只能说“被动成交无法确认”。

**刻意没做的：**按时段加权的缓冲数字。本期自身的标记 IV 已经为剩余时段定价，再按时段加权会重复计算；保留现有“剩余时段忙碌度 … 倍”一行。

## 3. 不适合做的提醒

`tools/astra_unsuitable_v1.py`（`unsuitable@0.1`）是唯一的规则来源，核验路径 V 步与保单卡共用：

| 项 | 类型 | 何时 | 依据 |
|---|---|---|---|
| 资料不完整 | 否决 | 报价缺口、深度不足、报价过旧等 | 读数不完整时其余判断不可靠 |
| 近端倒挂 | 否决 | entry_warnings 触发 | 阈值未验证，只作否决；“一种解释是…（未检验）” |
| 保费突然变厚 | 否决 | entry_warnings 触发 | 同上 |
| 缓冲窄 / 已进入 | 否决 | < 0.25 倍到期前预期波动 | 标准 0.35Δ 约 0.4 倍；阈值未验证 |
| 中间价也不够市场估价 | 提醒 | 两腿中间价 < 保留价 | 成本差 B，能否成交 C（17 号 §6） |
| 保护腿盘口空或过宽 | 提醒 | 买价为 0 或点差 ≥ 中间价 50% | 标记价可能失真，保留价不可靠 |

- 保单卡：有否决时显示“不适合做 · 否决 N 项”，逐条给出数字、为什么、解除条件；只有提醒时显示“提醒 N 项”；都没有时显示“未见否决项（这不是做的理由）”。页面顶部的前置条件横幅同时点名哪一侧现在不适合做。
- 不出现“默认不做”字样，不给概率，不把方向读数当理由。

## 4. 锁定快照补全

**根因：**10-15 起（323ae07），后台只为已锁定合同组装证据层（WPEM）。锁定那一刻取的是未组装的展示点，所以锁定详情“市场背景与两问摘要”的锁定时一列全部是“未记录”。

**修复：**

- 锁定前为这一张展示快照组装证据层（`_lock_ready_point`），快照本身不变；组装失败不阻止锁定。
- 旧锁定（10-15 之后的 6 条）：市场背景 6 行由锁定时快照里的市场事实重算，标 `compat_backfill_applied` 与来源，页面注“由锁定时市场事实重算”；只能由证据层生成的行（两问摘要、证据关系、观察窗口）标“锁定时未生成”。
- 本期结构：新模块 `astra_lock_levels_v1.py`（`lock_levels@0.1`，约 0.7 KB）在锁定时与每个采样点记录本期 Pin、Gamma 墙、持仓墙、前三大 Gamma、本期最大痛点、翻转位、链上持有者成本、KPF 区间；锁定详情新增“本期结构（锁定时 vs 最新）”表，含距短腿的百分比。旧锁定没有这部分，显示“锁定时未记录”，不回填。

## 5. 审查与修订

一次后端独立审查（1 项必须修、5 项建议修），已全部处理：

- 案卷（以及提问模型的输入）只保留旧的组件步骤，不放入 V/R/P/PL，模型输入不变，无需金丝雀。
- 锁定时组装会让每次请求的快照点不同：同一请求键的并发重试改为返回第一次的结果，而不是报错。
- 结算后会话文件被清理，承诺改从结论记录读取，锁定详情仍能显示挂单价与预案。
- 核验路径 P 步与保单卡的费用口径统一为“全部持有费用”，不再退回到只扣入场费。
- 研究归档保留新字段 `v_items`、`limit`、`plan`。
- 倒挂与变厚的“为什么”改为“一种解释是…（未检验）”，不把机制说成事实。
