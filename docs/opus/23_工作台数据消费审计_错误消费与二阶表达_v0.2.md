# 工作台数据消费审计：错误消费与二阶表达 v0.2

日期：2026-10-26　作者：Claude　状态：用户 10-26 同意实施 P1–P3（② 不做事先登记，直接作描述）；核验路径的步骤不动

**v0.2 更正：**v0.1 建议把业务层移到背景层前面，撤回。“事实在前”是既定设计：不是每期都承保，先看市场事实，再看保单。本稿只审两件事：

1. 数据有没有被**错误地消费**（读成了证据不支持的结论），或者放在了不合用途的位置。
2. 哪些数据组合成二阶表达后，能产生**真正的信息增量**。

**方法：**
- 三路只读调查：
  - 页面数据清单：位置、呈现方式、重复情况；
  - 读视图字段对照：前端有没有用到；
  - 16–22 号文档的证据分级。
- 实页浏览，并逐条抽查关键结论。

## 1. 错误消费

### 1.1 核心发现：研究撤回的读法只撤到了核验路径，事实层还保留着

20 号把一批读法从核验路径中删除或降级，依据是 16、17 号的研究；但事实层（五要素、背景卡）还在用原来的读法，而且带颜色。事实层的职责是陈述事实，现在却在给结论：

| 位置 | 现在的读法 | 研究结论 | 应改为 |
|---|---|---|---|
| 五要素 · 空间位置（`factors.js:174-175`） | 每侧“有利 / 不利”，绿 / 红色 | X：“空间位置相对有利”依赖周度和 0DTE 的市场口径墙，不属于本合约（17 §3.4）；核验路径已删 | 只陈述：沿不利方向先遇到什么价位、属于哪个口径；不给有利或不利，不上色 |
| 五要素 · Gamma 体制（`factors.js:69`） | “正 Gamma 钉住（对冲逆势，波动倾向收敛）” | GEX 不带符号，钉住还是加速判断不了（17 §7.2）；核验路径已删绿色读法 | “正 / 负 Gamma（信号层口径，不区分做市商方向）” |
| 五要素 · 宏观环境与外部资本（`factors.js:157,166,328`） | “温和顺风 / 逆风”标题；涨跌按利好、利空着色 | 宏观方向已从核验路径删除；公开信息已计入一天期报价（B，17 §2.2） | 数值和变化用中性色；标题写读数本身，不写顺风或逆风 |
| 五要素 · 量价路径、主动成交 | “强偏空”“买方略强”等标题；路径效率按 0.35 阈值着色 | C/X：同源，不能用来判断背离责任区（17 §2.4）；15 分钟走势无检验过的预测力（20 §6.2） | 读数保留，标题改为中性描述，去掉阈值着色 |
| 资金与慢背景 · 期权情绪 | IV 分位带标尺 | X：一天期 IV 分位无区分度，不作页面信号（16 号第 8 条） | 一行文字，不加标尺 |
| 顶栏 · 锚点 N/100 | 常驻指示灯，带颜色 | 空间门自 10-13 起只作评价；6 天快照状态一直不变 | 移出顶栏，保留在审计区 |
| 锁定详情 · “锁定时的依据，现在怎样” | 以 Gamma 体制、流向、锚定作为锁定的依据，逐条判断“仍成立 / 已不利” | 这些读法是 C/X，本来就不该是锁定的依据 | 依据只列有证据的项：缓冲（几倍预期波动）、补偿、时段与路径；其余移到“背景变化” |

**这是错误消费，不是摆放问题。**用户按“事实在前”的流程读页面，最先读到的正是这些已被撤回的结论，而且带颜色。这会让核验路径刻意去掉的方向叙事在事实层重新进入判断。这与用户 10-26 对自己阅读流程的担心（“方向为中心”）是同一个问题。

### 1.2 业务层：补偿用错了量

承保卡片的补偿只显示**毛信用占宽度**。这个量不扣费，也不对照市场估价，回答不了“给的钱够不够”。而下面这些量读视图里都已经算好，却没有用到：

- `economics.net_credit_after_fee_*`（扣费后净信用）；
- `decision_reduction` R1（对市场估价的差额：成交口径成本、费用）；
- `decision_reduction` R3（保护腿处净亏、币本位尾部）；
- `market_marks`（两腿 mark 价与 mark IV）。

例（当前 Put）：扣费后净信用约 131 美元，比市场估价低约 61 美元；保护腿处净亏约 1,943 美元。卡片上看不到这三个数。

### 1.3 同一概念多套口径，页面不说明

- 同一合约的预期波动有 4 个值：卡片与地图约 ±1.65%（gexmonitor IV 37.35）；`spatial_position` 1.656%；`expiry_gamma` ±1.58%（Deribit mark IV 35.58）；核验路径 D2 ±1.56%（IV 35.2）。
- “距离为几倍预期波动”有 2 个值：0.630 与 0.663。

D2 的“窄 / 标准”分档在边界附近会因此翻转。需要后端统一为本合约自己的 ATM IV，并在页面写明来源。

### 1.4 位置不合用途（在现有层次之内）

- **持有中的条件剩余风险**：例如“若到 hh:00 仍未触及：之后触及约 a%，越过约 b%”（17 §4.1，B）。它只在核验路径 H 步、而且只在开启核验会话时出现；锁定详情里没有。持有管理恰恰发生在锁定之后。
- **盈亏平衡距离**（价格、% 与占预期波动的比例）只能悬停地图才看到。
- **事件**对一天期合约的作用只是一个高波动窗口（B：已计入报价）。时段条没有标出事件所在的小时，事件放在单独一屏。这是摆放问题，不影响判断。

## 2. 二阶表达：什么样的组合才有信息增量

### 2.1 判据

一个组合值得做，要同时满足四条：

1. **回答一个任何单个分量都回答不了的问题。**只是把几个数排在一起，不算增量。
2. **组合规则来自机制或证据**，不是拍出来的权重。
3. **不重复计数。**例如期权报价若已经计入时段，再按时段调整距离就算了两次。
4. **能给出证据等级**，没有检验过的能用归档前向跟踪。

### 2.2 有增量的组合（按价值排序）

**① 定价分解：执行差，分“可回收”与“结构性”**

- 输入：
  - 可见信用、两腿 mark 价与成交价；
  - 两腿 mark IV；
  - 保护腿盘口点差、费用。
- 表达：净信用比市场估价（两腿 mark 价差）低 Y 美元，Y 正好等于两项之和：
  - 约 a 美元是两腿买卖价差：挂在中间价附近可以部分收回；
  - 约 b 美元是费用。
  - 另列一行：市场估价本身已含偏斜。保护腿 mark IV 比短腿高 c 个 vol 点；按短腿的 IV 给保护腿定价，会便宜约 s 美元。这一块是结构性的，执行收不回来。（v0.2 初稿把它写成“差额里剩下的部分”，不对：差额只由价差和费用构成，偏斜在市场估价之内。）
- 增量：回答“补偿薄，是因为成交方式，还是因为市场本来就这么定价”。这直接决定唯一的正向杠杆（挂单接近中间价）有没有用。单看信用、单看点差、单看偏斜，都回答不了。
- 证据：成本量级 B，挂单能否成交 C（17 §6，V5 待验）。提问单里已经反复出现这类问题（例：标注表第 3 题）。
- 数据：读视图里都有。

**② 单位剩余风险的价格：时钟校正后的 IV**

- 输入：
  - 本期 ATM IV、剩余小时；
  - 时段时钟的剩余方差（`remaining_clock_factor`）；
  - 参照：同一到期日 08:00 时的同一读数，或近 24 小时实现波动。
- 表达：现在的报价相当于“每单位剩余风险”的 IV，即 IV ÷ √剩余时钟倍数。再与本周期 08:00 时的同一读数比较：变贵了还是变便宜了。
- 增量：这是 16:00 较好这一 B 级结论背后的机制（17 §3.1 附录 A）：16:00 时报价仍按约 70% 的剩余方差定价，而实际只剩约 55–63%，报价跟不上风险的释放。原始 IV 看不到这一点，时钟也看不到；两者一比就出现了。
  - 它也是对 C 级“IV 与 RV 之差”的修正：原始的差混入了时段效应。
- 不重复计数：它比较的是“报价”与“时钟”，不去调整缓冲距离。
- 证据：总体机制 B；作为当期读数未检验。代码里已有这个计算（`entry_warnings` 的 `clock_adjusted`，期限倒挂就在用），只是没有单独呈现。
- 建议：先按 21 号的方式**事先登记**一次检验。用 17 号的同一份两年数据，在同一建仓时点内按“时钟校正 IV 相对 08:00 的变化”分组，看持有到期结果是否不同。通过了才上页面，而且只作描述。

**③ 持有中的条件剩余风险**

- 输入：
  - 锁定仓位的到期、短腿、现价；
  - 当前是否已被触及、触及时距到期的小时数；
  - 路径统计（16 §3.3–3.4）。
- 表达：
  - 未被触及时：“若到 hh:00 仍未触及：之后触及约 a%，到期越过约 b%”。
  - 已被触及时：“按剩余小时数，约 x% 走到保护腿”。
- 增量：把“现在离短腿多远”换成“剩下的路径里还要承担多少”。单看距离或单看时间都给不出这个数。
- 证据：B（方向为 A，幅度为 C）。只对 08:00 交割、剩余 ≤ 24.5 小时的合约给数字（20 号已有这条限制）。
- 位置：锁定详情的“现在”一行。计算在 `astra_path_stats_v1` 里已经有了，属于复用。

**④ 最坏 ÷ 补偿，以及币本位尾部形状**

- 表达：保护腿处净亏是净信用的 K 倍；保护腿以下按 BTC 计赔付继续增大。
- 增量：胜负不对称是 B 级事实（17 §2.3：一次大亏约抵四次满额信用）。K 让不同合约、不同日子可以直接比较，单个分量做不到。这个计算很简单，但读视图里的 R3 一直没有被用到。

**⑤（受规则限制，暂不上页面）平仓与持有的对比**

- 输入：
  - 锁定仓位当前的平仓成本（锁定详情的 `close_estimate`）；
  - 按路径统计折算的持有到期期望亏损。
- 增量：这是持有管理价值最高的二阶量：现在平掉，和持有到期按统计会损失多少，哪个更划算。
- 限制：13 §1、17 §5 规定，存档积累约 20 个到期日之前，页面不放平仓点。所以先在研究侧算（`intraday_exit_study`），不上页面。

### 2.3 看起来是组合、其实没有增量（不建议做）

| 组合 | 为什么没有增量 |
|---|---|
| 方向综合（TMV 24/48 + 主动成交 + 15 分钟动量 + 路径效率） | 同源（17 §2.4）；组合只是把同一条信息数了几遍；用来选边为 X |
| 拥挤综合（资金费 + 持仓量 + ETF） | 资金费拥挤为 C，不支持；其余未检验；组合规则只能拍权重 |
| “空间有利度”（墙与 Flip 相对短腿） | X（17 §3.4）；GEX 不带符号 |
| 按时段校正的缓冲距离 | 报价已经部分计入时段，再校正距离就算了两次；该比较的是 ②，不是这个 |
| 所需胜率（信用 ÷ 宽度推出的盈亏平衡频率） | 与 ① 的“对市场估价的差额”等价，只是换了单位 |
| 对冲流情景落到短腿处（`hedging_flows`） | 依赖对做市商持仓方向的假设，与 GEX 不带符号是同一个问题；未检验 |
| 宏观综合分 | 现有的宏观得分已经是这种综合；宏观方向已从判定中删除，没有可用的用途 |
| 状态四象限（21 号） | 已经检验：主检验不通过，只有一个时点交互勉强过线；保持核验路径 T 步的一行描述即可 |
