# 核验路径叙述式交互：原型设计稿 v0.1

日期：2026-10-27　作者：Claude　状态：用户 10-27 同意按推荐做原型（模板生成，备注一起做，系统给出证据举例）；核验流程仍是草案，本原型不改步骤与判定

## 1. 目的

现在的核验路径每步是一张“键：值”表，下面跟着小字依据；作答是三个与内容无关的按钮。信息够，但读者要自己把碎句拼成判断。

原型做三件事，信息一条不减：

1. **每步改写为一段话。**程序模板生成，不用模型。依据改为脚注编号。
2. **作答语义化。**每步提出一个与内容相关的问题，选项各自对应原来的三种倾向（更倾向承保 / 没变 / 更倾向不承保），记录格式与统计口径都不变。
3. **系统给出可引用的理由，并标明证据等级。**用户不必自己去找证据。系统列出与这一步相关的理由，标明研究给的等级和结论；用户可以勾选引用，并写备注。

## 2. 为什么模板，不用模型

- 核验路径一直是纯函数：数字、措辞、证据等级都能用测试锁住。
- 让模型改写会带来改数和夸大的风险，也违背“模型只提问、只解释，承保由人决定”的分工（17 号 §1）。

## 3. 证据举例的原则

用户要求系统提供证据举例，例如“量价和 Pin 点的倾向，可能让价格往有利方向走”。原型照做，但如实标注等级：

| 理由 | 等级 | 页面上的结论 |
|---|---|---|
| 挂单接近中间价可收回买卖价差 | 成本 B / 成交 C（17 §6） | 研究支持（成交性未验证） |
| 16:00 前后建仓较好 | B（17 §3.1，只限 08:00 交割） | 研究支持 |
| 公开事件已计入一天期报价 | B（17 §2.2） | 研究支持 |
| 胜负不对称：一次大亏约抵四次满额信用 | B（17 §2.3） | 研究支持（偏向不做） |
| 本期状态（扩张 / 隐含低于实现时 16:00 更好） | 边缘（21 §6） | 边缘 |
| 隐含远高于近期实现时结果偏差 | C（17 §3.3） | 候选，未验证 |
| 量价、主动成交朝有利方向 | C/X（17 §2.4：同源；方向不延续，A） | 研究不支持作为依据 |
| 本期 Pin、墙在有利一侧 | 未检验（17 §7.2：GEX 不带符号） | 研究不支持作为依据 |
| 周度 / 0DTE 墙构成的空间位置 | X（17 §3.4） | 研究不支持作为依据 |

- 用户可以引用任何一条。引用“研究不支持”的条目时，备注里记为“个人判断（研究不支持）”，系统不替用户把它升级为证据。
- 这样做，证据由系统提供，判断仍在用户；日后复盘时，可以统计“按个人判断引用的理由”和结果的关系。

## 4. 作答与倾向的对应

| 步 | 问题 | 选项 → 记录的倾向 |
|---|---|---|
| D0 | 资料够你判断吗？ | 够判断 → 没变；有缺口，让我犹豫 → 不承保 |
| D1 | 这样的赔付形状，你能承担吗？ | 能承担 → 承保；偏重 → 不承保；没影响 → 没变 |
| T | 要扛过的这些时段，对你： | 可以接受 → 承保；让我更犹豫 → 不承保；没影响 → 没变 |
| D2 | 这个缓冲距离，你觉得： | 够用 → 承保；偏近 → 不承保；没影响 → 没变 |
| D3 | 最近的走势，对你： | 不改变判断 → 没变；让我更犹豫 → 不承保；让我更想做 → 承保（要求写备注） |
| D4 | 持有期的外生事件，对你： | 可以接受 → 承保；让我更犹豫 → 不承保；没影响 → 没变 |
| Q1 | 有否决项时 | 按否决，不做 → 不承保；仍想看价格 → 没变（要求写备注） |
| Q2 | 补偿低于（不低于）市场估价，你有比市场更有把握的理由吗？ | 有 → 承保（要求写备注）；没有 → 不承保；先挂中间价再看 → 没变 |
| H | 这个盯盘安排，你做得到吗？ | 做得到 → 承保；做不到 → 不承保；没影响 → 没变 |

D3 选“让我更想做”、Q1 有否决仍继续、Q2 认为有更好的理由，这三处都要求写备注。原因是：这三处都是研究提示风险较高、或需要用户自己负责的判断。

## 5. 实现

- `tools/astra_decision_path_narrative_v1.py`（`dp_narrative@0.1`）：
  - 从每步的 `lines` 生成段落、背景（X/C 级读数折叠）、脚注、问题与选项、证据清单；
  - 在服务端提供会话时计算，不存储。旧会话也能看到叙述，`PATH_VERSION` 不变。
- `tools/astra_decision_path_store_v1.py`：标记记录 `choice`；新增 `notes[step] = {text, reasons, at_ms}`，允许只写备注；结论记录带上 `notes` 与 `choices`。
- 前端 `decision.js`：
  - “叙述 / 明细”切换；
  - 段落、脚注、背景；
  - 语义化选项；
  - 备注与引用理由；
  - 服务端没有叙述时，自动显示原来的表格。
- 测试：
  - 每一行读数都要进入段落或背景，数字不丢；
  - X/C 级只进背景；
  - 选项与倾向的对应完全一致；
  - 方向和 Pin 类理由永远不标“研究支持”；
  - 备注的校验与记录。

## 6. 不做的

- 不给概率、胜率，也不给“可以做”的建议。
- 叙述只改写，不新增判断。
- 不改步骤顺序与判定（核验流程仍是草案）。

## 7. 实施与审查后的修订（2026-10-27，本地原型，未部署）

**审查：**一次独立审查，结论为 1 项必须修、8 项建议修，均已修复。下面几处与 §3–§5 的原设计不同，以本节为准：

- **现在与开始的对照**由服务端逐行比较（含背景行），给出“变了 / 新增 / 不再有”，现在的读数用现在自己的脚注。只随时钟走动的读数（报价多少秒前、距到期多少小时、窗口倒计时）不算变化。
- **证据等级：**
  - “缓冲接近标准”改为 C（窄档阈值未验证），只有缓冲窄或已进入时才标偏向不做；
  - “高波动时段提示”一律中性（平均结果不更差，22 号 §2.3）。
- **背景：**D3 的方向读数，以及 T 步“回测无差异”的本期状态，固定放进背景，标“研究不支持作为依据”。
- **需要写理由的选项**（D3 让我更想做、Q1 仍想看价格、Q2 有更好的理由）：
  - 页面上点选只是暂存，写下理由并保存时，选择和理由在同一次请求里提交；
  - 取消就什么都不记；
  - 服务端拒绝没有理由的这类选择（`note_required`）。
- **服务端校验：**选项必须属于这一步、倾向必须与选项对应、引用必须是这一步提供的理由，否则拒绝。
- **引用的存法：**引用连同保存当时的证据等级与结论一起存下 `{key, grade, verdict_cn, label}`。日后能直接统计“个人判断（研究不支持）”的引用和结果的关系。
- **前端：**
  - 保存成功之前不清空草稿；
  - 输入备注时（包括中文输入法组字时）不因定时刷新重建页面；
  - 在明细视图里做的标记，在叙述视图里同样显示。
- **另修：**D2 墙正好在现价上时，不再显示“-0.00%”。
