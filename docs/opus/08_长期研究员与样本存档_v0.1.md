# 长期研究员与样本存档 v0.1

日期：2026-10-20　状态：已定，E0 实施中
依据：用户《Agent 持续研究与 Edge 挖掘设计说明 v1.0》（2026-10-20）、用户补充与确认、服务器核实

## 0. 路线修正

GrokBot 的定位从“逐张保单的外部复核员”改为**长期研究员**。

- 它不进入实时决策链路。
- 它的工作对象是冻结的样本存档：发现证据上的 edge 和决策方法上的 edge，提出假设并验证。
- 经验证接受的结论，晋升为程序读数或研究协议条款，再去调整消费端（原 Decision Path）。
- 不变量：**证据固定、结果固定、评价固定**。研究员可以改变假设、研究路径、证据用法和决策协议，不可以改变历史事实、冻结截面、结果和评价标准。

## 2. 样本单位

- **样本 = 一张合约（两腿 + 到期）从首次出现到到期。** 行情一动两腿就换，一天里同一侧会有多个样本。
- 同一天的合约按同一个交割价结算，结果高度相关。统计时**按交割日聚类**估计误差：
  - 入场条件类问题（距离、时点、结构）可以充分利用多样本；
  - 方向或市场状态类问题，有效样本接近天数。

## 3. E0 存档内容

存档根目录：`/var/lib/xxproject/research_archive/`。属主 bitnami，`research` 组只读，**只追加不修改**。

| 部分 | 频率 | 内容 | 用途 |
|---|---|---|---|
| `cases/<day>/` | 每小时，两侧各一份 | 完整案卷 `case_file@0.1`，gzip 压缩 | 冷存档：复现“当时看到了什么” |
| `ledger/<day>.jsonl` | 见下 | 合约路径账本：每张跟踪中的合约一行精简数值 | 热数据表：水平、变化、路径（WPEM 思路的数据化实现，不经 LLM） |
| `inquiry/<day>/` | UTC 02:00、14:00 两个时段 × 两侧，加手动 | 提问者输出（事实底稿与问题单），按 case_id 挂接 | “内置 LLM 当时如何解释” |
| `outcomes/<day>.jsonl` | 到期后 | 交割价、赔付、按各冻结点信用计算的结果、1 分钟指数路径统计（是否触界、最小距离、最大不利偏离、实现波动） | 结果固定 |
| `chain.jsonl` | 每次写入 | 文件路径、sha256、前一条哈希 | 防篡改：历史可验证 |

### 3.1 路径账本的频率（不牺牲信息前提下放宽）

- **基础频率**：每张跟踪中的合约每 30 分钟一行。
- **变化触发**：两次之间出现实质变化时立即补一行，包括：
  - 现价跨过短腿、盈亏平衡价或保护腿；
  - 到短腿的距离变动超过 0.25 个百分点；
  - 程序状态改变：Space 门、运动判读等级、Gamma 体制；
  - 合约开始或停止作为当前候选显示。
- **临近到期加密**：到期前 3 小时内，每次检查都记一行（约 10 分钟一行）。
- **完整价格路径**由到期后补取的 1 分钟指数提供，账本只需记录这张合约自己的盘口和程序读数。
- 跟踪范围：所有出现过的候选合约，从首次出现一直跟踪到到期，换腿后旧合约也继续跟踪。

### 3.2 每行字段（`ledger_row@0.1`）

`at_ms`、`contract_key`、`side`、两腿 `bid/ask/mark/mark_iv/delta`、`credit_bid_ask_btc`（卖短腿买价 − 买长腿卖价，未扣费）、`mark_spread_btc`、`index_usd`、`forward_usd`、到短腿/保护腿/盈亏平衡价的距离（%）、概率基线（`p_itm_short`、`p_touch_short`、`p_loss`、`p_max_loss`）、`displayed`（是否为当前候选）、程序状态（Space 门、运动判读等级、Gamma 体制、Flip），`locked`（是否有活跃锁定），以及 `trigger`（`first`、`base`、`change` 或 `near_expiry`）。完整字段以 `deploy/research_archive/DATA_DICTIONARY.md` 为准。

## 4. 提问者与研究员的分工（已确认）

| 职能 | 实时链路 | 研究链路 |
|---|---|---|
| 讲清事实 | 提问者，只在定时时段和手动拉起时运行 | 程序：案卷与路径账本 |
| 提出问题 | 提问者 | 研究员（跨样本的假设生成），并回头评估提问者的问题 |
| 当时如何解释 | 提问者输出按 case_id 冻结 | 研究员读取 |

- 提问者不对每个存档样本运行，每天约 4 次（两个时段 × 两侧），约 40 万 token。
- 研究员定期复盘“提问者哪些问题后来指向了真实兑现的风险”，提出 prompt 修订建议，经用户批准后升级提问者版本。

## 5. 每日节奏（以 UTC 08:00 交割为锚）

| 时间（UTC） | 动作 |
|---|---|
| 每 10 分钟 | 存档检查：到点的案卷、账本行、提问者、结果 |
| 每小时 | 两侧各冻结一份完整案卷 |
| 02:00、14:00 | 提问者运行并存档 |
| 08:10 起 | 到期合约补全结果 |
| 约 09:00 | 研究员复盘前一日，更新假设登记表 |
| 09:30 | 服务端前向验证（E3） |
| 每周 | 研究员提交协议修订建议 |

## 6. 后续阶段

| 阶段 | 内容 |
|---|---|
| E2 研究提交 | 研究员写入投递目录，服务端程序校验、打时间戳、计算哈希，再追加到登记表。假设必须写成程序可计算的条件（只读条件语言，作用于案卷和账本字段），并写明适用范围、形成样本、反例、同源变量、可推翻条件和前向验证计划 |
| E3 前向验证 | 服务端在登记时间之后的新样本上，按事先写死的评分规则自动评估，按交割日聚类。门槛草案：条件组 ≥60 个独立交割日，差异超过基线 2 个标准误，确认后写死 |
| E4 晋升 | 被接受的结论变成程序读数（案卷 L8）或协议条款，进而调整 Decision Path 和页面。每次晋升需用户批准，并升协议版本 |
| 说明书 | pilot-001 完成后，07 号改写为长期研究员版，写入不可改变事项清单 |
