# 事实案卷规范 `case_file@0.1`

日期：2026-10-20　状态：草案　对应：01 号 §5、02 号 P1

## 1. 定位

事实案卷是“一张具体候选在某一时刻的完整事实世界”，同时供提问者（内置 LLM）和研究员（GrokBot）读取。

原则：

1. **复用，不重算**：每个字段都取自现有生产者的冻结输出；唯一新增的计算是概率基线（`astra_market_baseline_v1`）。
2. **结构化的全量**：只剔除 hash、debug 与重复内容，不做 `[:N]` 截断。
3. **可寻址**：每条证据都有稳定的 `ref`，问题单和报告只通过 `ref` 引用。
4. **质量显式**：缺失或过期必须标出来，不补默认值。
5. **同源可见**：每条证据都写上游 `lineage`，用来判断同源、避免重复计权。
6. **按 as-of 冻结**：同一快照多次生成，字节完全一致。

## 3. 证据条目

```json
{
  "ref": "L2.baseline.p_itm_short",
  "label_cn": "短腿到期实值概率（市场隐含）",
  "values": {"value": 0.3658},
  "relations": {"abs_delta_short": 0.3604, "note_cn": "与 |Δ| 相差 0.005"},
  "asof_ms": 0,
  "quality": "ok|stale|missing|unknown|not_applicable",
  "quality_reason": null,
  "lineage": ["deribit.order_book.short", "deribit.order_book.long"],
  "source": "tools/astra_market_baseline_v1.py:from_capture"
}
```

- **`ref` 命名**：`L<层>.<主题>.<项>`，全小写，只用点号分隔。一旦发布不再改名；废弃时标为 `quality: not_applicable`。
- **`values`**：原值，单位写进键名（`_usd`、`_btc`、`_pct`、`_ms`）。
- **`relations`**：程序已经算好的关系，例如位置、距离、比值。
- **`lineage`**：上游产品 ID，取自 registry 或明确的数据源名。

**冻结边界**：`fact_context.market_facts` 在冻结时已经按白名单取字段（`_market_facts`，`astra_underwriting_fact_context_v20.py:450`）。白名单以外的字段，从快照里恢复不出来。案卷 v0.1 接受这一边界。要扩充字段，需改白名单并升级快照版本，单独立项。

## 5. 构建入口

- 新模块 `tools/astra_case_file_v1.py`，纯函数：`build(point, frame, view_parts) -> dict`。
  - `point`：锁定或可锁定点 `{candidate, packet}`，含完整快照与 `raw_payload`。
  - `frame`：`_dp_frame` 的输入。
  - `view_parts`：`data_health`、`gaps`、`release_identity`、`cross_asset`、`expiry_gamma`、`transitions`。
- 工作台在复核或定时时段组装输入，调用 `build`，结果按 `snapshot_id` 落盘到 `state_dir/case_files/`。
- 不改 `review_input@2.7.0` 的任何路径。

## 6. 体量

- 目标：单份 ≤ 1 MB JSON（约 250K token 以内），以 GrokBot 机器的内存（约 4 GB 可用）和提问者的 1M 上下文为界。
- 实测（T1.5）后补 p50/p95。若超标，按层拆成多个文件，不截断。
