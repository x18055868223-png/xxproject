# xxproject｜从用户 Decision Path 转向 Agent Research Loop 的路线调整说明

**日期：2026-10-19**  
**定位：研究设计稿 / 路线调整说明**

---

## 0. 核心结论

xxproject 原本计划在消费层建立一条 Decision Path，让用户按照固定顺序阅读价格地图、Space、Flow、Gamma、宏观、WPEM、Q1/Q2 等信息，并在一次次真实使用中逐步优化自己的决策路径，从而形成 edge。

现在需要调整这条路线。

原因不是 Decision Path 没有价值，而是它天然以人的注意力上限为边界。为了让用户能够读完、理解和决策，系统必须不断做选择、排序、摘要、折叠和压缩。

这意味着：

> **用户有限的注意力，不只是消费层的问题，也开始反过来限制整个研究系统能够保留和利用的信息。**

新的方向是：

> **不再要求完整研究世界首先适配人的阅读带宽，而是让机器研究层尽可能完整地消费事实和证据；用户最终消费研究成果、建议与必要证据，并保留最终决策权。**

---

# 1. 为什么需要改变原来的路线

原来的思路大致是：

```text
完整事实
    ↓
消费层压缩
    ↓
Decision Path
    ↓
用户阅读 / 推理
    ↓
用户决策
```

这个方向的优点很明显：

- 能帮助用户形成稳定阅读顺序；
- 能减少信息过载；
- 能降低宏观叙事、权利金或 LLM 过早锚定；
- 能让用户逐步积累自己的决策经验。

但它存在一个越来越明显的上限：

> **系统最终必须把复杂市场压缩到一个人可以处理的规模。**

一旦这样做，Decision Path 就不仅是在“帮助用户阅读”，也开始决定：

- 哪些信息被保留；
- 哪些信息被折叠；
- 哪些异常值得展示；
- 哪些冲突被省略；
- 哪些弱线索因为注意力成本而无法进入最终判断。

这会带来一个根本问题：

> **为了适配人的局限，系统可能提前损失掉真正有价值的信息。**

而市场中的 edge 很可能就藏在：

- 多个弱线索之间的联动；
- 不同时间尺度之间的变化；
- 同一现象的不同解释；
- 看似次要但持续出现的异常；
- 当前框架之外的新证据；
- 需要多轮外扩验证才能成立的关系。

这些内容并不一定适合被提前压缩成几个关键词或几张卡片后再交给人处理。

因此问题开始变化：

> 原来问的是“怎样设计一条更好的用户阅读路径”。

现在更应该问：

> **为什么还要让人的注意力带宽成为整个研究系统的信息瓶颈？**

---

# 2. 为什么现在适合引入 Agent

xxproject 已经逐渐形成一个相对固定的任务域。

它长期围绕的是同一类问题：

- 一张具体垂直价差当前承担什么风险；
- 当前价格与责任边界之间是什么结构关系；
- 市场正在怎样运动；
- 哪些已有结构可能提供缓冲、放大或失效；
- 当前外部环境与这张保单是否真正相关；
- 风险与补偿之间是否出现值得关注的错位；
- 原有证据正在增强、减弱还是失效；
- 是否存在值得继续调查的新线索。

底层事实空间也越来越稳定，例如：

```text
Contract
Price / Quote
Space
KPF
Gamma / Walls / Flip
Flow / Volume
WPEM
Cross-Asset
Macro
Events
Economics
...
```

这意味着 xxproject 不是让 Agent 在完全开放的世界里自由发挥。

更准确地说，它提供的是：

> **一个固定研究场景 + 不断变化的市场截面。**

这类任务非常适合 Agent。

因为相比人，Agent 可以：

- 一次读取更完整的证据；
- 同时维护更多关系；
- 高频重复同一种研究流程；
- 回查底层数据；
- 主动寻找反证；
- 对异常继续外扩；
- 比较历史截面；
- 检查多个因子是否只是同源重复；
- 在每次新截面出现后快速重做推理。

因此人的角色不必继续停留在：

> “每天亲自读完全部数据”。

更合理的是上移到：

> **监督研究质量、质询推理、决定是否接受剩余不确定性，以及最终配置资本。**

---

# 3. 期望的路线变化

原来的系统目标更接近：

> **系统帮助人更高效地完成研究。**

新的方向更接近：

> **系统和 Agent 完成大部分研究劳动，人负责监督、质询和最终决策。**

结构可以从：

```text
完整事实
    ↓
消费层压缩
    ↓
Decision Path
    ↓
用户阅读 / 推理
    ↓
用户决策
```

调整为：

```text
完整事实层
    ↓
内置 LLM
    ↓
Agent 研究员工
    ↓
证据整理 / 外扩研究 / 反证检查 / 结论收束
    ↓
用户听取汇报与建议
    ↓
用户最终决策
```

这个变化的核心并不是简单地“多接一个 Agent”。

真正发生变化的是：

> **研究系统不再首先为了人的注意力做压缩。**

完整信息优先服务于机器研究。

人最终消费的是：

> **研究成果，而不是全部研究过程。**

---

# 4. 内置 LLM 与 Agent 的角色应该分开

## 4.1 内置 LLM：Evidence Analyst

内置 LLM 离事实层最近。

它最适合承担：

- 当前截面的事实描述；
- 已知关系的解释；
- 异常识别；
- 冲突发现；
- 线索提出；
- 有依据的外扩问题生成。

例如：

> Spot 接近 Flip，同时 Put Wall 下移，主动卖压增强。

内置 LLM 可以进一步提出：

> 这三个变化究竟只是同一轮下跌的重复表达，还是分别提供了独立信息？

这属于合理的研究线索。

但它不需要直接越权得出：

> 因此这张 Put 不应该做。

它的主要任务是：

> **把事实讲清楚，并把值得继续调查的问题暴露出来。**

---

## 4.2 Agent：Researcher

Agent 不应该只是阅读 LLM 摘要后再做一次摘要。

它应该能进一步：

- 查看原始事实；
- 检查证据引用；
- 回看历史；
- 调查异常；
- 验证推测；
- 寻找反证；
- 查找必要的外部资料；
- 判断哪些解释真正具有增量；
- 判断哪些信息只是重复表达；
- 对当前风险—补偿关系形成研究意见。

最终它要回答的是：

> **基于当前可获得证据，这张具体保单最值得用户关注的是什么，为什么，以及还有哪些无法消除的不确定性。**

---

# 5. 必须避免的新错误：多层自然语言压缩

新的路线不能变成：

```text
Raw Data
↓
LLM 摘要
↓
Agent 只看摘要
↓
Agent 再摘要
↓
用户
```

这会把原来的信息损失问题从用户层搬到 Agent 层。

每经过一次自然语言总结，都可能发生：

- 弱证据丢失；
- 事实强度变化；
- 未知被隐含填补；
- 同源信息被重复计权；
- 局部关系被讲成完整因果；
- 某个异常因为“看起来不重要”被提前删除。

因此更合理的结构应该是：

```text
                    ┌─ 内置 LLM 描述 / 推理
Canonical Evidence ─┤
                    └─ Agent 可直接读取
                             ↓
                      Agent Research
```

也就是说：

> **内置 LLM 是 Agent 的研究助手，不是 Agent 的事实世界。**

Agent 必须始终能够回到底层证据。

---

# 6. Decision Path 不消失，而是改变身份

原来的 Decision Path 主要服务于：

> **用户应该按什么顺序阅读。**

路线调整之后，它更适合演化成：

> **Agent 的 Research Protocol。**

它不再需要规定一条死板的固定顺序：

```text
Space → Flow → Gamma → Macro → WPEM
```

而应该逐渐沉淀成一套研究纪律，例如：

- 形成结论前必须检查哪些问题；
- 哪些信息不能互相替代；
- 哪些证据可能存在同源重复；
- 什么时候必须寻找反证；
- 什么时候必须承认 Unknown；
- Q1 风险与 Q2 补偿不能相互偷换；
- 外部叙事不能覆盖具体保单事实；
- 任何材料性推理都应该能够回到证据；
- Agent 可以动态改变研究重点，但不能跳过基本证据纪律。

因此 Decision Path 的身份从：

> **固定阅读路线**

逐渐变成：

> **研究协议与方法论。**

---

# 7. 用户角色的变化

旧设计中的用户更接近：

> **亲自工作的研究员。**

需要不断：

- 阅读；
- 比较；
- 解释；
- 排序；
- 试错；
- 调整 Decision Path。

新的结构里，用户更接近：

> **投资负责人 / 研究主管。**

主要职责变成：

1. 操作工作台，决定研究哪张具体保单；
2. 听取 Agent 的汇报和建议；
3. 必要时质询证据、反证与推理；
4. 决定是否接受最终剩余的不确定性；
5. 做最终资本决策。

这里减少的是：

> **重复研究劳动。**

没有减少的是：

> **最终决策权。**

---

# 8. 这次路线调整真正想解决的问题

这次变化并不是：

> “Agent 比人聪明，所以让 Agent 替人交易。”

真正的问题是：

> **既然机器可以处理比人更大的信息空间，就不应该为了适配人的注意力而提前压缩整个研究世界。**

新的目标是：

> **让事实尽可能完整地进入机器研究层，让机器完成大部分搜索、关联、验证、反证和收束工作；用户最终消费的是一份可追溯、可质询的研究成果。**

因此这次路线变化可以浓缩成一句：

> **从“让系统适配人的阅读能力”，转向“让 Agent 充分利用系统的信息能力，人负责监督和最终决策”。**

---

# 9. 对既有模块的影响

这次路线调整并不意味着 WPEM、Space、动态跨资产参考、Q1/Q2、证据引用、Decision Path 等既有设计失效。

它们的角色在发生变化。

过去，它们更像：

> **用户需要亲自阅读和理解的模块。**

未来，它们更可能成为：

> **Agent 可以调用、组合、验证和继续研究的结构化能力。**

例如：

- **Space**：为 Agent 提供当前责任位置与结构关系；
- **WPEM**：提供时间连续性和证据演化；
- **动态跨资产参考**：帮助 Agent 判断当前哪些外部市场值得参考；
- **Q1/Q2**：分别组织风险质量与风险补偿；
- **Decision Path**：从用户阅读顺序转为 Agent Research Protocol；
- **证据引用与审计**：保证 Agent 的结论可以回到底层事实。

---

# 10. 参考性框架

当前可以把未来结构理解为：

```text
事实层
Data / Contract / Market / WPEM / Economics
            ↓
内置 LLM
事实描述 / 异常识别 / 线索提出
            ↓
Agent Research
证据整理 / 外扩 / 反证 / 历史比较 / 验证
            ↓
Agent Synthesis
风险—补偿关系 / 关键不确定性 / 研究建议
            ↓
用户
工作台操作 / 质询 / 最终资本决策
```

其中：

> **事实层负责提供可靠世界。**

> **内置 LLM 负责把截面讲清楚，并暴露值得研究的问题。**

> **Agent 负责完成主要研究劳动。**

> **Research Protocol 负责约束研究质量。**

> **用户负责监督和最终决策。**

---

# 11. 当前阶段不应过早写死的内容

这次路线调整仍然处于设计阶段，因此以下内容暂时不宜写死：

- Agent 是否只能使用一个模型；
- Dot / Muse / Grok Bot 等具体实现谁是主 Agent；
- Agent 是否必须按固定顺序研究；
- 每次必须输出固定数量的证据；
- 必须使用何种评分；
- 是否需要多个 Agent 互相投票；
- 是否必须使用固定的“最终建议”格式；
- 哪些外扩资料永远必查。

当前最重要的是先确定职责关系：

> **事实尽可能完整 → LLM 提供解释和线索 → Agent 完成研究 → 用户消费研究成果。**

实现方式可以在真实使用中继续演化。

---

# 12. 最终收束

这次路线调整的本质，不是把 Decision Path 换成 Agent。

而是重新定义：

> **xxproject 到底应该为谁优化。**

原来主要优化的是：

> 人如何在有限注意力下读完足够多的信息。

未来更应该优化的是：

> **机器如何在完整证据空间中进行高质量研究，而人如何以最低注意力成本监督并消费研究成果。**

因此未来最值得建设的，不只是一个更聪明的消费页面，也不是单独一个更强的 Agent。

而是：

> **一个事实完整、研究可追溯、Agent 可主动外扩、用户可质询并保留最终决策权的 AI 投研工作流。**

这才是本次路线调整希望建立的新方向。
