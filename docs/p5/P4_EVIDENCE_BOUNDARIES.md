# P4 证据边界审计（P4_EVIDENCE_BOUNDARIES）

**结论摘要**：P4 交接包（`99_SHA256SUMS.txt` 32/32 文件 SHA-256 本地校验全部一致）有效支撑了 **P0 上游证据/时钟资格修复** 与 **P2 确定性边界/版本门禁** 的工程价值；它**不支持**“B 相对 A 有初始择侧胜率优势”“混合 Prompt 经 P4 实测”或“C 已证明可提前止损”的结论。

## 1. 样本盘点与核验口径

- **有效独立样本**：仅 **3 张历史冻结牌面、8 份首次模型输出**（H2 `A_raw / A+P0 / B`、H3 `A_raw / A+P0 / B`、H4 `A+P0 / B`），并非 8 张独立牌。H1、H5 未进入对照分母。
- **投喂保真与载体差异**：H2/H3 的 `A+P0` 与 H4 两组输入均为研究构造/同证据重render；官方网页单输入框中的 `【SYSTEM】` 文本不等价于 API 原生 `role="system"`；网页“可见思考文本”不能等同于未公开内部推理，且无原生 API token/延迟账本。
- **清单差异记录**：`H4同证据_manifest.json` 记 `"original_a_full_sha256": "1d57b8e1..."`，而 `原始语料manifest.json` 与 `00_初始语料来源审计.md` 记 H4 原 `A_full.md` 为 `07507079...`（`original_b_full_sha256` `edf6b85f...` 一致），已在证据索引中显式标出。

## 2. 四层证据边界

### A. 已证实（Confirmed）
1. **P0 事实资格修复在 `@1.0` 下可被直接消费**：H2 `A_raw → A+P0` 后，模型正确采用 15:59 UTC 合格末点 `63,152.5`（替代未清理读牌指数 `63,069.2`），并将 4h/12h 现货流从“当前已成立反证”降级为 `OBSERVED_UNALIGNED`。H3 `A_raw → A+P0` 正确采用 `64,448.9`、`239/240` 与现货降级。
2. **同证据下三局择侧 3/3 一致**：H2 全 `Accept / Call`、H3 全 `Accept / Put`、H4 全 `Accept / Call`；**零样本显示 B 择侧优于 A+P0**。
3. **B 稳定产出四要素 C 结构，而 A/A+P0 的 C 退化**：B 在三局均列出最强已知不利事实、暂未排除理由、时钟/覆盖不确定性与未来复核条件；A 与 A+P0 则退化为入场前提、笼统模板或复述机械规则 M（如 H2-A+P0 缺前瞻 Hold 条件）。
4. **模型对机械边界、时钟和 JSON 摘录存在稳定失真，必须由程序兜底**：
   - `H2-B` 因冻结态实为 `UNKNOWN` 而主动省略 `require_outside_at_t0`；
   - `H4-A+P0` 将严格返回外侧错写成“回到 `65,500` **及以下**”，并将入区限定为“65,500 至 67,500 区间”（漏保护腿边界与外侧）；
   - `H2-A+P0`、`H3-A_raw`、`H3-A+P0` 在 `<ANNOTATION_JSON>` 出现首句截断/短摘（`comparison` 在“其一”后截断），且 `H3-A+P0` vs `H3-B` 对 `ard_responsibility_meaning` / `ard_review_on` 放于 `condition_plan` 内还是顶层分裂；
   - **源头自伤**：`A_System_v1.0.md` 与 `B_System_v1.1candidate.md` 自身均写有 `按 UTC 网格 / UTC 每 5 分钟网格`，`A_System_v1.0.md` 自身还将责任区定义为“短腿与保护腿之间”，直接诱发模型复述错误口径。

### B. 仅有提示（Suggestive Only）
- 最小 C 契约可从 `@1.1-candidate` 抽离并与 `@1.0` 择侧内核结合，但**`@1.0 + 最小 C` 混合体在 P4 从未真实运行过**。
- 8 次首次输出全部 `Accept`，未见即时 Reject 偏移（受限于小样本与结构范围，不可外推）。

### C. 未证明（Unproven）
- 任何择侧胜率、长期收益 Edge、Reject/误拒分布等价性（N=3，不计事后 PnL）。
- **C 能否在机械 M 触发前、于真实 Hold 链路产生正确且早于 M 的风险预警**。
- B 的思考长度（H2-B 863 行、H3-B 1,209 行、H4-B 1,080 行）与 A+P0（H3-A+P0 1,543 行、H2-A+P0 1,048 行）在相同 API 参数下的真实 token/尾延迟差异。

### D. 挑战 P4 原建议的反例与 caveats
1. **B 未根治同源重复计票与无证据否定**：H3-B 在 `ARD判读` 承认 `+77.8 USD` 仅 `0.05×` 尺度且不预测未来后，仍在 `两侧对比择优` 将其升格为“最明确的方向性不对称”作第一选侧依据（且正文中忽略近 5m `-102.3 USD` 下行）；H4-B 在思考闪过全窗极值未给的情况下仍在正文断言“从未达到保护腿 `67,500`”。
2. **B 产出了不可用或晚于 M 的 C 触发**：H2-B 三条未来触发中有两条（`64,000 Pin 邻域 [63,626.5, 64,373.5]` 与 `责任区内结构位`）逻辑上只能在 `M(new_entry > 63,500)` 触发**之后**发生；H4-B 的 trigger②要求盘中“补齐历史 Pin 可用收据”，在实时持仓复核中不可操作。
3. **H3/H4 A+P0 vs B 非严格单变量对照**：H3/H4 的 `A+P0` 保留了 `136d2d96` 之前的旧 User 外框，缺失“反复穿越 Gamma 位不得赋予阻挡力”“事中事件门不必等到机械越界”等句；且 H4-A+P0 出现**二次读取文件失败**（思考骤降至 11 行，正文 40 行），不能与完整读取同等计权。
4. **程序端风险警告**：在保留严格中文正则校验的前提下若放松格式前缀，容易在 `retries=0` 单次发牌模式下制造误拒。详见 [P5_DESIGN_DECISION.md](./P5_DESIGN_DECISION.md) 与 [P5_VALIDATION.md](./P5_VALIDATION.md)。
