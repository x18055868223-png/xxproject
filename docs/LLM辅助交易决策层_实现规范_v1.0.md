# LLM 辅助交易决策层实现规范 v1.0

## 1. 定位

本层位于 FMZ 前置信号之后、人工交易决策之前。它使用本地事实约束与 Gemini 两阶段复核，把不同调节回路收束为结构级人工复核建议，但不修改信号、不重算置信度、不选择具体合约，也不产生交易授权。

允许的建议仅为：卖 Put 价差复核、卖 Call 价差复核、中性单边价差复核、等待确认、不交易或无法判断。

## 2. 不得产生逻辑缺口或冲突

以下为本轮必须同时满足的跨层不变量：

1. **信号只读**：FMZ `decision`、EDB、confidence、blocking、trade permission 和 schema 保持 producer-native，不因 LLM 输出而改变。
2. **盲读独立**：第一次 Gemini 调用仍不读取系统结论、耐用性结论或时区标签；第二次调用只能沿用第一次盲读结果，不得重写。
3. **职责正交**：前置信号负责方向和证据账本；辅助层负责跨回路推理、结构适配、主要矛盾与条件边界。两层观点相同是允许且正常的，不以文案相似度判断无效。
4. **硬阻断优先**：producer 的明确硬阻断、宏观冲击阻断或 `NO_TRADE_BLOCKED` 不得被结构复核建议绕过；等待确认状态不得被舒适窗口或 LLM 升级为价差复核。
5. **时区只提醒**：`session_context` 与 `comfort_window` 只解释流动性和价格发现环境，不改变 recommendation、方向或 confidence。美股核心时段不能升级弱信号，非核心时段不能反转信号。
6. **失败封闭**：API 超时、解析失败、非法枚举、无效证据引用或边界字段错误时，sidecar 输出 `UNABLE_TO_JUDGE`，原审计卡继续有效且不生成默认交易建议。
7. **兼容透传**：`integrated_trade_advisory` 仅新增在 LLM sidecar。旧 sidecar、无 LLM 卡和错误卡仍可被 materializer 处理；历史卡不得伪装成已具备新结论。
8. **执行隔离**：固定 `audit_only=true`、`trade_authorization=false`。不得输出仓位、杠杆、具体到期日、行权价、报价或下单动作；任何前端展示也不得把结构复核建议渲染成交易许可。
9. **方向中立**：偏多、偏空、中性/区间与等待确认使用相同先验和证据门槛。不得假设加密资产天然上涨或下跌，不得把卖方结构、中性或谨慎等待当作默认答案；缺失数据必须进入无法判断，而不是自动解释为中性。
10. **镜像一致**：方向性事实和上下墙体完全镜像时，Put/Call 侧建议应对称互换，其他准入门槛保持不变。Gamma、Funding、宏观和时段按各自角色影响结构适配、拥挤、尾部风险或提醒，不得由单因子创造方向。
11. **裁决解耦**：固定按数据充分性、硬阻断、中性接管、卖方结构适配、侧向容错的顺序裁决；`source_alignment` 最后填写。机械结构适配不等于最终建议，高冲突或数据质量问题仍可形成不交易结论。
12. **授权与适配解耦**：`trade_allowed=false` 与 `execution_allowed=false` 是审计层的预期执行隔离事实，不得单独导致等待或不交易。结构复核建议不开放交易许可，交易许可关闭也不等于结构本身无法复核。
13. **执行参数双重防线**：提示词禁止具体行权价、到期日、仓位、杠杆、开平仓和订单参数；本地校验必须再次扫描 advisory 文本。模型即使自报 `not_trading_advice=true`，一旦输出执行参数仍按失败封闭处理。
14. **人机表达隔离**：枚举码和字段名只存在于 JSON 机器字段，人读中文不得回显机器码。`NEUTRAL_SINGLE_SIDE_REVIEW` 只能解释为中性单侧结构复核，不得在文案中扩展成双边或其他结构。
15. **盲读冲突必须裁决**：第二阶段不得把第一次盲读的明确反向倾向静默改写为“与系统一致”。盲读与 producer 方向明确相反时，不得输出任一方向价差复核，必须显式标记分歧并收束为等待、不交易或无法判断；`source_alignment=ALIGNED` 只允许两者方向实际一致时使用。
16. **完整结论与多语言防漏**：最终结论、跨回路理由、接管依据、结构适配依据、侧向依据、主要矛盾、关键前提、失效条件、下一观察和时区依据均须为非空人读文本。机器码和执行参数校验不区分大小写，并同时覆盖中英文及所有 advisory 嵌套枚举；任何空壳结论、具体价差腿位、英文 strike/expiry/entry/exit、仓位、杠杆或订单动作均失败封闭。服务器严格验收必须独立重验完整字段、嵌套枚举和人读防漏，不得仅信任 sidecar 自报的通过标志。

只要任一不变量无法成立，本层不得输出可用的结构复核建议。

## 3. 事实与推理职责

本地代码负责清洗并索引真实审计事实、校验证据引用、执行硬边界和失败降级。LLM 负责回答：中性接管是否成立、当前结构是否适合继续复核定义风险卖方价差、哪一侧容错更合理，以及当前最大风险或信息缺口是什么。

LLM 不得使用外部行情或补造缺失数据。每条关键前提必须引用本地事实包的稳定 evidence id。

## 4. 输出与版本

- sidecar schema：`signal_llm_review@1.4.0`
- prompt：`gemini_signal_review_prompt@1.4.4`
- packet：`signal_llm_review_packet@1.1.0`
- 新字段：`llm_review.integrated_trade_advisory`
- FMZ 信号本体：保持 `1.5.6`
- 信号卡 schema：保持 `nrd.schema.v1.0.0`

审计前端在顶部六项指标之后、Gamma/GEX 之前显示完整 advisory 的中文读者版结论；materializer 负责原样透传新字段。服务器可通过显式严格开关验收新 sidecar，默认不破坏旧部署。

## 5. 验收

验收至少覆盖：两阶段调用不变、事实包与证据哈希稳定、同向综合结论可通过、盲读反向分歧不可伪装成一致或升级为方向价差、等待/硬阻断不可升级、无效证据和非法授权 fail closed、中英文执行参数与大小写机器码均被拒绝、所有人读字段非空、时区只改变提醒、旧 sidecar 继续兼容，以及 materialized 卡保留完整 advisory。

还必须运行方向平衡矩阵：偏多适配、偏空镜像适配、中性区间、冲突等待、硬阻断、信息不足、同方向不同 Gamma/墙体/Funding、仅时区变化。确定性 mock 是发布门禁；真实 Gemini 影子调用用于观察模型遵循程度，但不得作为 FMZ 或服务器真实部署证明。
