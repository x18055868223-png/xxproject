# 信号审计更新部署规范 v2.0

## 锁定保单观察的安装与本地验收

工作台依赖包含 `astra_locked_candidate_store_v1.py`、`astra_locked_candidate_compare_v1.py` 及复用的公开脱敏模块 `astra_observation_replay_v1.py`。锁定记录位于既有 `ASTRA_WORKBENCH_STATE_DIR/locked_candidates`，更新代码时须保留该目录与原 state；不能用重建状态来替代幂等或恢复验证。

采样复用工作台后台，默认最小间隔 60 秒、最多 4 张 active、64 个 episode、1440 个归档点及 256 MiB。实际间隔受既有采集耗时影响；资源到顶显式暂停，不覆盖 t0。环境变量见 `workbench-v20.env.example`。本地验收须启动新 Python 进程，并区分源码哈希、实际加载、短时真实公开更新、合成反例和生产部署；本地版本仍需用户本版本的页面发布确认。

## 当前补丁增补

GEX时间语义按[Astra补丁20](astra/20_GEX时间语义补丁与FMZ1.6.2.md)实施：FMZ1.6.2、事实包2.1.1、Prompt2.2.1，LLM输出/摘要/投影仍2.2.0。本次只需一张冻结真实卡做隔离Prompt检查；旧事件/固定读取及时间场景另由兼容测试覆盖，不为恢复历史卡重置预算。

发布仍需本地新页面确认。先安装兼容新旧的GEX与审计服务，保护缓存时间身份、原始审计、评审、预算及持久尝试，再同步用户可见FMZ交付。实例确认和自然新卡前向验收分开。旧24小时独立报告/双调用门禁不适用于当前单次评审；下文旧章节只在明确legacy入口适用。

当前用户批准的单次综合评审契约见 [Astra方案07](astra/07_总体证据评级与单次综合评审_v2.md)。旧两次调用/24小时报告/跨轮冷却重置规则退出新自动流程，旧协议仅供历史读取及显式离线研究。

后续升级必须同时遵循[Astra版本兼容与数据复用约定](astra/10_版本兼容与数据复用约定.md)，保护原始数据、评审、持久尝试和预算；安装不能因索引缺失而覆盖真实卡。

## 1. 目的与适用范围

本规范适用于 `deploy/signal_audit/`、`tools/signal_llm_review*.py`、materializer、systemd 资产、LLM Prompt、sidecar schema 和信号审计前端的后续功能迭代、推送与服务器更新。目标是把发布变成可重复、可停止、可回滚的标准流程，禁止把生产服务器当作开发调试环境。

FMZ producer、GEX 服务或交易执行层不因信号审计发布而自动进入范围。涉及这些资产时，必须另行执行三层版本一致性与各自的安全门禁。

## 2. 不可绕过的发布原则

1. `xxproject` 是项目权威仓库；提交、推送和部署前必须核对 remote、分支和目标提交哈希。
2. LLM 始终是 `AUDIT_ONLY`，不得改变 producer direction、confidence、blocking、trade permission 或 execution permission。
3. 密钥只存在于环境变量或服务器 `/etc/signal-audit/llm.env`，不得出现在命令回显、日志、diff、sidecar、截图或项目记忆中。
4. 本地测试通过不等于部署成功；部署脚本成功不等于真实调用成功；systemd service 成功不等于前端卡片完整。每一层必须分别给出证据。
5. 前端改动必须先完成本地桌面与移动浏览器检查，并经过用户的“当前本地页面可推送”门禁，才允许提交、推送和部署。
6. 默认安装不得自动启用 LLM timer。只有 canary、严格自检、物化和外网页面验收全部通过后才能启用。
7. 任一强制验收失败都立即停止，不得通过连续 API 重试、放松 validator、跳过自检或直接启动 timer 来掩盖问题。

## 3. 标准发布流水线

### 阶段 A：变更前基线

- 阅读 `AGENTS.md`、`PROJECT_MEMORY.md` 和本规范。
- 确认工作树、分支、`xxproject` remote、HEAD、dirty files 和服务器当前提交。
- 记录本次明确范围、禁止触碰范围、代表卡 ID、预期 schema/provider/model/prompt 版本。
- 读取服务器 timer、service、usage ledger 和最新真实卡状态；禁止先写服务器再调查。

### 阶段 B：本地实现与最小充分测试

- Prompt/schema/validator/entrypoint/materializer/frontend 必须按真实调用链一起审查。
- 至少覆盖正常输出、空正文、非法 JSON、缺字段、语义冲突、硬阻断、旧卡兼容、冷却/终止、每日额度和敏感信息脱敏。
- 前端覆盖唯一行动结论、分侧证据等级、中文事实、下一观察、下载、长中文、旧卡和错误卡。普通页面及展开区不出现机器字段、内部码、旧总分；旧卡独立历史阅读。
- 运行相关 Python 测试、语法检查和 deploy asset 测试；保存命令与结果，不得声称未执行的测试通过。

### 阶段 C：真实 API canary

- 使用一张代表性模拟或复制卡，在隔离临时目录执行真实 DeepSeek 调用；不得直接写生产 sidecar。
- 事件卡与固定轮次分别验证一次高推理综合评审、实际调用数、输入大小、token、耗时、分侧校验、本地行动、源引用及摘要绑定。不生成新24小时长报告或独立变化LLM。
- 每卡固定事实包、Prompt和调用模式共享持久的最多两次HTTP额度。传输恢复和格式恢复共用额度；跨定时轮次或进程不重置。
- 临时网络、空内容、截断、JSON语法或共享结构错误可恢复一次；可隔离单侧错误只影响该侧。引用伪造、明确事实矛盾、权限越界、鉴权/配置错误不自动重试。
- 不按等级或结论满意度重试。代码修复后验收使用明确标识的新输入/工具指纹并保留此前失败，不冒充初次稳定成功。
- canary 不通过时禁止推送、部署和启用 timer。

### 阶段 D：本地页面验收

- 用 canary 真实 sidecar 物化仓库外临时站点。
- 桌面 1440×900 与移动 390×844 均检查：层级、溢出、长段落、点位来源、旧卡兼容和原始追溯。
- 确认唯一行动结论、Put/Call总体证据、中文市场事实、下一观察可达；旧阻断影响行动而不压低证据字母。
- 用户确认“当前本地页面可推送”后才进入阶段 E。

### 阶段 E：提交与推送

- 只提交已验证且在范围内的文件；再次检查 diff 和 secrets。
- 推送到 `xxproject` 的目标分支，记录不可变 commit SHA。
- 不得以分支名或 `FETCH_HEAD` 猜测部署版本；服务器必须验证拉取到的 SHA 与目标完全相等。

### 阶段 F：服务器安全安装

- 停止 LLM timer/service，保留 materialized cards、sidecar、ledger、state 和 `/etc/signal-audit/llm.env`。
- 安装脚本使用安全默认值：不自动运行初始 LLM、不自动启用 timer、不覆盖运行数据。
- 核对安装后的脚本、systemd unit、timeout、provider/model/prompt/schema 与目标提交。
- 失败 trap 必须让 LLM timer 保持关闭，并输出单一部署日志位置和退出码。

### 阶段 G：服务器 canary 与生产验收

- 在服务器隔离目录先运行 canary，不写生产 sidecar；通过后才允许针对明确 card ID 做一次生产复核。
- 严格自检至少要求：LLM、integrated advisory、transition、materialized passthrough、session context、provider/model/prompt/schema 全部通过。
- 核对目标卡新sidecar为OK或有合法单侧结果的PARTIAL，2.0.0协议、持久尝试额度、完整评级与列表摘要同源。ERROR或缺字段不能封版。旧协议使用显式legacy自检。
- 启用 timer 后检查 timer active、service 无失败循环、每日 HTTP ledger 未越界。
- 从外部URL打开目标卡，桌面与移动检查新阅读顺序、两侧等级与行动、中文来源、无横向溢出或机器字段泄漏。

### 阶段 H：关闭与证据

- 最终记录：commit SHA、测试、canary 调用数、严格自检汇总、timer 状态、ledger 用量、目标卡 ID、外网页面结果。
- 删除本地和服务器临时脚本、临时站点与临时 SSH 凭据；不删除发布证据日志和生产历史 sidecar。
- 检查工作树干净，并更新本规范与 `PROJECT_MEMORY.md` 中经过验证、可复用的规则。

## 4. 失败状态与重试预算

- 默认 `single_evidence_v2`：正常一次高推理；输出预算32768、主超时240秒。格式恢复使用原有非思考交付模式。
- 每卡固定包及调用模式至多两次HTTP，持久记录在sidecar旁的v2_attempts目录；发出HTTP之前写入占额记录，崩溃不返还已占尝试。
- 共享北京日预算60与互斥锁；日额度不足没有发出请求，不消耗卡片尝试；次日仍使用固定包与剩余额度。
- 正常结束、单侧语义失败及最终失败均不通过定时重跑反复请求。坏卡错误应隔离，不使其他新卡饥饿。
- 旧retry-id及旧2/5/15分钟恢复只适用于显式legacy离线入口，不重置v2。

## 5. 回滚与停止条件

出现以下任一情况，保持 LLM timer 关闭并回滚到上一已验证提交或保留上一份公开静态输出：

- provider/model/prompt/schema 与发布目标不一致；
- canary 或严格 validator 未通过；
- hard block 被绕过或出现交易授权；
- 新卡缺少当前协议要求的最高辅助结果或有效复核；四小时／二十四小时条件情景允许缺省，不要求独立报告；
- materializer 覆盖/丢失历史卡；
- 页面溢出、空白、关键块消失或泄漏机器对象；
- service 失败循环、timer 重入、ledger 越界或密钥泄漏。

回滚只替换版本化代码和静态资产，不回滚或覆盖服务器本地密钥、sidecar、ledger、状态和 FMZ 源 JSONL。

## 6. 规范维护规则

每次功能迭代、推送或服务器更新完成时，负责人必须同时检查本规范和 `PROJECT_MEMORY.md`：

- 新增了稳定、可复用的发布门禁或故障分类时，更新两者；
- 只属于单次事故的日志、卡 ID、临时目录、主机凭据和猜测不得写入长期记忆；
- 规范修改与实现修改在同一分支评审和推送；
- 若流程与代码不一致，发布暂停，先修正规范或代码再继续。

## 7. LLM 重试轮次与人读输出规范

- 显式 `--retry-id` 是一次新的记录级重试轮次。新轮次首次失败必须从 `record_retry_count=1` 重新计数；相同 packet 的旧普通 `VALIDATION_ERROR` 或旧普通终止记录不得污染新轮次。`FATAL_AUTH`、`FATAL_CONFIG` 与 `RECONCILIATION_EMPTY_CONTENT_RECOVERY_EXHAUSTED` 仍跨轮次保持终止，除非配置或 packet 发生可证明的变化。
- 同一卡同一 packet 存在已校验 blind 上下文时，人工重试 reconciliation 阶段的 `EMPTY_CONTENT`、`INVALID_JSON` 或 `VALIDATION_ERROR` 应优先复用该上下文，只发起一次 reconciliation 调用；不得为修复第二阶段格式问题重新消耗 blind 调用。
- 服务器金丝雀必须把生产 main/transition sidecar 复制到隔离目录后再运行；main 隔离副本须剔除目标卡旧 OK 行但保留其失败/blind 恢复历史，再对目标卡显式开启新重试轮次，保证本轮产生新结果且不重复已有 blind；已完成的 transition 保留并复用。只有隔离结果、严格自检和物化全部通过后，才可把目标卡的唯一新 OK 结果原子合并回生产 sidecar。
- 人读字段禁止出现字段路径、`KEY=VALUE`、JSON 布尔值或机器枚举串。Prompt 负责要求自然中文；entrypoint 只对已知、安全、机械可翻译的表达做受限修复；任何未知原始字段语法继续由 core validator 拒绝，不得直接进入生产 sidecar。
- `containment_assessment` 与 `premium_selling_fit` 只接受规范化后的 `state/basis_cn` 两字段：合法状态与文本保留并剔除模型附加键，缺项安全降级为 `UNABLE_TO_JUDGE`，显式非法状态仍必须由 validator 拒绝。该规范化不得生成市场事实或提升结构建议。
- 时段与舒适窗口证据不得支撑核心建议前提。entrypoint 只可删除前提中的 `EV_SESSION_CONTEXT/EV_COMFORT_WINDOW` 引用；删除后仍有其他真实证据的前提可保留，引用被删空的前提必须丢弃，若全部前提均被删空则保持原输出并由 validator 失败关闭，禁止自动补造 evidence ID。
- 模型缺失 `containment_assessment` 或 `premium_selling_fit` 时，只允许补成 `UNABLE_TO_JUDGE` 的本地安全值，并使任何价差复核建议降级为 `NO_TRADE`；不得猜测为适配或成立。
- 最高辅助决策中的墙位距离由本地代码从同一 packet 的现价、`call_wall` 与 `put_wall` 确定性计算。文案只解释现价处于两墙之间或墙外、到上下墙的相对距离，并明确不单独决定方向或辅助建议；不得依赖模型自行计算，也不得转写成行权价或订单参数。
- 发布验收必须同时覆盖：旧终止记录后的新重试轮次、单调用 reconciliation 恢复、缺字段安全降级、原始字段语法拒绝、墙位距离算术、最新默认卡渲染和至少两张最近卡的真实 sidecar 状态。

## 8. 补全链路的规范化、恢复与发布边界

- 主信号复核只允许一条公共预校验规范化路径。entrypoint、定时任务和 canary 必须复用同一 core 入口，不得各自维护一套人读字段修补逻辑。
- Blind 只缺 `boundary_cn` 时可写入固定 AUDIT_ONLY 边界；只缺 `counter_evidence` 时可写入“未提供可校验反证、按信息不足处理”的确定性说明。两者都不得补造市场事实、证据 ID 或方向依据，并必须写入 `blind_completeness_repair` 审计对象。
- 任何经过 Blind 完整度修复的复核，其最终建议上限为 `NO_TRADE`。非法方向、非法置信枚举、缺失依据或关键驱动、Gamma 体制错误、卡内事实不一致、执行参数和授权越界仍立即失败关闭。
- Reconciliation 返回空正文但带 reasoning 时，只能复用已经通过校验的 Blind，在同一轮追加一次 `main_reconciliation_recovery`；不得重做 Blind。恢复仍为空、非法 JSON 或未通过完整 validator 时结束本轮，不继续同型重试。
- Canary 判断 transition 状态时，只检查目标卡 ledger 对应 transition ID 的最新结果。无关历史 transition ERROR 不得阻塞目标主卡恢复；目标 transition 自身最新 ERROR 仍阻止 promote。
- 未来 24 小时报告采用分区降级：主结论、权重、审计边界或内容安全不合格时隐藏整块；单个低层点位的名称、依据、来源或数值不可安全展示时，仅隐藏该点位并记录显示降级。任何机器对象、执行参数、外部事实或授权违规仍隐藏整块。
- 已知卡内点位别名在 core 校验前确定性中文化，包括 `gamma_regime`、`max_gamma_strike` 以及 wall/flip/pin 路径。未知原始字段不得通过宽泛替换进入人读正文。
- 回归夹具必须覆盖一次 service 周期内的完整闭环：Blind 可修复缺项、一次 reconciliation recovery、最终完整 validator、原子 sidecar 写入和 materializer 展示；同时证明冷却卡、终止坏卡和无关 transition 失败不会让新卡饥饿。

## 9. Astra 信号用途评级的发布检查

- signal_rating@1.0.0 必须由新 producer 在完整性哈希前原生生成；旧卡缺字段显示历史未评级，不在 materializer/前端伪造原生值。
- 评级用途固定为环境与侧别支持；候选报价经济性未评估。旧 confidence、分类、事件、materiality 与权限应通过固定输入对照；新评级不增加 LLM 调用或触发。
- 盲评不接收新评级；完整核对阶段可解释与提出异议，不能把派生评级视为新独立市场证据、唯一建议依据或解除 producer 阻断。
- 本地真实历史卡重放与模拟卡必须明确区分；原始历史记录和完整性哈希不得覆盖。真实 API canary 使用隔离输入/输出，并计入现有权威 HTTP ledger，不修改生产 sidecar。
- 语义/浏览器检查通过不代表评级已证明收益；FMZ 原生版本、真实 API、服务器与用户页面确认分别取证。

### 当前舒适度迭代的补充要求

- 当前规格为 `docs/astra/06_信号舒适度评级与页面收束.md`。在既有第二次 reconciliation 生成 Put/Call 等级，本地核验后再透传；保留原生四态证据与旧信号算法，不新增第三次调用、重评计时器或通知。
- LLM schema/主 Prompt 候选均为 1.6.0；这与 FMZ producer 候选 1.6.0 分别登记，不能因为数字相同就视为同一交付或已经部署。
- 页面只消费最终等级。原评、限级原因与来源保留审计链；缺失、错误和未完成必须显示未评级。B 为页面关注，A/S 是信号层人工准备资格，不能覆盖 WAIT/BLOCK 或变成执行许可。
- 本轮浏览器验收覆盖全部展开区、辅助阅读文本和错误状态的中文事实表达；原字段与实现细节仅留在完整资料下载中。上一版页面批准不能替代本轮的“当前本地页面可推送”确认。

## 10. 只读工作台局部修订的验收边界
