# 执行层 FMZ 空跑交互收束补充意见（2026-06-23）

> 性质：本文件记录本轮用户补充的产品/执行层交互返修意见。它不覆盖 `执行层_FMZ空跑综合测试返修记录_20260623.md` 中的 Chrome 真机实测事实，而是作为下一轮代码返修和文档重写的输入。

## 1. 当前问题

当前 FMZ 策略交互仍保留 7 项：

- `执行`
- `急停`
- `恢复`
- `拒绝`
- `授权止盈`
- `风险退出授权`
- `撤销授权`

用户反馈：这仍然过于冗杂，且会继续制造“执行层需要人工逐项容错/授权”的误解。FMZ 本身不适合承载频繁交互，执行层前端交互应极简化，只作为计划层进入执行层的硬授权入口。

## 2. 目标交互模型

FMZ 前端交互应收束为唯一主交互：

| 保留项 | 类型 | 作用 |
|---|---|---|
| `执行` | 字符串输入 + 执行按钮 | 输入计划层给出的方案确认码，完成计划轮到执行轮的授权过渡 |

目标体验：

1. 操作者只需要输入一次方案确认码。
2. 点击 `执行` 后，执行层自动锁定当前方案并进入执行层流程。
3. 不再暴露 `急停`、`恢复`、`拒绝`、`授权止盈`、`风险退出授权`、`撤销授权` 等常驻前端按钮。
4. `授权止盈` 不应作为人工二次交互；止盈、风险退出和降险管理应在确认码授权后按默认规则自动执行。
5. 一个确认码 + 一个执行动作，足以完成计划层到执行层的过渡。

## 3. 代码层返修要求

### 3.1 删除 FMZ 常驻容错按钮

从交付物、runbook 和 FMZ 配置指引中移除常驻交互项：

- 删除/废弃 `急停`
- 删除/废弃 `恢复`
- 删除/废弃 `拒绝`
- 删除/废弃 `授权止盈`
- 删除/废弃 `风险退出授权`
- 删除/废弃 `撤销授权`

说明：这里的“删除”指不再作为 FMZ 前端常驻交互项暴露。若执行层仍需要内部安全保护，应通过默认 fail-closed、门控配置、状态机自恢复、重启后重新等待确认码等代码路径实现，而不是让操作者在 FMZ 页面上频繁点击。

### 3.2 止盈默认执行

确认码授权成功后，执行层应默认允许当前方案生命周期内的止盈和风险退出管理，不再要求操作者额外输入 `授权止盈` 或 `风险退出授权`。

验收口径：

- `执行:确认码` 成功后，状态栏显示本轮授权边界。
- 本轮授权边界应覆盖：开仓尝试、订单管理、止盈、风险退出、必要的降险退出、到期/退出后归档。
- 授权只覆盖当前方案/当前持仓生命周期；退出、归档或放弃后回到下一轮待确认码状态。

### 3.3 命令反馈必须进入日志与状态栏

点击 `执行` 后必须产生明确反馈：

- 确认码不正确：日志和状态栏显示“确认码无效/过期/不匹配”，状态保持待授权。
- 确认码正确：日志和状态栏显示“确认码通过/方案锁定/进入执行流程”。
- 预提交失败：日志和状态栏显示失败原因，例如 `vrp_rechecked`。
- 执行层流程刷新：状态栏从计划等待态刷新到执行层当前流程，而不是仅靠重复刷屏日志推断。

反馈要求：

- 不能只依赖 FMZ 弹窗“指令已发送”。
- 不能只通过“状态没有变化”间接推断错误码已被拒绝。
- 日志应记录关键状态变化，不应每几秒重复刷同一条无信息量状态。

### 3.4 删除无效日志刷屏

当前日志中存在大量重复的 `RUN_CYCLE:HARD_APPROVAL_WAIT`、`RUN_CYCLE:PLAN_LOCKED` 等周期性状态刷屏，影响操作者定位真正事件。

代码层要求：

- 删除或降频无状态变化的周期性日志。
- 只在状态变化、命令处理、授权失败、授权成功、预提交结果、退出/归档等关键事件时写日志。
- 状态栏负责展示当前状态，日志负责记录事件历史；不要用日志持续重复模拟状态栏。

建议日志事件模型：

| 事件 | 写日志 |
|---|---|
| 策略启动 | 是 |
| 待批方案刷新且内容变化 | 是 |
| 收到确认码 | 是，脱敏 |
| 确认码错误 | 是 |
| 确认码正确并锁定方案 | 是 |
| 预提交通过/失败 | 是 |
| 进入/退出执行层关键阶段 | 是 |
| 无状态变化的周期轮询 | 否 |

## 4. 文档返修要求

后续整合 PDF、空跑 runbook、小额实盘配置文档应同步改为：

1. FMZ 策略交互只配置 `执行` 一项。
2. 日常操作流程只写“复制计划层确认码 -> 粘贴到执行输入框 -> 点击执行 -> 查看状态栏/日志反馈”。
3. 不再把 `急停/恢复/拒绝/授权止盈/风险退出授权/撤销授权` 作为操作者需要配置或理解的常规按钮。
4. 明确“止盈默认执行，不需要二次授权”。
5. 明确“FMZ 不承担高频交互；FMZ 只承载计划到执行的确认码授权”。

## 5. 验收标准

下一轮返修完成后，A2 空跑验证至少满足：

- FMZ 交互面板只出现一个可用交互：`执行`。
- 输入错误确认码后，状态栏和日志均显示明确拒绝原因。
- 输入正确确认码后，状态栏刷新到执行层流程，日志记录确认码通过和方案锁定。
- 执行后无需再点击 `授权止盈` 或其它授权按钮。
- 日志不再被无状态变化的周期性状态刷屏淹没。
- 最终退出/归档后，策略回到下一轮 `HARD_APPROVAL_WAIT`，等待新的计划层确认码。
