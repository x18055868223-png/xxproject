## FMZ 交互配置（必读·一次性）

> 交互契约（v2.16 收束·见《交互收束交付单》）：**FMZ 前端只配置一个交互 = `执行`**。两轮模型：授权成功前=**计划入口轮**（看明细、输确认码）；输入 `执行:确认码` 成功后=**执行轮**（单轮轮询，自动维护持仓管理/止盈/风险退出/对冲/到期归档，全部代码内完成，无需再点任何按钮）。安全/放弃不再是前端按钮：**急停=配置门 `KILL_NEW_RISK`**、**放弃/重新等待=批准 TTL 过期 + 重启**。

### 1. 为什么必须手工配（部署须知）
FMZ 不支持随策略单文件自动建「交互」项；新建策略/机器人后，若不手工配置，机器人能运行但**没有可点的输入框**（此时是交互缺配，不是交易所 API 失败）。`GetCommand()` 在回测系统不生效，**只能用真实机器人验收**。

### 2. 配置步骤（FMZ 策略编辑页 → 底部「策略交互」区）
点「添加」，填「名称」「类型」「描述」，保存——**只此一项**：

| 名称（必须完全一致） | 类型 | 描述（给操作者看） |
|---|---|---|
| `执行` | 字符串(string) | 输入待批方案明细表里的【确认码】，点执行进入执行轮 |

- 名称必须为 `执行`（命令路由按中文名匹配，见 `cmd_router.COMMAND_ALIASES`，现仅此一项）。
- **保存策略后必须重启机器人**，交互项才进入运行实例（FMZ 会提示「绑定策略已更新，重启实盘生效」）。
- 确认码半角 `执行:IWJS` 与全角 `执行：IWJS` 均可（v2.15 R4 已兼容）。
- 不需要、也不应再配 `急停`/`恢复`/`拒绝`/`授权止盈`/`风险退出授权`/`撤销授权`——这些命令已下线，输入也只会得到「未知命令」。

### 3. 安全 / 放弃如何处理（不再是按钮）
- **急停（停新风险）**：在 FMZ 策略参数把 `KILL_NEW_RISK` 改为 `True` 后重启机器人 → 阶段进入 `KILLED`、进场门 ✗、退出/对冲减仓继续；改回 `False` 重启即回到待计划授权。`EMERGENCY_REDUCE_ONLY` 同理（强制只减）。
- **放弃当前待批/已锁方案**：不操作即可——锁定方案超过 `APPROVAL_TTL_MS`（默认 30 分钟）自动作废、回到 `HARD_APPROVAL_WAIT` 等新确认码；版本/入场配置变更也会使旧批准失效。

### 4. 发命令的等待规则（R2，避免误判滞后）
- 发出 `执行:确认码` 后，FMZ 弹「指令已发送 / 知道了」——**先点「知道了」**，再等 **15–25 秒（约 1–2 个 `run_cycle` 周期）**，看「交互控制台」的「阶段」「最近命令」行更新到目标状态。
- 「最近命令」行会显示明确结果，用它确认，不要只靠「状态有没有变」间接判断：
  - `执行 → 执行通过：方案已锁定·进入执行轮`（正确码）
  - `执行 → 执行失败：确认码为空 / 确认码格式无效 / 确认码无效或已过期`（错误码）
  - `执行 → 重复命令已忽略（同码幂等）`（重复粘贴同码）

### 5. 状态栏怎么看（状态栏=当前态，日志=事件历史，两者不互相替代）
- 状态栏「运行概览·版本/轮次」标当前是**计划入口轮**还是**执行轮**。
- 计划入口轮：看「待批方案明细」表（期号/到期/胜率/保证金释放/盈亏比/建仓可行性/**确认码**），复制确认码到【执行】。
- 执行轮：「授权边界」行显示 方案#/确认码脱敏/批准剩余分钟/止盈预算/风险退出预算/自动退出状态；正常**无需任何操作**。
- 日志只在**状态变化**时写一条 `[事件] …`、命令到达时写一条脱敏 `[cmd] …`；无状态变化的周期轮询**不再刷屏**。

## 阶段 A1：本机合成成交场景矩阵（SyntheticFillAdapter）

用 `tests/synthetic_fill.py` 把 `/private/buy|sell|get_order_state|cancel` 换成合成成交，用**真实** entry campaign / 退出 / 对冲主链跑 §11.1 场景。已自动化覆盖的关键项见 `tests/test_run_cycle.py::test_synthetic_e2e_*`；**手动补跑/复核**以下矩阵（在一次性脚本或 REPL 里设 `fmz_shim.exchange.io_handler = make_synthetic_handler(base, model)`）：

| 场景 | 成交模型 | 期望 |
|---|---|---|
| 保护全成 + 短腿全成 | buy 1.0 / sell 1.0 | commit、快照 short=prot=amount |
| 保护全成 + 短腿部分成 + 尝试耗尽 | buy 1.0 / sell 0.5 | **放弃→冻结 1:1 覆盖、`long_remaining_qty ≥ remaining_short_qty`（无裸短腿，INV-03）** |
| 保护全成 + 短腿不成 | buy 1.0 / sell 0.0 | 全退保护、清锁、无持仓 |
| 保护部分成 + 短腿等量成 | buy 0.5 / sell 1.0 | short ≤ prot（不变量保持） |
| 信号活动中途过期 | 任意 + 过期包 | 不新增风险、phase 回 WAIT_SIGNAL |
| 净 credit 低于底线 | 调宽 `ENTRY_MIN_NET_CREDIT` | ENTRY_PAUSED_CREDIT / 超额 ABANDONED |

通过判据：**任意分支都不留裸短腿、不留无法解释状态；所有 commit 的快照 `protection_qty ≥ short_qty`。**

## 阶段 A2：真实机器人·静态方向只读/空跑（OFFLINE_MANUAL）

> `GetCommand` 在回测系统不生效，**必须真实机器人**。本阶段验证交互与读取链，不真实下单。

配置（`config.py` 顶部全局，FMZ 运行时可改）：
```
SIGNAL_SOURCE = "OFFLINE_MANUAL"
ALLOW_ENTRY_TRADING = ALLOW_EXIT_TRADING = ALLOW_HEDGE_TRADING = False
KILL_NEW_RISK = EMERGENCY_REDUCE_ONLY = False
DIRECTION_BIAS = "SHORT_CALL"（或 SHORT_PUT，与当前信号一致）
```
FMZ 交互项见上方「FMZ 交互配置」节（**仅 `执行` 一项**；急停=配置门、放弃=TTL 过期）。

逐项核对（状态栏顶部「交互控制台」+「运行概览·轮次」+「待批方案明细」表）：
1. 启动日志含 `STRATEGY_VERSION 2.16.0`；启动即跑恢复检查 → 控制台无 `DATA_UNKNOWN`/`RECOVERY_BLOCKED`（若有→先排查读取/持仓）。「轮次」显示**计划入口轮**。
2. **计划入口轮明细可见**：控制台出「待批方案明细」表，每条含 期号/到期/短行权(Δ)/距现价/胜率/有效净credit/盈亏比/保证金释放/建仓可行性/**确认码**；挑一条，【执行】输入其确认码。错误码反馈分支逐项核对（「最近命令」行直接可见）：空 → `确认码为空`；含标点/格式错 → `确认码格式无效`；不存在/过期 → `确认码无效或已过期`；阶段均保持 `HARD_APPROVAL_WAIT`。正确码 → `方案已锁定·进入执行轮`、阶段 PLAN_LOCKED、「轮次」转**执行轮**、出现「授权边界」行。
3. 预提交 13 项：OFFLINE 下 `vrp_rechecked` 必 fail（无 market_context）→ **不真实开仓、仅空跑预览**。确认控制台显示「将下达订单」意图表（保护腿在前）。
4. 即便临时把 `ALLOW_ENTRY_TRADING=True`：因 **OFFLINE-in-LIVE 守门**，仍只 DRY_RUN（不 commit）。验证后改回 False。
5. **急停=配置门**：把 `KILL_NEW_RISK=True` 后重启 → 阶段 KILLED、进场门 ✗、退出/对冲减仓仍可；改回 False 重启 → 回待计划授权。**放弃=TTL**：锁定后不操作，超 `APPROVAL_TTL_MS`（默认 30 分）自动作废、回 `HARD_APPROVAL_WAIT`（预提交标 `APPROVAL_EXPIRED`）。
6. **重复消费可见**：同一确认码重复【执行】→ 「最近命令」行显示 `重复命令已忽略（同码幂等）`（`duplicate_ignored`，界面直接可见）。
7. **下线命令为未知（契约核对）**：手输 `急停`/`授权止盈:X`/`撤销授权` 等 → 「最近命令」显示 `未知命令（FMZ 前端仅支持【执行:确认码】）`，不改变任何状态。
8. **Gate-A 提交合法性（v2.12）**：①意图表每条腿价格落在该**真实合约有效 tick**（高价合约 tick 更粗，不应出现越网格价）；②数量 = `ORDER_AMOUNT` ≥ 该合约 `min_trade_amount`。③临时设 `ALLOW_ENTRY_TRADING=True` 但 `ALLOW_EXIT_TRADING=False`（或 `RISK_EXIT_MAX_SPEND=0`）→ **启动自检 `validate_config` 报错**（能开不能关，INV-E10）；改回 False 后正常。
9. **日志不刷屏（本轮要求）**：无状态变化的多个 `run_cycle` 周期，事件日志**不再重复输出** `RUN_CYCLE:*`/空腿位行；只在状态变化时写一条 `[事件] …`、命令到达时写一条脱敏 `[cmd] …`。状态栏（LogStatus）仍每轮刷新当前态——状态栏管当前态、日志管事件历史，二者不互替。
10. **命令账本人工核验（R5）**：每条命令（含确认码错/重复/未知）都落 `_G("spm_cmd_ledger_v1")`（上限 200 条、跨重启可查），字段含 `type/name/status/outcome/ts`（确认码 arg 仅入账本审计、不入显示日志）。核验路径：FMZ「调试/运行信息」查 `_G` 该键，或临时 `Log(_G("spm_cmd_ledger_v1")[-5:])` 打最近 5 条比对界面「最近命令」一致。
11. **交易所只读核对（R5）**：本阶段「无真实下单」除门控/日志推断外，另做只读复核——经 Deribit 账户页或 `dbt_get_open_orders`/`dbt_get_positions` 确认**无本策略 label 的活动订单、无新增期权持仓**（与控制台「将下达订单」仅为意图、未真实下达一致）。

通过判据：**前端仅 `执行` 一项**/计划入口轮明细全量可见/执行反馈分支可见/重复幂等可见/下线命令为未知/急停经配置门/放弃经 TTL/预提交 fail-closed/读取三态/Gate-A 提交合法性/**日志不刷屏**/命令账本可核验/交易所只读无下单 全部如期；**OFFLINE 下无任何真实下单**。

## 阶段 A3：真实机器人·FILE/G 端到端空跑（门仍全 False）

验证「信号包驱动方向 + VRP 经 market_context + 真实复核链」，但**门控仍全 False**（不真实下单，仅观察主链是否能走到 entry campaign 预览）。

配置：
```
SIGNAL_SOURCE = "G"   （或 "FILE"，对应 SIGNAL_G_KEY / SIGNAL_FILE_PATH）
门控仍全 False
```
信号侧落一份 `SignalEvidencePackage`（同托管共享，见 HANDOFF §4 总线 spike），至少含：
```
schema_name="SignalEvidencePackage", schema_version 前缀 "nrd.integration.signal.",
package_id, expires_ts(未来), reject_state 无, data_quality 无问题,
strategy_recommendation.side_hint（put/call/bullish/bearish），
market_context = { side, front_anchor_iv, atm_front_iv, term_reference_iv_5_10d,
                   rv_24h, rv_72h, rv_7d, rv_percentile, history_days,
                   executable_short_iv, executable_protection_iv }
```
逐项核对：
1. **方向权威（T0-C）**：把 `DIRECTION_BIAS` 故意设成与 `side_hint` 相反 → 候选仍按 **side_hint** 生成（如 side_hint=put → 卖 put 价差）；`side_hint` 缺失/中性/不可映射 → fail-closed（不建库、phase WAIT_SIGNAL）。
2. **VRP（T0-D）**：用一份"肥 IV"market_context（front_iv ≫ RV）→ 预提交 `vrp_rechecked` 通过；用"薄"上下文 → BLOCK。确认推荐库/预提交只放行通过 VRP 的候选。
3. **信号一次性（INV-05）**：同一 `package_id` 在一次 commit（本阶段为 DRY 预览，不会真消费）后，真实成交阶段不得二次成仓——在小额实盘阶段验收。
4. **过期/拒绝/坏质量包** → 一律禁新开、持仓管理继续。

通过判据：方向由信号驱动且不可映射即阻断；VRP 双门按 market_context 真实裁决；坏包一律 fail-closed。

## 阶段 A4：持仓管理空跑（注入快照，门仍 False）

直接注入 `_POSITION_KEY` 快照（带 `entry_risk_anchor`），观察 manage 一轮（执行轮的一部分）。
> 注：**退出授权随开仓批准自动捆绑（v2.10），无手工授权按钮（v2.16 已下线）**；本阶段因直接注入快照（未走 commit），需自行注入降险授权 `_G("spm_exit_auth_v1", build_authorization(pos_id, POLICY_RISK_EXIT, now))` 再观察；不注入即模拟「授权异常」分支。
1. 高 delta 短腿 → 控制台「风险」行显示 EXIT_PREFERRED + 触界概率；「风险动作」显示 preferred=EXIT_PREFERRED；若**未**注入授权（仅本注入场景）→ executable 回落 HOLD/对冲，「软授权」行标「退出未授权（异常）」。
2. 短腿盘口缺 delta/IV → 「风险」行显示**数据缺口**（不静默 NORMAL）。
3. 止盈资格达标 + 已授权（正常=commit 自动捆绑；本阶段=注入）→ exit_campaign WORKING（门关仍 dry）；**全程不需任何前端按钮**。
4. 裸 perp（短腿=0、perp≠0）→ ORPHAN_HEDGE_EMERGENCY（即便对冲门关也标记清理意图）。
5. reconcile 不符 → 控制台标「不符·已记录，风险收口继续」（不阻断）。

通过判据：风险/止盈/对冲/孤儿/对账 全部正确 surfaced，且**门关下无真实下单**。

## 阶段 A5：到期结算端空跑（24h 交割；注入到期快照，门仍 False）

注入 `_POSITION_KEY` 快照（含 `short_instrument/long_instrument/short_expiry_ts`），观察 manage：
1. **已结算归档**：`short_expiry_ts` 设为过去（DTE≤0）+ 交易所期权持仓读到两腿均不在（[]）→ manage 清零腿量、`close_reason=EXPIRED_SETTLED`、归档 CLOSED、清快照（**无幽灵持仓**）。
2. **读失败 fail-closed**：DTE≤0 但持仓读失败（None）→ **不归档**，快照与腿量保留待复查。
3. **临近可见**：`short_expiry_ts` 设为 DTE≤`EXPIRY_IMMINENT_HOURS`（默认 2h）→ manage 返回 `expiry_imminent=True`；退出仍由风险模型驱动、不强平丢信用。
4. 真机注：Deribit 期权 08:00 UTC 现金结算；持有到期的方案应在结算后下一轮即归档（不应卡在买回已下市合约）。

通过判据：到期+确认结算 → 干净归档 EXPIRED_SETTLED；到期+读失败 → 不归档（fail-closed）；EXPIRY_IMMINENT 可见。
