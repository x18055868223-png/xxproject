## 1. 权限模型（三类动作）

| 类别 | 动作 | 小额实盘策略 |
|---|---|---|
| A 新增风险 | 开垂直价差 / 加短腿 / 开非 reduce-only 期货 | **每笔人工硬批准**（`执行:确认码`）+ 系统 13 项预提交复核 |
| B 中性维护 | 撤未成交单 / 刷新 / 放弃过期方案 / 对账恢复 / 告警 | 全自动 |
| C 风险收缩 | 买回短腿 / 卖多余保护 / reduce-only 平期货 / 清孤儿 | **不逐笔批准**；开仓时**同时**授权（见 §3） |

原则：**人工批准只把方案从"禁止"变"允许继续复核"，不能越硬门、不能改腿/数量/价格/上限；任何修改 → 重新生成方案与确认码。**

## 2. 全参数配置（`config.py` 顶部全局；FMZ 运行时可改。空跑/小额实盘两列）

> 列说明：**空跑** = 跑《空跑验证流程》时的值（多数=代码默认）；**小额实盘** = 据真实账户改的值（`<>` 为须你标定的占位，余可沿用空跑）。

### 2.0 实盘**必须改**的 6 项（其余默认即可起步）
| 参数 | 空跑 | 小额实盘 | 说明 |
|---|---|---|---|
| `SIGNAL_SOURCE` | `OFFLINE_MANUAL` | `"G"` 或 `"FILE"` | 实盘新增风险必须来自总线；OFFLINE 即便开门也只 DRY_RUN |
| `RISK_EXIT_MAX_SPEND` | `0.0` | `<非零>` | **=0 则风险退出受阻→回退对冲**。建议 = 单结构最大损失×0.3~0.5（结算币 BTC）。开仓门校验要求 >0 |
| `PORTFOLIO_LIMITS["max_margin"]` | `0.50` | `<账户净值×5~10%>` | 首跑用小占用上限（结算币 BTC） |
| `PORTFOLIO_LIMITS["max_spread_loss_per_trade"]` | `0.02` | `<单结构最大损失>` | = (腿宽 − 净credit) 折算结算币 |
| `ENTRY_MIN_NET_CREDIT` | `0.0` | `<非零>` | ≥ 来回摩擦（≈2×期权费+半价差），勿留 0 |
| 三门控（见 §4 逐门开） | 全 `False` | 按 §4 顺序逐个 `True` | 降险门先于新增风险门 |

> **能开不能关硬校验（v2.12 INV-E10）**：一旦 `ALLOW_ENTRY_TRADING=True`，`validate_config` 要求同时 `ALLOW_EXIT_TRADING=True ∧ RISK_EXIT_MAX_SPEND>0`，否则**启动自检报错**——杜绝"能开新风险却无退出路径"。

## 3. 一次开仓批准 = 同时授权退出边界

> **不应允许人工批准新增风险，却没有同时授权系统在预定边界内关闭该风险。**

当前实现的授权链（v2.16 交互收束·前端唯一交互 = `执行`）：
- `执行:确认码` → 锁定方案 → 预提交 → 受控开仓（新增风险，人工硬批准）；这是**唯一**人工交互。
- 成持仓即**自动捆绑降险授权**：止盈（达 80% 资格自动退）、风险退出（风险严重时**越价限价**退出、成本封顶 `RISK_EXIT_MAX_SPEND`）、reduce-only 对冲、孤儿清理——**全部代码内自动执行，无需任何二次授权按钮**（受 §4 门控）。

**v2.10.0 起：开仓批准自动捆绑降险授权**——成持仓(含部分冻结)时系统自动建**降险授权**（绑定持仓 + `max_exit_spend=RISK_EXIT_MAX_SPEND`），止盈/风险退出/孤儿清理无需再逐笔输码（§5.2「批准新增风险即同时授权预定边界内自动降险」）。**v2.16.0 起手工 `授权止盈`/`风险退出授权`/`撤销授权` 按钮已下线**（前端只剩 `执行`）。**前提**：`RISK_EXIT_MAX_SPEND` 须标定为非零，否则风险退出受阻→回退对冲。

> v2.10.0 已落地 `NewRiskApprovalPackage-lite`：锁定方案带 `approval_expires_ts`/`code_version`/`config_hash`（过期/版本/配置漂移→作废重批），commit 自动捆绑降险授权。完整独立 schema（含对冲/孤儿策略细分字段）属后续增强、非小额实盘阻塞项。

## 4. 逐门开真顺序（降险先于新增风险）

默认全 False。按以下顺序逐门开，每步真实机器人观察 ≥ 数个完整周期无异常再进下一步：

1. **`ALLOW_EXIT_TRADING = True`**（先放降险）：验证止盈/风险退出**真实可成交**——尤其风险退出越价吃单与"越价不可成交→回退对冲"两条路径（需 `RISK_EXIT_MAX_SPEND>0`；退出授权随开仓批准自动捆绑，无需手工授权）。
2. **`ALLOW_HEDGE_TRADING = True`**（减仓门，仅当需要清理孤儿/减仓时）：验证 reduce-only / 孤儿清理。**`ALLOW_HEDGE_OPEN` 保持 False**（开仓门拆分，v2.10.0）——本阶段不主动开期货对冲敞口。
3. **`ALLOW_ENTRY_TRADING = True`**（最后放新增风险）：仅在总线信号 + 人工 `执行:码` + 13 项预提交全过时真实开仓；`ORDER_AMOUNT` 维持最小、单仓。

急停=**配置门**（v2.16，非按钮）：`KILL_NEW_RISK=True` 重启 → 停新风险+撤开仓单（退出/对冲减仓继续）；改回 `False` 重启 → 回待计划授权。放弃待批/已锁方案 = 不操作，批准 TTL 过期自动作废。

## 6. 晋级判据（小额实盘 → 放宽 / 窄范围自动）

不只看 PnL；连续若干完整 entry/exit campaign 满足：
```
无 P0 事故（无裸短腿 / 无不可解释状态 / 无重复下单）
所有持仓血缘完整（signal_package_id → 一持仓，INV-05）
所有读失败/未知 → 均阻断新增风险（DATA_UNKNOWN / RECOVERY）
所有重启均能恢复（不凭本地空判交易所无仓）
无未知活动订单（no_unknown_orders fail-closed 生效）
人工批准与真实成交差异可解释（含审批延迟成本）
```
满足后再考虑 Tier2（动态再平衡 / Class A 自动 + 否决窗口 / 影子追踪 / 标定）。**是否完全自动由数据决定，不预先承诺。**

## 7. 一页速记（操作员）

```
开仓： 计划入口轮看控制台待批方案明细 → 评估最大损失可接受 → 复制确认码 →【执行:确认码】
      （唯一人工动作；进入执行轮后 commit 自动捆绑降险授权，止盈/风险退出/对冲/归档全自动）
盯盘： 控制台「风险」行（触界概率/EXIT_PREFERRED）、「止盈资格」、「对冲」、「对账」、「授权边界」（正常无需操作）
到期： 临近交割看 EXPIRY_IMMINENT（DTE≤2h）；持有到期 OTM → 现金结算后系统自动归档
      EXPIRED_SETTLED（无需手动平）；短腿逼近行权 → 风险模型转 EXIT_PREFERRED 自动退
异常： 急停=配置门 `KILL_NEW_RISK=True` 重启（停新风险，退出/对冲减仓继续）→ 排查 → 改回 False 重启
红线： OFFLINE 不会真开仓；门默认全 False；非"策略已验证"；最小仓 + 单仓起步
24h： 专做 ~24h 剩余 → SHORT_DTE_HOURS 收窄如 (12,24)；专用子账户、无其他持仓
```
