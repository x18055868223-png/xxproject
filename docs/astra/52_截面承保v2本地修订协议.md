## 修订理由与候选范围

R17 已裁定“风险工具有用，业务未成立”。当前页面先呈现选侧倾向，不能回答“这张具体保单承担什么、市场报价补偿了多少责任”。本轮把候选合同、同期盘口、费用和适用的冻结赔付参考按同一快照绑定，作为交易前人工研究资料。第一版只处理 Deribit BTC inverse、同到期、同量的单一 Put 或 Call 信用价差；由用户显式给定两腿和数量。无自动选腿、无新模型训练、无信用/尾部阈值搜索。

四种 `origin` 仅描述如何发现同一候选：手动、现有固定轮、自然 NR、状态刷新。它们共用一个纯评估函数；状态刷新在本地回放中使用已保存/显式输入快照，不在生产新增定时器。相同快照合并多来源，更新报价/输入产生新版本，不算新独立交易机会。没有 NR episode 时不得补造修复起点。

## 数值与审查约定

- 合同原生 BTC 赔付复用 `astra_commercial_math_v17.inverse_spread_payout`；列静态终值表和所有可解的净盈亏平衡根。`qW/S_0` 只是参考尺度，不是 inverse Put 的 BTC 尾部上限或账户保证金。
- 仅用同目标数量的卖腿 bid / 买腿 ask 深度算“顺序分腿盘口估算”；空深度、非 open、过期、跨腿不同步或时间晚于评估点时 `c_visible=null`。技术时效门限预先固定为各腿距评估点最多 5 秒、两腿时间差最多 2 秒，Deribit 两腿 index 与所列参考价相差最多 0.1%，仅约束数据资格，未经收益优化。报价不保证成交。
- FMZ 已有 `EvaluationSnapshot` 每 tick 写入 `snapshots.jsonl`，含 `decision.ts_ms`、`runtime_facts` 与 `factor_snapshot`，可作连续事实来源。只取估值时点之前最近一条，并要求距估值最多 5 分钟、价格原始观测未晚于估值；源行 hash、运行模式、事实时间和价格来源保持可追溯。超过该技术时效只作背景，不称当前事实。FMZ 价格和 Deribit index 身份分别保存，不能未经口径核对就相互替换。
- `B_loss=c_visible-f_assumed`；`M_ref=c_visible-μ_ref-f_assumed`。费率身份为实际、明确配置假设或未知；未知费用时不得生成严格净余量。风险参考必须同候选、同数量、同参考价和同输入时点，模型/校准/支持域与哈希明确。超域或缺失时 `μ_ref` 不进入账，`M_ref=null`。不把 IV、Delta、LLM 或事后结算代替物理赔付参考。
- 合成风险参考只进入合成身份；非合成 `μ_ref` 要绑定 BTC 当期 FMZ 事实与 64 位来源 SHA。即使直接喂 JSON，“当前”FMZ 事实也必须有绑定估值时点、5 分钟内的事实/价格观测、live 公共只读模式和价格来源。历史回放必须带源文件 SHA，且不能作为当前专项 LLM 评审。页面只展示 `astra_underwriting_causal_review@2.0.0`、同快照/候选且资料包身份完整的评审正文，评审适用性不等于经济裁定。
- LLM 只接收已冻结快照的合同、可见报价、风险及缺口，审查因果适用性、同源重复和取数问题；每快照沿用现行一次正常评审和最多两次 HTTP 共享恢复额度。**本轮离线验收不发真实 LLM 请求**；评审包只标记待评审，旧 LLM JSON/预算不改。
- 状态只为“资料缺口、参考补偿不足、可复核、已失效/到期”，均为阅读状态。人工执行前仍须重新取价、账户约束与原独立许可。所有新候选 `execution_allowed=false`。

## 主要评价与停止条件

验收分层：合同计算正确性（含 inverse Put 极低交割价、Call 双根）、报价深度/时钟/费用资格、风险绑定与缺口、四来源去重和失效、LLM 审查包版本绑定、旧卡与旧预算字节不变、页面阅读和本地服务。合成夹具只证明计算与展示；保存盘口若无当时冻结 `μ_ref` 只能证明缺口处理。并列记录四来源覆盖与新增行情/LLM 需求，不从卡数推断经济提升。

遇到任何双腿身份/时钟/数量不一致、费用不明、模型超域或旧资料被改写，停止输出严格参考余量并保留原因。若只有合成场景通过，本轮交付可称“本地研究工具可审计”，不得称生产消费、自然卡验证或经济 edge。任何新版前端在浏览器审计和用户再次明确确认“当前本地页面可推送”以前不提交、推送或部署。
