# 63 MAP来源与字段契约 v2.4

本文件记录本轮 `tools/astra_map_sources_v24.py` 的薄适配边界。它不是生产发布记录，也不表示 MAP 已进入工作台消费；主工作台、registry 启用和页面注入由集成任务另行完成。

## 1. 本轮模块接口

| 接口 | 责任 | 不做什么 |
|---|---|---|
| `collect_sources(engine, now_ms, *, transport=None, config=None)` | 只通过 `engine.fetch` 采集有限来源，并用实际 retrieved/first_seen 完成时钟重新读取 `background` 用途资格后返回记录 | 不自建缓存、不绕过 engine、不调用 LLM、不改变模型或交易权限 |
| `read_sources(engine, now_ms, config=None)` | 只读取同 scope 缓存记录并重新计算 usage 资格，不发 HTTP | 不刷新慢源、不重取网页、不改变 source first_seen |
| `build_background(records, now_ms, *, current_price_usd=None, previous=None)` | 从 engine 记录生成四行背景：`allocation`、`inventory`、`financing`、`external_conditions` | 不生成方向总分、不估计胜率、不修改 `mu_ref` 或候选排序 |

每行背景固定输出 `summary_cn`、`metrics`、`cutoff_at_ms`、`missing`、`source_record_ids`、`fact_state`。背景会严格拒绝 `first_seen_at_ms` 或 `observation_end_ms` 晚于本次 `now_ms` 的记录；原始规范化值只作为 `*_source_values` 留痕，不能进入当前合格摘要。

## 2. Registry 与 usage 需求

主集成需要启用或确认以下产品。慢源建议业务用途 TTL 与 fetch 检查频率分离：业务 TTL 只判断事实是否适合当前用途，`request_policy.min_fetch_interval_ms` 控制实际外部检查节奏。

| product_id | 本轮用途 | 建议 fetch 节奏 | 业务使用说明 |
|---|---|---:|---|
| `btc.etf.flow.daily.v1` | ETF日净流与 F3/F7/v/q/U | 1小时或披露节奏 | `fetch` 可取新表；背景使用最新已闭合美国交易日，不用未到收盘的当日 |
| `btc.brk.cost_basis.v1` | CP_STH/LTH/ALL、源相位、源价格 | 6小时 | 必须 official search → metadata → sample；不得硬拼 series id |
| `btc.brk.realized_pnl.daily.v1` | realized profit/loss/cap 的完整UTC日窗口 | 6小时 | 日值、累计、rolling 按 metadata 分别处理 |
| `binance.um.btcusdt.oi.native.v1` | 原生 BTC OI 当前值与24h同口径 endpoint 差额 | 沿用现有 FMZ/服务器频率 | 缺交易所 `time` 不回填抓取时钟；24h窗口缺失则明示 |
| `binance.um.btcusdt.funding.settled.v1` | 过去结算 funding | 沿用现有或8小时结算节奏 | 只合并实际 settlement；预测费率单列不混入已支付 |
| `cex.usdt.borrow_rate.v1` | USDT借款报价或受阻身份 | 1小时，若有合法源 | 无公开机器源或授权只读时保持 `PARTIAL` 受阻，不申请私有权限 |
| `macro.usd.broad.close.v1` | 广义美元主源公开日值 | 6小时或官方更新节奏 | 当前实现用 FRED `DTWEXBGS` 公共CSV |
| `macro.us10y.nominal.v1` | DGS10公开日值 | 6小时或官方更新节奏 | 观察日来自CSV日期，抓取日不冒充观察日 |
| `macro.us10y.real.v1` | DFII10公开日值 | 6小时或官方更新节奏 | 与 DGS10/美元取真实共同观察端点 |

`macro.dxy.close.v1` 保留为未接通产品，不能用 `DTWEXBGS` 填充。`collect_sources` 在 registry 未启用某产品时会跳过该产品，不阻断其他来源。

`engine.fetch` 已计入每个产品的第一条 wire request；loader 内第2条及以后 wire 若当前 engine 暴露 `reserve_request(product_id, now_ms=...)`，模块会调用它消耗同产品额外预算。模块也保留 collect 级 `shared_http_budget_per_collect` 上限，防止一个 loader 内隐藏无限请求。

## 3. 字段契约

### 3.1 ETF 配置

来源优先使用 Farside 历史表 `https://farside.co.uk/bitcoin-etf-flow-all-data/`。parser 识别日期行，排除 `Fee`、`Seed`、`Total`、`Average`、`Maximum` 等汇总行；括号转负，`0` 是零，`-`/空白/`N/A` 分别保留为不同缺口状态。基金列动态识别，不写死固定名单。

规范化值包括：

- `fund_columns`
- `rows[].date / total_usd_m / total_state / funds / missing_funds / observation_end_ms`
- `metrics.f3_usd_m / f7_usd_m / v3_usd_m_per_day / v7_usd_m_per_day`
- `metrics.q_abs_usd_m_prior60 / u3 / u7 / windows / missing / summary_cn`
- `request_audit.actual_http_requests / max_http_requests / endpoints`

NYSE交易日由本地日历函数处理常规美国市场假日、Good Friday、Labor Day 和美东 DST 收盘时钟；没有安装 pandas、exchange_calendars 或 tzdata。

### 3.2 Bitview / BRK

实现只走官方发现流，并先用较短语义查询，例如 `capitalized price`、`short term holder capitalized price`、`realized profit`。官方 search 返回字符串 ID 数组时按 `id/series_id` 候选处理；只有 search 返回的 ID 经 metadata 语义核验且 metadata 暴露支持 index 后，才请求 sample：

1. `/api/series/search?q=<concept>&limit=<n>`
2. `/api/series/<returned_series_id>`
3. `/api/series/<returned_series_id>/<metadata_supported_index>?start=<integer>&end=<integer>`

`day1` sample 使用以 2009-01-03 为起点的整数 index，`date/day` sample 使用 ISO 日期窗口，`end` 按官方 exclusive 边界处理；`height` index 没有配置高度窗口时只记缺口，不把抓取时钟或日期字符串伪装成链上观察日。不把文档中的概念名拼成外部 ID。成本记录输出扁平字段，便于 projection 直接消费：

- `cp_sth_usd`
- `cp_lth_usd`
- `cp_all_usd`
- `source_phase`
- `source_price_usd`
- `price_basis`
- `observation_dates`
- `latest_observation_date`
- `series` 原始映射、metadata 摘要和 sample points

兑现记录输出 `profit/loss/realized_cap` series，并生成 `metrics.profit_14d_usd / loss_14d_usd / loss_share_14d / realized_cap_start_usd`。累计序列按差分，rolling 不重复累加，零活动分母为空。

缺 sample 或 metadata 不合格时，`observation_end_ms=0`，只保留 `retrieved_at_ms` 作为本系统 first_seen；不把抓取完成时间当链上经济观察时间。

### 3.3 融资

OI 当前样本使用 `GET /fapi/v1/openInterest?symbol=BTCUSDT`，值为原生 BTC 数量。若响应缺交易所 `time`，记录为 `PARTIAL`，`observation_end_ms=0`，不回填 `retrieved_at_ms`。默认同时读取 `GET /futures/data/openInterestHist` 的24h窗口，并计算 `change_native_btc / change_native_pct`；缺窗或不靠近目标点时保留原值但不形成合格24h差额。

Funding 使用 `GET /fapi/v1/fundingRate` 的 settlement 记录，按 `fundingTime` 去重。预测费率不混入 settled 合计。

借款记录默认是受阻：未配置合法公开机器源或已有授权只读输入时，不调用 `USER_DATA` 路径、不申请私有权限、不模拟账户签名。若后续提供合法公开样本，小时小数利率按 `hourly_rate_decimal * 24 * 365` 给出简单 APR。

### 3.4 宏观

当前公开下载映射：

| product_id | series | URL |
|---|---|---|
| `macro.usd.broad.close.v1` | `DTWEXBGS` | `https://fred.stlouisfed.org/graph/fredgraph.csv?id=DTWEXBGS&cosd=<start>&coed=<end>` |
| `macro.us10y.nominal.v1` | `DGS10` | `https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10` |
| `macro.us10y.real.v1` | `DFII10` | `https://fred.stlouisfed.org/graph/fredgraph.csv?id=DFII10` |

FRED 请求使用 `cosd/coed` 限定最近90天窗口，不拉全历史。CSV 的 observation date 是经济观察日；`retrieved_at_ms` 只表示本系统首次取得。`build_background` 用三条序列的真实共同观察端点计算5/20观察变化，利率变化另列 bp。

保留的失败身份：

- `source_real_sample_attempt.json` / `source_requests.json` / `source_state_actual/`：attempt01，证明旧解析把 Bitview 字符串 ID 搜索结果误判为空。
- `source_real_sample_attempt02_doublecount_failure.json` / `source_state_actual02_doublecount_failure/`：raw transport 复用模块 `_get` 导致共享预算双扣，保留为工程失败。
- `source_real_sample_attempt02_sourceprice_partial.json` / `source_state_actual02_sourceprice_partial/`：`source_price` 先命中 height-indexed by-term 矩阵后过早停止，保留为候选选择失败。
- `source_real_sample_attempt02_pnl_blocked.json` / `source_state_actual02_pnl_blocked/`：共享预算耗尽曾把 PnL 产品整体 blocked，保留为局部缺口传播失败。

最终 attempt02 共 24 次 HTTP，先采集 ETF、Binance OI/Funding、FRED 三条公开日源，再给 Bitview 成本与 PnL 使用剩余有限预算。结果：

| 来源 | 结果 | 说明 |
|---|---|---|
| Farside ETF | 可用 | 真实响应保存为 `source_raw02_farside...txt`；业务 `background` 资格通过 |
| Binance OI | 可用 | 当前 endpoint + 24h `openInterestHist`，原生 BTC OI 与24h同口径差额均保留 |
| Binance Funding | 可用 | settled endpoint 1次请求，预测不混入 |
| USDT Borrow | 受阻 | 无公开机器源或授权只读输入，0次HTTP，`PARTIAL` |
| FRED `DTWEXBGS` | 取得但当前背景过期 | 90天 `cosd/coed` 公共CSV成功；最后观察日早于业务TTL，不能作为当前合格美元背景 |
| FRED `DGS10` / `DFII10` | 可用 | 公共CSV成功，两条合格利率源共同端点为 2026-09-24；美元 broad 过期退出比较，使 external row 保持 `partial` |
| Bitview cost basis | 可用 | official search→metadata→day1 sample 得到 `cp_sth=73552.76`、`cp_lth=84755.66`、`cp_all=82112.69`、`source_phase=raging_bull`、`source_price=86137.29`，观察日 2026-09-24 |
| Bitview realized PnL | 局部缺口 | `realized_profit` search+metadata 证明为 `height` index；未配置 height 窗口，不猜边界；24次共享预算耗尽前未完成 loss/cap，记录 `bitview_shared_budget_exhausted`，不形成14日窗口 |

最终四行背景中 `allocation`、Bitview 成本、OI 与 Funding 可形成合格子事实；`inventory` 因 realized PnL 缺口仍为 `partial`，`financing` 因借款缺口仍为 `partial`，`external_conditions` 因美元 broad 过期仍为 `partial`。这些 partial 不阻断其它来源缓存，但不得在 MAP 工作台中渲染为完整背景。
