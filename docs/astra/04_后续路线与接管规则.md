# 后续路线与接管规则

## 1. 当前实施顺序

当前唯一实施及验收路线为[总体证据评级与单次综合评审v2](07_总体证据评级与单次综合评审_v2.md)：事实包和描述量→单次评审/分侧校验/本地行动→中文收束页面→场景、链路、真实API与独立审查→用户确认新版本地页面→向xxproject发布及核对真实FMZ版本→连续前向用途观察。

旧两次调用/旧行动字母/独立24小时报告均不再是新自动流程的前置要求。前序讨论保留在项目记忆历史节，不能恢复多个当前优先级。具体候选补偿另行验收，不因环境等级较高直接认可成交；本轮没有调整旧信号算法或交易开关。

以下为研究问题库，仍标记建议/待验证，不自动成为当前实现的额外硬门。

| 优先级 / 编号 | 待解决问题 | 所需证据与依赖 | 验收条件 |
| --- | --- | --- | --- |
| P0 / R01 | 不同目录、main、工作分支与运行资产的“当前”互相覆盖 | 台账列出的 SHA/文件哈希、源代码内部版本、已批准交付分类；若核验运行态，再收集同一时点服务与 FMZ 身份 | 每模块具有独立基线与证明上限；所有差异有解释，未知项保留未知；不以 main 或最高 tag 代替运行事实 |
| P0 / R02 | 当前执行路线分流，自动信号消费与人工审计门关系易误解 | 旧 v2.9.9 暂停点、manual-gate 规范、独立执行 v1.5.1/v1.5.2、事实优先重构宪法 | 明确选择的研究/验证对象及输入权威；此前不恢复自动消费，不迁移另一项目的门控默认值 |
| P0 / R03 | 执行正确性包含“不该动作”与“该动作不能饿死” | 目标 artifact 哈希、确认/订单/成交/持仓/结算/持久化证据，覆盖并发意图、数据缺口和重启 | 各动作满足当前事实契约；同一动作不重复；取消/部分成交后强制重读；合法 TP/对冲不被无关记账永久压住。只有精确版本外部证据可升级 FMZ 状态 |
| P1 / R04 | 不同信号刻度与触发机制的数据不可直接混用 | 原始 producer 版本、episode/固定轮次标签、方向/置信/缺失/阻断、观察窗与后续价格路径 | 按版本、触发类型、市场状态分层；v0.5.4 标定改变与 1.5.7 固定轮次单独标识；报告覆盖率、拒绝比例和反例，不把固定观察卡当 NeutralRepair 样本 |
| P1 / R05 | 时区与耐久先验是否对真实信号有增量解释 | K 线代理结论及真实信号样本，预先固定标签、观察窗和比较组；依赖 R04 | 分开市场先验、信号校准与期权收益；没有真实信号校准证据时维持 AUDIT_ONLY，不将时段系数乘入 confidence |
| P1 / R06 | VRP 的正 edge 能否跨盘口/时点稳定存在 | 同期 IV/RV、实际可成交 bid/ask、完整手续费滑点、两腿建仓路径与失败成本 | 区分窗口预筛和候选净 edge；薄 edge、拒绝和失败也入样本；理论定价、仿真、真实成交三类结果分开；不把阶段参数称为实盘批准参数 |
| P1 / R07 | GEX 数据迁移是否改变理论输入含义 | 旧抓取与公共 JSON 的字段/单位/时点/覆盖范围、缺失状态及有界历史对照 | 名义 GEX 与 proxy 不混单位；last-good 不能冒充当前有效输入；覆盖不足和单位不明能被明确识别 |
| P1 / R08 | 单次综合评审是否带来可说明的理解与决策增量 | 同一截面的支持/竞争解释、事实引用、人工判断变化、拒绝/恢复原因；旧盲审仅作历史研究材料 | 检查事实误读、缺口和有依据的反证；不把模型叙述流畅或重复一致视为独立置信；不恢复额外自动调用 |
| P2 / R09 | 全链成本和收益来源尚缺统一可比账本 | 具体期权结构、成交费用、保护腿残值、对冲成交/资金费、退出与结算；依赖 R03/R06 | 得到可对账的净 P&L；权利金/波动/方向/对冲贡献不重复计入；未实现与已实现分开，残值处置不伪装成交易所结算 |
| P2 / R10 | 最早源稿、补丁版本与分支继承存在缺口 | Gamma Observer v6 原档、v0.4.1/v0.5.1 引用来源、未收录变更证据 | 找到则补来源和变更依据；找不到仍保留缺口，不造日期、补丁或合并关系 |

建议顺序为 R01/R02 确定事实与研究对象；R03 按所选执行线验证，R04/R07 可独立整理数据；之后开展 R05/R06/R08，最后结合 R09 讨论收益归因。此顺序不要求为了文档整理重跑交易或启动服务。

## 2. 延续的边界

校对后的第一轮研究先处理三件事：信号如何改变实际使用决策、补偿判断由谁承担、分数名称是否符合真实事件与消费方式。具体反例见[核心档案 K01–K12](knowledge/01_核心思路与尝试档案.md)，研究提示词、六种视角和练习量表见[训练框架](knowledge/02_多元思维模型与训练.md)。知识训练不等于模型权重训练，也不替换生产 Prompt。

- 信号层的观察、方向、置信和触发规则以相应 producer 为准；固定分析轮次是采样机制，不是事件确认。
- VRP 回答补偿是否足够，对冲回答持仓后风险如何收束，LLM 提供旁路解释；任何一层都不能越权替代其他层的事实或许可。
- 历史参数和新建议明确分栏。需要改变方向规则、风险预算、阈值、输入权威或交易权限时，应形成单独的版本化变更任务与验收依据。
- 安全边界按项目和版本记载：整合交付物的门关闭，不代表独立执行 artifact 也关闭；代码常量为 True 不证明人工或实盘验证已经完成。
- 已有 fail-closed 检查不能靠输出“看起来完整”绕过；执行重构还需检验阻断是否符合事实，防止永久等待掩盖缺陷。

## 3. 每次接管的最小步骤

1. 阅读本专区 README、PROJECT_MEMORY、当前进度、与本次模块相关的台账；读取工作目录 AGENTS 和根项目记忆。先分清用户确认、已证事实和待验证建议，记忆不能覆盖新证据。
2. 核验目标远端、分支、HEAD、工作区差异和所引用 artifact 的内部版本/哈希。固定引用该次检查的 SHA，不在文档中只留可移动分支链接。
3. 明确本次修改的理论问题、允许改变的职责、输入与拒绝条件；先查历史是否已解决，避免重复实现。
4. 将相关的新证据加入台账：来源类型、项目/路径、SHA 或 SHA256、文内日期、提交日期、采样日期、证明上限。
5. 同步更新路线中的变化原因和替代关系、证据台账及进度页；受影响的知识卡同步修订，保留旧裁定适用范围。五份主文档及知识库保持相对导航可用；原始历史稿不覆盖。
6. 进行范围、链接和事实检查；实施任务另运行与变更相关的检查，不将历史测试记录重述成本轮执行结果。
7. 若发布文档，明确目标 `xxproject` 整理分支，验证远端提交 SHA，并同步可见文档副本。若将来涉及前端/策略/服务，则回到各自原有发布门，本专区不提供豁免。

## 4. 记录模板

以下模板用于后续条目，当前不填入假设性的版本或结果：

| 项 | 要填写的内容 |
| --- | --- |
| 问题 / 决定 | 触发变化的具体证据；新规则与被替代规则 |
| 来源 | 项目名、相对路径；远端固定 SHA 或本地 SHA256；必要摘录/章节 |
| 时间 | 文内日期、提交日期、tag/Release 发布日期、采样日期分别记录；未知写“未取得” |
| 版本体系 | 理论稿 / 工程 release / 策略内部版本 / schema / Prompt / 数据源，分别填写 |
| 落实状态 | 仅设计 / 本地存在 / 已提交远端；是否存在未提交差异 |
| 验证状态 | 本次实际执行结果 / 历史材料记载 / 未验证；包含版本绑定与证明上限 |
| 下一步 | 所需证据、依赖、可判定的验收条件；明确建议还是已批准任务 |

维护完成的标准是另一位接管者能沿证据找到原文、判断当前结论适用哪个版本、明确还有什么未验证。目录数量和文档长度不作为完成度指标。
