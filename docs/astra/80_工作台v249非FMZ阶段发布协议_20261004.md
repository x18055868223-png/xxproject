## 唯一源码与提交边界

提交和打包均从 `.worktrees/astra-signal-rating-v1` 的同一冻结提交进行。根目录旧前端不能作为 v2.4.9 的包源。所需资产分为：

1. `deploy/signal_audit/frontend/` 的页面源、VERSION 和既有静态历史卡；`deploy/signal_audit/` 的包脚本、完整/数据专用安装器、service/timer、env **示例**、Apache/Nginx 示例与运行说明。
2. `tools/` 的 workbench、underwriting/store/review/risk、MAP/数据引擎/retention、materializer 与既有信号工具。打包脚本逐项复制这些模块，缺文件即失败。
3. `demo/shared/data_product_registry_v23.json` 和 `demo/最新交付物/neutral_regulation_demo_fmz.py`；FMZ 文件仅用于版本与 schema 对照，不由非 FMZ 包安装。
4. 对应 producer、review、store、preview、前端、部署、兼容和失败路径测试，以及本协议与必要的长期规范。

以 Git 暂存名单和干净检出的 `package-manifest.json` 精确列出提交与包中的每一文件、大小和 SHA-256。文档可能受根 `.git/info/exclude` 的 `/docs` 规则影响，需显式加入本协议；不得据本地存在推断它已进提交。`.artifacts/`、私有 env、密钥、原始运行卡、共享预算账、临时包和服务器状态不能进入提交。既有 `xxproject/main` 项目资产树必须保留；本阶段目标工作分支不得强推覆盖 main。

打包器的 `source.head` 只说明所读 Git HEAD，`source.release_commit=null` 明确表示打包器不独立认证 release commit。发布窗口须在干净检出中将实际 HEAD、包 manifest/ZIP SHA、前端 cache token、有界协议和本协议同版核对，才可记录可复现的候选对象。此前 v2.4.8 包不代表当前 v2.4.9。

## 三层版本门禁

按项目 `AGENTS.md`，推送前同时核对 Git 提交、FMZ `demo_version`、服务器最新**原生真实卡**的 `identity.strategy_version` 及关键 schema 字段。最后一层需要带源身份、生成时间、是否 synthetic、是否 compat backfill 的实际卡证据；公开索引只是可见范围的证据，不能代替对未索引服务器内部记录的调查。

2026-10-04 只读复核：公开 `signal_cards/index.json` 仅列 15 张卡，最新确认时间为 2026-09-25 23:00（北京时间），其 `identity.strategy_version=1.6.2`；公开页面仍是旧 cache token。该观察与本地 FMZ 2.0.1 不一致，但不能证明服务器未公开目录绝无更新。若最新真实卡与三层仍不能证明一致，保持 `NOT_VERIFIED` / 不推送。若需要改变非 FMZ 阶段推送的规则适用范围，必须先得到明确的项目规则变更，不能借 package `reference_only` 字段静默豁免。

本协议没有授权 FMZ 本体部署。未见 2.0.1 原生真实卡及 `SignalSessionPremiseDurabilityContext`、`clock_window`、`backtest_delta_pp`、`validation_basis`、`decision_matrix.temporal_durability` 等关键字段的严格同版证据时，不宣布真实工作台可准入、真实新候选、交易就绪或全栈封版。materializer 兼容回填须带 `compat_backfill_applied=true` 和来源，不能伪装原生输出。

## 非 FMZ 安装与回滚条件

已部署 MAP 的预期接线是 `ASTRA_MAP_SOURCE_MODE=producer_manifest`、`ASTRA_MAP_SOURCES_ENABLED=0`、`ASTRA_MAP_PRODUCER_CURRENT_PATH=/opt/astra-map-data/state/current_map.json`。这是待对照的配置要求，不授权覆盖服务器私有 env。只有确认证据链 manifest/hash、源时钟、用途资格后才称接线通过；页面 GET 不抓慢源。

公网 HTTP 只读。手动评审令牌仅经可信 HTTPS 或经验证的 loopback 访问；未经认证 POST 必须拒绝。不得绕过证书、开放明文令牌或降低服务端预算、冷却、幂等和单任务门。

部署前只读记录实际 unit/timer、代理、私有配置、最新卡及 producer 健康，备份版本化文件和运行状态。写入前静止会读写被替换代码的工作台、materializer 与旧自动 LLM 任务，停止失败即停止安装；保留卡、sidecar、账本、冷却和幂等记录。完整与 data-only 安装器分开验收，已部署 KPF/MAP 不默认重装。回滚先停新任务，恢复上一已验非 FMZ 版本与配置；不覆盖 FMZ 或账本，不自动恢复旧自动 LLM timer。

真实 provider `bounded_claim_ids@2.4.7` 的小范围兼容验收必须受现有预算和账本约束；本地模拟不能替代。邮件与 23:00 快照、可信入口、代理、状态迁移、KPF 90 日 WARMUP/缺借款/缺 μ 等应分别给实机证据或保持“未启用/未知”。本地产品与包测试通过不等于服务器运行验收。

本阶段停止条件：任何三层版本、源身份、协议、包内依赖、鉴权/预算、关键 producer 字段或回滚路径未核对时，保留原系统和公开输出，不把 `NOT_VERIFIED` 改写成 `PASS`。
