## 内容为什么不能采用

模型把“Put 最大损失接近价差宽度减补偿”作为反证，并把短腿附近移动描述为净额转负。主 agent 与独立 explorer 用同一冻结合同核对后判为重要错误：

- 95,000 以下的 BTC 赔付为 `2000 / 交割价`，没有固定 BTC 深尾上限；宽度只对应 USD 内在值差上限。
- 在短腿 97,000 处赔付为零，静态净额仍为 `+0.004 BTC`。本样本的盈亏平衡点约为 `96,613.55 USD`。
- 交割价 47,500 时，赔付约 `0.04210526 BTC`，静态净额约 `-0.03810526 BTC`；交割价 1,000 时，赔付 `2 BTC`，静态净额 `-1.996 BTC`。

另一个“背景可用但状态缺失”的说法来自原输入同时携带 `usable/missing`，不是模型凭空创造。已在当前投影收为单一状态口径，但原回答因前两项金融事实错误仍不予采用。

**本轮验证器可以检查 JSON、引用、快照、文本约束和关键输入缺口，不能证明任意自然语言金融命题正确。** 没有为了让回答通过而放松验证器、隐藏原文或重新调用。HTML 顶部明确拒收，先展示确定性反例，再折叠保留原始模型正文。

## FMZ 裁定与后续边界

根目录与工作树 FMZ 文件仍字节一致，内部版本 2.0.1，本轮实际修改行数零。文档 76 给出了死状态/配置、小 helper、旧进程内 LLM 封装、重复 tick 审计及输出投影的清理次序；SpaceGate 恢复状态和连续截面环保留。实际 FMZ 加载版本仍缺新的原生运行证据。
