## 这次调整了什么

模型仍使用既有 DeepSeek 配置。原目录选择保留，新解释可以基于本次输入综合说明关键事实、变化、冲突及其对本单的含义；数值和权限仍由程序负责。引用展开显示程序从实际输入取出的片段，不让模型补写来源。新解释的选择范围受本次有限目录约束，去掉旧短摘要每类六项上限；逐项成员、角色、重复、关键反证及权限检查保留，旧协议仍按原规则回放。

主评审未准入时，同一评审接口可使用 `purpose="observation"`。它共用鉴权、预算、冷却、互斥和幂等，只产生研究回执。资料局部不足限制对应结论，费用、风险参考或完整窗口缺失不再整体关闭观测解释。原主评审门和交易权限保持不变。

MAP 消费修复只接受双方原始哈希有效、其他清单字段一致、内层记录逐条属于外层、额外记录符合已核实 FMZ 追加产品的情况。连续周期中，已接受 GEX 可已在内层，也可作为第五条追加记录；其余四条须齐全。保留兼容来源标记，重建已有 MAP；服务器 producer 原件未被改写。

完整回执留在本地审计原件中。公开工作台复用已有摘要过滤；需要权限的完整 proof 支持标准 gzip 下载，仍保留传输大小限制。

## 验证依据与使用边界

本轮来源、真实请求、provider 原始响应、严格校验和浏览器走查保存在 `.artifacts/observation_baseline_20261006_01/`；最终结果以该目录 `ACCEPTANCE.json` 和 `samples/current_validated/actual_llm/receipt.json` 为准。前三次拒绝原件分别留在 `samples/current/`、`current_corrected/`、`current_final/`：引用/数值约束、目录 ID 混入事实引用、旧条数限制。第三次同时发现宏观变量混成 BTC 方向的语义风险，继续保留拒绝，没有修剪原始响应后冒充成功。最终修复区分事实引用和目录、各变量方向及概率边界，再用新快照验证。接口回归使用可控 transport，实际调用单独记录，不将模拟测试当作 provider 成功。

仍有的限制：

- μ/M 未知，不能宣称补偿充分、正期望或模型有经济优势。
- GEX、部分慢源和历史窗口各有时效或资格限制；保留能读的事实，不把同源信息当多票确认，也不把有限片段写成完整趋势。
- 本地 8919 未复制生产凭据和预算账，因此新的真实模型按钮保持关闭。本轮实际调用通过既有服务器配置和共享预算完成验证；正式交互调用需要批准部署工作台后启用。
- 本地连续更新和本次真实调用是观测基线的验证，不等于长期可用性或生产部署证明。
