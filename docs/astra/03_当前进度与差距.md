## 1. 主路径应怎样理解

目前可证的主路径分成两条在研工作流，而不是一个已经自动闭环的系统：

1. **信号使用主线**：实时因子 → producer `1.5.7` 的事件/固定轮次只读记录 → 审计页及 LLM 旁路 → 人工理解和选择如何使用。后续模型信号调整以这条线的目标、样本和真实消费方式为准。
2. **执行工程主线**：人工给定方向与约束 → 市场候选、确认与成交 → 持仓/对冲/退出/结算。独立执行 v1.5.2 是成熟行为的本地后续；事实优先重构为另一条当前候选线。源码不能证明用户此刻在 FMZ 运行的是哪一个。

旧“信号包直接驱动执行”设计并未由当前 manual-gate 自动实现；人工从审计页转为执行参数的决策，当前也缺少一份已验证的端到端归因链。**整理不能替用户默默选择一条实盘策略，也不能把尚未连接的模块画成已闭环。**

次级知识库保存核心思想、失败尝试与迁移经验。进入主线的条件不是名字熟悉，而是能说明目标、输入、实际消费者、失效条件和可检验的增量价值。

## 3. 当前路径的校对裁定

### A. 方向与开仓权已主动分离，但用途链尚不完整

整合 `demo/execution_build_manual_gate/realsrc/src/strategy.py` 的人工审计主链和最新交付 README 都明确由人工参数计划，不是接收 producer 的事件后自动执行。这是有意边界调整，不是死代码证据。

校对结论：第一性“分工与拒绝条件明确”仍在；早期“系统自动连接”的整合叙事已不适合当前入口。后续研究应先记录某条信号究竟影响了人工的方向、等待、结构审视还是放弃，否则无法判断信号有没有实际价值。

### B. 定价补偿职责在新执行线存在待解释缺口

已核对的消费链：旧 manual-gate `strategy.py:299` 的计划预览及 `:1221` 附近运行分支调用 `apply_vrp_gate`；缺 `market_context` 标为 `VRP_CONTEXT_MISSING`，不生成可锁定候选。

新重构 `src/runtime_loop.py:839` 的 `_build_library` 调用 `build_candidate_library`；`src/planner.py:573–632` 计算 bid/ask credit、手续费、容量、最大损失和比值，`credit <= min_net_credit` 会拒绝。在这条主链及当前单文件中，检索并核对未发现旧 VRP 的 IV/RV 补偿输入或同等净 edge 门。

裁定是“**早期定价职责未在已查新路径中得到同等证明**”，不是“策略无效”或“必须立即回接旧 VRP”。净 credit 为正说明收入方向与基本结构可行，不足以证明承担的尾部风险得到足额补偿。是否改由人工承担、采用另一种定价模型，或保留为待实现职责，应成为单独的版本化决定。

### C. 有些概率名称实际是代理刻度，而且确实影响排序

新重构 `src/planner.py:619` 将 `win_rate` 定义为 `1-abs(short.delta)`，`:851` 附近把它与收益风险/资金效率放入综合排序。因此它**不是不被消费的形式字段**，而是被消费但名称容易过度承诺的代理。

同项目 `src/hedge_policy.py:45` 的 `first_touch_probability` 在 IV 可用时使用无漂移对数距离近似，返回 `HIGH`；缺 IV 时以 `1.8×abs(delta)` 有界回退并标 `LOW`。`position_manager.py:1276–1327` 用它形成当前概率、相对入场漂移并分类。`HIGH` 在这里反映输入/方法分支，不能当成统计置信区间或已校准概率。

后续应先改正研究与展示解读，再决定是否校准或替换模型。本次只在整理文档中校正概念，没有修改上述代码或现有 UI。

### D. 只读层需要验证“被怎样使用”，而不是要求它越权

时区、耐久与 LLM 旁路的 AUDIT_ONLY 设计有明确理由，不能因为不直接改变订单就判为形式主义。判断其实际价值应查：是否改变了使用者对证据有效期、反例或等待条件的理解，以及这些改变能否留下可复核记录。

反过来，如果只新增一个分数、一个段落或一个 “Bayesian” 标签，却没有目标事件、先验/似然依据、实际消费者或对照检验，也不能把它算作新增推理能力。当前 LLM 的结构化报告存在，不等于真实后验概率模型已经训练或验证；详见知识库的判定规则。

### E. 已找到默认权重关闭的实际案例

整合 manual-gate `config.py:39` 的 `PLAN_WEIGHTS.manual=0.0`。`plans.py` 中 confidence→preferred_delta→delta_fit 的计算仍存在，但初筛及综合排序都乘以该零权重，调用方也实际使用此配置。因此该契合项在这两个排序阶段不贡献分数，不能只因看到计算函数就写成“置信驱动选腿”。此结论仅限该默认配置和阶段，详见[知识卡 K12](knowledge/01_核心思路与尝试档案.md)。

现有 LLM Prompt 则已经明确把情景权重标为主观参考；不要把有意的旁路、关闭的排序项、被消费但未校准的概率代理归为同一种问题。
