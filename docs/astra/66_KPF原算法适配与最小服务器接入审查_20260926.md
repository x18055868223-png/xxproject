## 算法与用途

原链路读取 Binance USD-M BTCUSDT aggTrades 日文件，按 100 BTC 切成交量柱，在 50 USD 内部桶上累积密度；0—7/7—30/30—90 日权重为 1/0.75/0.35，做三点平滑，按峰和两侧谷底提取 raw basin。90 日历史窗和 60 日新证据窗、证据等级仍属于原算法。250 USD display_center 及 ±125 展示带用于阅读，不能代替 raw_basin_low/high。

这些区域描述历史成交在哪里较密集，可以作为当前价格路径的观察背景。它不直接估计期权到期概率、选边、胜率、EV 或未来承接效果；当前路径的进入/跨区/返回仍须由真实样本证明。Binance USDT 历史价系不能直接升级为 Deribit BTC/USD 指数的精确共位；无合格映射时保留名义背景。

证据：原项目 `kpf/volume_bars.py`、`density.py`、`basins.py`、`targets.py`、`evidence_rules.py`；`README.md` 明确算法不是交易/方向系统。

## 最小落地范围与验收顺序

优先沿用已有 `kpf_server/` 单 worker、流式、逐日增量版本，保留下载/校验、日缓存、成交量柱、密度、basin、证据与状态；不迁入 PDF/HTML 全分析、SLRP 与 walk-forward 研究流程。精简部署资产，不改变算法窗、权重或证据规则。Astra 侧只保留最新合格快照和有限审计；KPF producer 仍需要其算法的 90 日滚动计算数据，不能按“下游只留快照”把计算依赖删掉。

1. 增加薄导出契约，直接读取原 `StreamingKpfResult.debug_candidates` 的已计算结果；联合 snapshot/audit/raw zones 的同运行身份和 hash，原始上下界、原展示中心、证据等级/拒绝理由、源市场、价系、观察端点与生成时刻原样保留。
2. 区分公开合格主目标与 debug 弱候选/连续性 scaffold，不把所有 debug basin 自动标为 can_use。新接口发布同版本原子结果；消费者 first_seen 是实际可得时刻，不回填成历史运行时已知。
3. 用同一批冻结输入比较原输出与精简版，逐字段证明 basin、证据和公开 targets 相等；拒绝 CSV/JSON 错配、混版本、过期、缺界/缺钟、无价系、弱证据及损坏文件，并保留失败身份。
4. 真实输出进入 Astra 引擎后，先验证名义显示与冻结责任解释；没有 qualified mapping 不进行精确距离/BE 共位。GET、选区域与 LLM 复核不触发 KPF 计算。
5. 完成本地 producer/consumer 联调与资源验收后，再按项目既有页面确认门进入推送/服务器部署，最终单独验收持续新鲜真实输出。

本审查没有升级经济裁定、模型、交易权限或 LLM 额度。当前 MAP v2.4.1 可做本地呈现验收；**完整真实 KPF 数据工程仍有导出及最新样本缺口，不可封为已部署或已接通。**
