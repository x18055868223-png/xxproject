# Decision Path 层：最小闭环设计

日期：2026-10-14 · 分支 `claude/astra` · 状态：方案，待用户确认后实施

## 0. 要解决的问题

组件已经够多，缺的是一条固定的阅读与推理顺序。这条顺序要满足四点：
- 先事实，再结构，最后才是解释；
- 权利金、宏观叙事和 LLM 都不能过早锚定判断；
- 每一步都必须给下一步带来新信息；
- 能在实盘中被验证，再被修剪。

Decision Path 是一个独立但极薄的层：
- 它只集中定义顺序，并给每一步一句程序读数；
- 事实与分析仍留在原来的组件里，它不复制，也不新增分析。

## 1. 现状：页面实际的阅读顺序

页面现在是这样排的：状态条 → 价格地图 → 承保前置条件 → 两张保单卡 → 锁定追踪 → 五要素 → 外源事件 → 资金与慢背景 → 推理审计 → 记录。

每张保单卡内部的顺序是：腿与剩余时间、模型解释标记 → 四个数字 → 事件 → 约简 → 距离规则 → 四要素对照 → Q1/Q2（模型或程序）→ 操作。

和原则冲突的地方有四处：

| # | 冲突 | 后果 |
|---|---|---|
| 1 | 权利金（理论最大净信用、毛信用占宽度）与责任距离并列在卡片第一行 | 补偿在风险之前被看到，形成锚定 |
| 2 | Q1/Q2 的模型文本在卡片里，排在五要素（结构、流向）之上 | 先读结论、后读结构，叙事先于事实 |
| 3 | 五要素整块排在锁定追踪之后，而且不按"位置 → 运动 → 外部"分层 | 结构判断没有固定的入口 |
| 4 | 宏观、跨资产、慢背景永远全量显示，没有"本期不必参考"的出口 | 读者每次都要自己过滤，注意力成本高，也容易被叙事带走 |

## 2. 推理链：七步，每步一个问题、一个小词表读数

| 步 | 问题 | 读哪里（已有组件） | 读数（固定词表） | 对下一步的增量 |
|---|---|---|---|---|
| D0 资料 | 现在能读吗？ | 状态条、报价时效、FMZ 事实 | 可读 / 部分可读（列出缺口）/ 停 | 不可读就停，后面不读 |
| D1 责任 | 这张保单承担什么？ | 合约、责任区、赔付形状、到期 | 方向、责任区、最坏赔付形状、剩余时间（不出现权利金） | 确定"什么算坏"，后续每一步都相对它判读 |
| D2 位置 | 现价离责任区在结构上有多远？ | 短腿距离对比到期前隐含波动；空间位置（先遇到什么）；锚点；Gamma 体制 | 缓冲：宽 / 中 / 窄（以预期波动为尺）；路径：途中有结构位 / 没有；钉住 / 放大 / 过渡 | 把"远近"从百分比变成结构语言 |
| D3 运动 | 市场正怎么动，会不会被放大？ | 量价路径、主动成交 4h/12h、M-DIE、Gamma | 朝责任区 / 背离 / 无方向；持续 / 新近 / 反复；若同时朝责任区且负 Gamma，判为易放大 | 位置是静态的，这一步回答"在往哪去" |
| D4 外部 | 哪些外部信息这期真的值得看？ | 事件日历、跨资产、宏观 | 只列通过过滤的条目；其余写"本期不必参考"并说明原因 | 默认允许忽略；只有通过过滤的才进入判断 |
| D5 变化 | 这些状态是怎么变到现在的？ | 锁定后：依据账本；锁定前：已有的多窗口字段（4h/12h、24h/48h、锚点与空间门变迁） | 持续 / 新近（几小时内）/ 反复 | 区分"一直如此"和"刚变"，后者权重更高 |
| Q1 风险质量 | D1–D5 合起来，这张保单的风险是什么样？ | 程序汇总 D1–D5 | 风险要点 ≤3 条，每条都引用某一步的读数 | 收束；这一步之前不看钱 |
| Q2 风险补偿 | 这样的风险，给的钱够不够看？ | 净信用、信用占宽度、市场估价差（这里第一次出现） | 补偿相对 Q1 要点的对照（不给概率） | 钱只在风险成形之后出现 |
| 审计与约简 | 模型是否认同程序读法？还剩什么需要你判断？ | LLM 复核、决策约简 | 认同 / 有分歧（逐条）；待你判断的问题 ≤3 条 | 默认折叠，读完前面再展开 |
| 决策 | 承保 / 不承保 / 只观察 | 用户 | 记录"由哪一步决定" | 形成可验证的样本 |

D4 的过滤规则（第一版）：
- 事件：只列合约有效期内的 FOMC/CPI/非农/PCE/PPI/GDP。没有就写"本期无重要事件"。
- 跨资产：只写"本期合约是否跨过美股交易时段"。相关性已验证为日频无参考价值，所以不进判断。
- 宏观：只有宏观体制为逆风或顺风、且方向朝向卖出侧时才列出。中性一律写"不必参考"。
- 资金与慢背景（ETF、OI、资金费、链上）：永远不进路径，只留在下方背景区，作为"不投票"的参考。

防污染规则（硬约束）：
1. D1–Q1 的所有读数不出现任何权利金数字。
2. 模型文本只出现在审计这一步，默认折叠；保单卡上不再放模型的 Q1/Q2 正文，只放程序读法。
3. 每步的读数只用固定词表，不用形容词或叙事句。叙事只允许出现在 LLM 审计里，而且必须引用程序读数。

## 3. 缺失维度审计

已有组件覆盖了责任、位置、运动、外部、变化这五层，不需要再加因子。只有一个真正必要的维度缺失：

- **已实现波动（RV）对隐含波动（IV）。**
  - 卖权利金的核心问题是"隐含是否高于将要实现的"。
  - 现在 Q2 只能把权利金和宽度、市场估价比，不能和波动本身比。
  - 程序的证据路由里已经把它列为缺失项（`astra_evidence_routing_v1.py:1054`："BTC RV未在当前已冻结事实中发现"）。
  - FMZ 快照里只有 M-DIE 位移评分用的窗口级已实现波动：字段 `factor_snapshot.m_die.components.displacement.raw.realized_vol`，算法见 `neutral_regulation_demo_fmz.py:11524`。它没有年化，口径不能直接和 IV 比，工作台也没有读取。
  - 补法很轻：用已有的现货价格序列算 24h/7d 已实现波动，与到期 ATM IV 并列，作为 Q2 的一行。

其余维度都已有，问题是它们是否重复，这要靠 §5 的实盘记录来回答，不是现在加东西：
- 流向 vs 量价路径 vs M-DIE：三者可能高度共线。
- 锚点 vs Gamma 体制 vs 空间位置：可能存在重复。

## 4. 最小闭环（第一期）

| 件 | 内容 | 规模 |
|---|---|---|
| A. `tools/astra_decision_path_v1.py` | 纯函数，输入是现有读视图里一张候选及共享事实，输出每侧 D0–D5 + Q1/Q2 的读数。每步包含读数、一句话、读了哪些组件（引用）、缺口。不新增数据源 | 小 |
| B. 读视图字段 | 每个候选附 `decision_path`，供页面和复核使用 | 小 |
| C. 页面 | 保单卡改为按路径排列。权利金从卡片首行移到 Q2 步；模型文本移到审计步并默认折叠；每步读数旁链接到原组件；五要素等组件原样保留在下方 | 中（前端需页面确认） |
| D. 记录 | 每次定时复核（UTC 02/14）、每次锁定、每整点，记一行精简路径，写入 `decision_path/YYYYMMDD.jsonl`，每行约 1 KB | 小 |
| E. 候选结算 | 每张被记录过的候选到期后，用 Deribit 交割价算到期结果（复用锁定的结算代码），回填到记录上。这样每天两张候选都有结果，不依赖是否锁定 | 小 |

第一期不做的事：
- 不改 LLM 复核输入，不加 RV，不做候选的低频影子记忆；
- 现在的 D5 只用已有的多窗口字段，锁定后用账本。

## 5. 如何在实盘中找到增量（后续核心迭代）

每条记录里，每一步都有一个读数，到期后有结果。积累 2–4 周后（约 30–60 张候选），出一份很短的报告：
- **改判率：** 这一步的读数有多少次改变了前面几步的初步结论。从不改判的步骤可能是重复的。
- **同向率：** 与上一步读数同向的比例。持续超过 90% 的，说明与上一步共线，考虑合并。
- **结果分组：** 按每步读数分组，看到期结果分布。样本很少，只看是否明显分离，不算概率。
- **用户决策与结果：** "由哪一步决定"与结果的对照。

修剪规则：一步在 4 周内既不改判、又不分离结果，就降级为背景，从路径里拿掉。新维度（例如 RV）先作为候选步骤记录，验证有增量后再进入正式路径。

## 6. 第二期（视第一期数据决定）

1. RV 对 IV，作为 Q2 的一行。
2. 候选的低频影子记忆：每个默认候选每 5 分钟记一行采样行（复用锁定采样格式），D5 在锁定前也有真实路径。
3. LLM 复核改为"对路径的审计"：输入是路径读数，输出是逐步认同 / 分歧，加约简。
