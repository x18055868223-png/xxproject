## 已落实的收口

| 环节 | 本轮行为 | 保留的边界 |
|---|---|---|
| 财务核算 | 同一冻结合同生成责任表、盈亏平衡点和 BTC 尾部性质 | LLM 不能改数值、公式、费用或风险输入 |

| 来源消费 | 工作台可显式只读消费 producer 的 `current_map.json` 冻结记录 | 不共享可写 DataEngine 目录、不隐式慢源补抓 |
| 来源失败 | 缺失、过期、损坏、错版或中途更新保留合同账，MAP 标 ERROR/缺口 | 未合格来源不进入 LLM 可引用 MAP 目录；原生硬门保留 |
| 来源健康 | producer 产品从实际消费记录派生 health，报价/合同保留本地 health | producer 失败不借旧私有缓存显示健康 |
| 风险模型 | 标准配置可加载受审资产并返回 `risk_consumption_diagnosis` | 不做推理，不注入 risk_provider，不填 μ，不授予消费资格 |
| FMZ | 删除死配置、写后不读状态和无消费者旧 LLM 包装 | 连续截面、SpaceGate、宏观 hard veto、历史审计和只读默认保留 |

投影还修复了一项真实重放缺陷：MAP 背景对象按固定键序派生缺口列表，避免 JSON 账本排序后同一快照得到不同 `projection_hash`。

producer 校验包括 schema、8MiB 有界读取、UTF-8/JSON、生成/冻结时钟、有效期、内外 manifest 内容与 hash、同 record ID 和同 product/scope 冲突。TTL、资格判定、freeze 和 health 均复用现有 DataEngine 规则，不另立一套策略。

旧真实捕获的内嵌 manifest 存在完全相同记录的重复项。仅在去除精确重复后整个 manifest body 与外层完全相同的情况下允许只读消费，并显式记录 `legacy_exact_duplicate_manifest=true`；不改变捕获原字节或原 hash。其他内容、时钟或身份冲突仍拒绝。
