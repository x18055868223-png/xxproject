## 当次双侧真实采集与失败回显

在看到两侧报价结果之前，[54](54_当前保单发现口径补充冻结_20260925.md)已冻结发现规则与费用假设。2026-09-25 08:34 UTC 一次手动只读采集选到 26SEP26 08:00 UTC 到期，发现时剩余 23.4241 小时；Deribit 发现指数 84,358.48 USD。两侧各 1 BTC，宽 2,000 USD，**只并列审计，不选边也不同时建仓**。这是 2026-09-25 的新采集身份，不进入截至 2026-09-13 的历史研究冻结数据，也不是独立未见检验。

| 候选 | 卖腿 / 保护腿 | 可见双腿信用 | 公开费率假设 | 静态赔付预算 `B_loss` | 冻结风险 `μ_ref/M_ref` |
|---|---|---:|---:|---:|---|
| Put | `BTC-26SEP26-84000-P` / `BTC-26SEP26-82000-P` | 0.0035 BTC | 0.0004125 BTC | 0.0030875 BTC | null / null |
| Call | `BTC-26SEP26-84500-C` / `BTC-26SEP26-86500-C` | 0.0044 BTC | 0.0004375 BTC | 0.0039625 BTC | null / null |

Put 估值 08:34:51.985 UTC、Call 08:34:53.553 UTC；两侧两腿盘口的状态、深度、5 秒年龄、2 秒腿间时差与指数一致性均通过。费用是公开 taker 与权利金上限逐档假设、daily 交割零费，非账户实际费；盘口非成交。服务器 `snapshots.jsonl` 同一原始 FMZ 行 SHA256 `f5361e46decda635e2eb1acf114fc1761571481f64cb56d75cf05be24364ed8f`，事实时点 08:34:24.851 UTC，对两卡分别早 27.134 与 28.702 秒；原始模式 `live_public_read_only`、标的 BTC、价格来源/观测时间通过。本地只转出该行的最小事实投影，不复制整条原日志或改服务器。Put 有同截面量价下行的不利方向背景；Call 未见同口径直接反证，但不能推断 Call 更优。两侧缺合格、同候选冻结物理赔付参考，故 `μ_ref/M_ref` 仍空，正信用不是正期望。

研究侧凭据只在本机请求进程内读取，未写进制品；生产 `llm.env` 与额度账未使用。双卡各第一请求为 `FORMAT_ERROR`，各第二请求为 `SEMANTIC_REJECTED`；共用研究账总计 4/4 HTTP，均收到实际 API 响应。没有合格正文，不得算成正常联合复核通过。第一次客户端只记录了状态、请求 hash 和用量，**没有保存这四份原始 API 回复**；这一不可恢复证据缺口原样标注，不因失败而再请求。代码已改为后续在解析/校验前落原始回复及 hash、保存拒绝原因；本次旧尝试状态不伪装成已有原文。

最终本地预览为 `http://127.0.0.1:8890/`，浏览器实看两张卡的责任、费用、币本位深尾、FMZ 来源、Put 反证、`μ_ref/M_ref` 缺口及“已调用，语义校验拒绝 / HTTP 2 次”回显；索引改称“公开盘口采集截面”，避免把静态报价称为现在实时。最终证据 `.artifacts/astra-underwriting-v20-local-20260925-r5/acceptance.json` 和同目录 `verify_acceptance.py` 核验八张卡：五张旧卡与一张历史回放逐文件 SHA 不变；两张新卡独立追加；预览 `app.js` 与源码 hash 相同。

## 验证及保留失败

- 本版新路径最终 60 项通过，包括旧真实盘口、当次双侧规则、费用/时钟/身份、合成 μ/伪造 FMZ hash 反例、同版评审 fake transport、失败响应未来落盘、落账故障不追加 HTTP、独立卡到前端与旧卡兼容；真实请求结果如上，不能拿 fake transport 的通过替代。最终前端相关回归 78 项通过、1 项需专用 canary 目录而明确排除。`node --check app.js` 与新增 Python 模块编译通过。
- 扩展前端/物化/核算回归使用 `python -X utf8 -m pytest ... -k 'not root_final_canary_cards_have_no_reader_text_leaks'`：132 通过、1 失败、1 因需专用 canary 目录而显式排除。唯一失败为基线老测试期望 `display_projection_version=2.2.0`，而 HEAD 已固定 `2.3.0`；本轮未改测试或旧物化逻辑。首次无 `-X utf8` 的旧 materializer 测试因 Windows GBK 解码 UTF-8 文件失败，失败记录保留。`test_signal_llm_review_pipeline.py` 是独立脚本而非 pytest fixture 文件，以原入口运行显示 PASS。旧 `test_fmz_157_fixed_analysis_round.py` 脚本 PASS；旧 `test_fmz_157_producer_contract.py` 期望 FMZ 1.6.1、现有源码 1.6.2，基线失败保留。
- 独立项目 agent 分别复核合同/时钟/费用/FMZ 标的和 LLM/UI 接线，发现的费用覆盖、BTC 标的校验、缺口硬约束、合成风险隔离、直接 JSON 伪来源 hash、review schema/适用性展示与正文守卫、annex→页面桥接已修并有针对性测试。其余历史失败没有覆盖或清除。

## 待推送前的硬边界
