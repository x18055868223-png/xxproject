## 必须保留的状态

- `SpaceGateStateTracker:10830–10919` 保存 `since_ts_ms / previous_state / last_transition_ts_ms`，重启延续和转变语义需要它；测试 `tests/test_fmz_20_space_gate.py` 已覆盖。
- `WorkbenchSnapshotExporter:13089–13380` 是有界连续截面环，事件卡 JSONL 是事件历史。两者频率、身份和消费者不同，不应混成一种记录。截面环已有原子替换、短写失败、cadence 与非有限数测试。
- GEX LKGV 显式 stale，SpaceGate 拒绝 stale/lkgv；它没有以旧数据打开空间门，不能把所有缓存一律删除。
- FMZ 短推是提醒，完整审计证据在 JSONL/静态页。它们适合共用投影，不适合互相替代。

## 更成熟的整合方式

当前更合适的是“一个事实冻结体 + 无状态派生投影 + 单一复核执行器”，没有证据需要工作流框架、多模型投票或新持久层。研究复核的本轮落地已经采用这个方向：保留完整历史事实，LLM 只读可核验投影，成功/失败均留在原尝试账，生产账不接收研究回执。

结构化 JSON 只能约束形状，不能证明事实或授予权限。继续保留本地精确字段集合、快照绑定、来源资格和语义检查；若跨语言消费者增加，再考虑统一 JSON Schema。标准对额外属性的约束见 [JSON Schema object](https://json-schema.org/understanding-json-schema/reference/object)，DeepSeek 当前 JSON 输出和截断边界见 [官方 API](https://api-docs.deepseek.com/api/create-chat-completion/)。这是基于现有消费者数量与失败边界作出的架构判断，不是工具能力的保证。

## 建议顺序

先处理无消费的配置与死状态，并迁移旧 LLM 契约测试；再统一输出投影和单 tick 合同审计；最后单独讨论 Macro cached hard veto、session buffer 等行为语义。每步单独验收，避免借“收口”同时改掉安全边界和业务定义。

两个独立 explorer 分别审计状态生命周期与冗余输出，主 agent 复查关键源码、哈希和 AST，并运行本地 producer/export 回归；执行结果记入文档 77。没有使用本地测试替代 FMZ 线上验收。
