# 同机 KPF 轻量生产消费与 MAP 数据完备性：实施冻结

用户本轮授权设计简化部署并推到权威远端，KPF 生产与消费都在现有服务器运行；继续补齐 MAP 数据工程并检验真实完备性。范围为独立数据部署，不发布尚待新页面确认的前端，不升级 FMZ 交易规则、模型、统计阈值、经济裁定或 LLM 调用权限。本轮可以安装这一路数据服务，不能由安装成功认定数据已经齐备。

## 已核验容量与停止条件

2026-09-26 首次只读资源回执 `.artifacts/astra-kpf-light-server-20260926/server_resources_run01.json`：2 CPU，物理内存 990,969,856 B，可用 417,202,176 B，根盘剩余 13,554,864,128 B。已有 FMZ、GEX、Web/PHP/数据库共存，不能按旧 README 的 2GB RAM / 60GB SSD 判断。

KPF 单任务、低优先级、CPU 配额 50%，systemd 最高内存不超过 240 MiB；最低空闲磁盘 6 GiB，KPF 计算存储预算 5 GiB。服务不开放端口或读取 LLM 凭据。超过容量、checksum 失败、文件混版、坏源、计算未完成、观察/可得时钟缺失、未齐90日，均退出合格层并明确状态。禁止缩历史窗、减样本、截原始 basin 或删真实尾部来通过容量门。

## 保持算法的轻量化边界

90 日历史、60 日证据、跨日连续 100 BTC 成交量柱、50 USD 内部桶、原权重、证据和主目标筛选不变。优先仅保留官方 checksum 验证的原日 ZIP 单副本，流式解析，去掉冗余 verified ZIP、未压缩 parsed CSV、全窗口 bars 数组、PDF、研究/SLRP/replay 部署依赖。原 ZIP 容量/运行时超门时明确阻断；其他紧凑缓存必须先证明顺序、跨日柱相位、密度、原 basin 和公开目标等价，不能只保存每日柱后假定90日重切等价。

每5分钟检查和处理至多一个缺失完整日；只有新完整日与完整窗口变化才重算，不每5分钟扫描90日。初始化按真实进度 warmup，旧结果不刷新源时钟。原算法代码按文件 hash 固定，独立 namespace 安装可回滚；仅保留当前/上一版本快照与有限失败审计，计算需要的90日压缩窗口按白名单滚动维护。

## 导出与消费契约

生产端输出同运行 `version_id` 的 snapshot/audit/raw zones JSON，原始 basin、展示中心、等级/类型/拒绝理由分别保留；仅原公开主目标且 A/B、数据/自审查通过，才可用于合格背景。其他 debug 候选不能自动升级。三文件 hash 与不可变相对路径由原子 `current.json` manifest 指向，消费者一次解析指针后校验三件，拒绝越界路径/混版/坏hash。

在新增实际结果前补记背景底价范围：FMZ连续事实为空时，允许独立采集 Deribit BTC-PERPETUAL ticker 的 index_price 与原 timestamp，仅作为 MAP 背景价格轴；单列 `deribit.btc.index.map_context.v1`，300秒用途时效，与五秒保单报价产品分离。禁止写入或冒充 FMZ 原生事实、SpaceGate 或盘中路径；缺源时间、异常值、未来时间、过期均不展示底价。每轮末尾最多一次公开读取，与其余来源共享有界运行和provider预算，总上界25次HTTP；零LLM/交易。此项只补价格坐标，不改变金融值、模型或经济裁定。

市场与价系保持 Binance USD-M BTCUSDT / USDT / 原成交历史，原 source observation / known 与本机 first_seen 分开。没有经验证映射仍为名义背景，不计算 Deribit 的精确距离或 BE 共位。服务器本地消费者把合格原始结果接入统一 DataEngine 并建立 MAP 快照；GET、点区域、评审不下载或计算 KPF。
