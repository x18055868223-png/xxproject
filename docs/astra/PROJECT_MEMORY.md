## 3. 本轮工作判断与建议：尚未成为已接受交易规则

**工作判断**：当前最值得先查的是信号的具体用途与反馈目标是否明确。不能仅因迭代次数多，就预设全面调权可以解决问题。

**建议的短路径**：固定一个可追溯的信号版本和一类现有候选规则，先检验信号用于“接受/否决一笔候选”是否带来增量；这是最小用途试验，不预设过滤一定有效，不代表永久禁止研究选边或退出用途。

1. 先写一页用途约定：决策时点、候选如何产生、观察/持有窗口、前提失效条件、已有执行与风险边界。不把调整多个环节捆绑进同一次比较。
2. 先审一小批连续、同版本、真实记录，例如10个案例，仅定位数据、语义、时效和消费错误；不得挑最成功或最失败案例算胜率，展示样例不能当实盘证据。
3. 若记录足够，再做前向影子比较：同一时点、同一候选、相同事前风险口径与固定退出规则，仅改变是否接受；基础候选不能先被信号筛选。保留所有机会与否决，不把省下的风险预算重新加到获准交易上。
4. 比较整个机会集合的净结果、被避免的损失、被错过的利润、参与率与尾部/路径风险。没有同期报价则只能检查方向/路径，不能编造期权净收益；影子估算不是实际成交。
5. 用具体误差决定修改位置：数据错修输入，语义错修定义，期限错修用途窗口，方向描述对但交易差查结构/报价/成本，才到证据支持的权重调整。每次只改变一个主要假设，保留原基线。

十个或几十个案例只用于诊断/流程试行，不能认证稳定收益或尾部安全。已有连续观察跨版本或跨市场状态时不能直接合并校准。工程缺陷可单独修复，但须留版本分界；不在试验中静默换模型。

## 4. 信号先按用途解释，不再增加一个总评分

研究记录先分开四件事：输入是否可用；结构与方向有哪些支持/冲突；前提对哪个时间窗有效、何时失效；是否与具体价差的亏损路径有关。报价补偿和执行许可仍由相应职责独立判断。已有confidence保留作研究变量，不把它当仓位或胜率刻度，也不在本轮修改生产输出。

## 5. 什么证据才允许改变路线

- 改动前写明：原问题、触发变化的具体案例/新证据、被否定的假设、最小替代、预计改变哪个消费者，以及验收/停止条件。
- 只有新事实、可重复错误、前向对照或用户明确改变目标，才足以提出路线调整；单次盈亏、新术语、模型一致或文档变长均不足以独立支持调整。
- 若候选过滤没有显示增量，先检查数据与用途定义；证据足够时可以放弃该用途，保留信号作为观察工具或另立一个可检验用途，不自动扩大系统。
- 样本不足保持“未知”；框架好看、代码通过、历史观察较久，都不能替代明确目标下的验证。
- 每次结论变更同步[路线与规则](04_后续路线与接管规则.md)、[台账](02_版本与证据台账.md)和[进度](03_当前进度与差距.md)。记录新裁定为什么替代旧裁定；用户确认、工作判断和待验证建议始终分栏。
