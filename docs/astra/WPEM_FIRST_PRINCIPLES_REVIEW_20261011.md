# WPEM 现状审视与重构方向（对照第一性设计说明 v1.0）

日期：2026-10-11 · 分支 `claude/astra` · 依据：用户《xxproject WPEM 第一性设计说明 v1.0》、代码静态审查、EU 生产只读取证。

## 结论

**WPEM 目前没有完成它的核心使命。** 它在生产中提供的是“单一时点的截面 + 两点并列”，不是围绕同一风险对象的时间记忆：

- 五问中只有 ①“现在在哪里” 做得好；② 部分；③ 基本没有；④ 完全没有；⑤ 部分。
- 生产里 WPEM 历史存档 2026-10-08 起已写满停止（134,157,810 B / 128 MiB），当前没有任何锁定在采样；默认候选每天换到期、日内来回换腿，路径永远积累不起来。
- WPEM 名下约 1.1 万行代码中，纯“时间记忆”只占约 15–20%；大部分是 LLM 评审输入、目录、文本校验与离线风险模型。

## 对照五个目标

| 目标 | 现状 | 证据 |
|---|---|---|
| 1 同一对象连续性 | **身份做对了，取样做错了**。`candidate_id` 绑定双腿/到期/数量，锁定库拒绝跨合同追加。但窗口取“同侧最近 24 行”而非同一对象，导致锁定合同被默认候选挤出、误报“换腿”；每次代码发布都被当作方法断点重置窗口 | `astra_underwriting_v20.py:132`、`astra_wpem_workbench_v1.py:136`、`astra_wpem_shadow_v1.py:482`、`astra_candidate_asof_v1.py:290` |
| 2 Level / Delta / Path | Level 完整；Delta 只有窗口首尾差、6 个数；Path 只是参考价方向计数，不区分持续变化与一次跳变；窗口只有 15m/60m。生产中两侧均 `NO_STRICT_DELTA` / `NO_PATH_DUE_TO_WINDOW_GAP` | `shadow:230-323`、`native:249` |
| 3 证据演化 | **缺失**。锁定时保存了 t0 全量快照，但支持/反证的 ID 含快照哈希，t1 无法逐条对应；对照只把路由整体并列为一行“内容发生变化”。生产中的“支持/反证”是数据质量陈述，Put/Call 文本相同 | `evidence_routing:242`、`compare:388-406` |
| 4 区分变坏与未知 | 锁定对照的行状态做得好（missing / latest_missing / not_precise / changed）。但 `path_unavailable`、`reference_not_qualified` 被放进反证；信用下降被自动标为 COUNTER——正是说明书禁止的“数值下降=恶化” | `shadow:684-697`、`routing:924-951` |

## 根因

1. **存储单位错了**：每个样本存 0.8–2 MB 的完整评审包，而时间记忆只需要每点 1–2 KB 的数值行。128 MiB 只够约 70 个点。
2. **对象与取样混层**：Space（当前截面，随最优候选轮换）与 WPEM（固定对象的运动）共用一条按“侧”取样的流水线。
3. **WPEM 被做成了 LLM 评审的输入工厂**：claim catalog、选择校验、提示词版本、产品评审文本，这些替最终判断做准备，而不是记忆。
4. **没有稳定的论点身份**，所以“当初的理由现在怎样了”在结构上无法回答。

## 重构方向

原则：WPEM 只做时间记忆，输出确定性的五问投影；评审、Q1/Q2、LLM 消费它，不属于它。

### P0 止血（小改动，不改设计）

- 窗口先按 `candidate_id` 过滤再取行；锁定合同不再误报换腿。
- 可比性哈希改用语义方法版本，不含源码文件哈希。
- `path_unavailable`、`reference_not_qualified` 从反证移到未知；取消“信用下降=COUNTER”的自动映射。
- 统一距离符号约定。
- 查清锁定采样 `locked_packet_unavailable` 的原因，使实际节奏接近 60 秒。
- 存档满时在页面明确显示“记忆已停止”，而不是静默。

### P1 WPEM Core（新的最小核心）

1. **对象**：锁定合同是正式对象；另外对“出现过的每个候选”以低频（如 5 分钟）记紧凑行，使日后锁定时能回看锁定前的历史。默认候选的轮换只属于 Space。
2. **紧凑时间序列**：每对象每点一行：时间、各源时钟、责任距离（短/长腿）、可见信用与平仓借记、费用、剩余期限、锚点评分、净伽马与体制、SpaceGate、流向状态、质量标志。按对象追加，按保留期裁剪；锁定期以 60 秒为目标。
3. **Delta 与 Path**：对每个数值项在 15m / 1h / 3h / 自 t0 四个尺度计算：首尾差、点数、最大缺口、形态（持续单向 / 单次跳变（最大一步占比）/ 反复 / 平稳）。点数或缺口不足时为 Unknown，不补值。
4. **论点账本**：锁定时把支持、反证、未知各自落成带稳定 ID 的条目（语义键 + 可判定规则，例如“短腿距离 ≥ X%”“无持续卖压”“风险参考缺失”）。t1 由程序逐条判定：成立 / 减弱 / 失效 / 无法核验；并列出新出现的反证、已消除和新增的未知。LLM 只负责表述，不做判定。
5. **五问投影**：一个小而确定的输出（现在在哪里 / 相比 t0 什么变了 / 偶发还是持续 / 论点怎样了 / 还不知道什么），同时供页面与评审使用。

### 不在 WPEM 内

- `astra_wpem_reference_v1`（风险模型资产）与 `astra_wpem_results_v1`（交割复原）在 `tools/` 内无引用，应移出 WPEM 名下或归档。
- 产品评审目录、提示词与文本校验归入评审层（消费 WPEM Core）。

## 与“两问证据”设计的关系

Q1（风险）与 Q2（补偿）的时间维度应直接引用 WPEM Core 的五问投影与论点账本，而不是各自从快照重建。建议顺序：P0 → P1（对象、紧凑序列、Delta/Path）→ 论点账本 → 再设计两问证据。

## P0 完成情况（2026-10-11，commit `43d7dfb`，已部署 EU）

- 窗口按 `candidate_id` 取行，锁定合同不再被挤出或误报换腿。
- 可比性改用语义版本 `candidate_replay@1` + 快照 schema，代码发布不再重置窗口。
- “风险参考不合格”“路径不可得”移入缺口；删除与 μ 缺口重复的“预计赔付未知”反证；验证器不再强制至少一条反证。
- 信用/余量变化一律为 Q2 REASSESS，不再自动判为反证或支持。
- 读者可见的距离统一为“距责任边界，正值=仍在责任区外”。
- `data_health.wpem_archive` 显示存档用量与停止原因；锁定采样缺口记录异常类型。
- 副作用：工作台刷新周期由约 150s 降到约 50s。
- 未做（属 P1）：旧存档已满，路径仍无法积累；需紧凑时间序列存储。
