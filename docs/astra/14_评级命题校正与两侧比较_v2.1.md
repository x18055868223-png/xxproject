## 1. 交易员会看到什么变化

保留 D、C、B、A、S，不增加正负子等级。两侧都是 B 可以成立，但必须能看清哪一侧更有依据，以及差异由什么事实决定。相对有利不等于达到 A，也不自动允许人工准备。

Put 信用价差评审的固定问题是：**下行侵入风险是否受到可解释的约束**。Call 侧对应上行。价格偏多或偏空单独表达，不能把“看跌证据较强”写成“Put 适配证据较强”。上涨可以减弱 Put 的下行风险，却不能仅因此被写成 Put 适配失效。

阅读顺序及中性纸面保持不变。列表及最高辅助决策区补齐卡片时点价格、单位、独立价格倾向和已采纳的两侧比较；量价和主动流仍是依据。增强条件、削弱条件分别展示，等级依据允许解释 D/C 为什么支持不足。

## 2. 从事实到判断的接口

推理顺序继续为：结构与位置 → 本侧不利压力 → 压力对应的价格表现 → 竞争解释。墙距说明位置，不证明承接；墙、翻转点与 Pin 不因接近就成为等价约束；Gamma 过渡区不因净 Gamma 为正就已确认抑制波动。净变化和 OHLC 不证明全程路径，传导较弱只能提示可能承接。

| 字段或对象 | 责任 |
| --- | --- |
| fit_thesis | 本地固定 Put 下行约束、Call 上行约束，模型不能改评审对象 |
| mechanism_cn、basis_cn | 适配机制及成立程度；总体等级依据 |
| evidence_roles | 为实际引用标注支持适配、反对适配、仅作背景，并说明具体作用 |
| strengthen_if_cn、weaken_if_cn | 分别说明什么观察增强或削弱适配解释 |
| side_comparison | 同次评审返回 Put 相对有利、Call 相对有利、接近或不可比较，以及理由、引用和反转条件 |
| price_bias | 独立价格倾向；不从等级或相对侧别反推 |

新模型回复不重复填写支持、反对引用数组；本地从证据角色派生旧页面所需引用。同一事实可以有不同作用，但不能算成多份独立确认。非投票 Funding 保留背景，不凭温和正负值建立独立方向票。

本地只检查明确可判定的关系：本侧不利推进不能直接当正面支持；缓冲机制可由结构或响应支持，但不利压力仍是反证。引用必须存在、可用且不晚于卡片时点。不能用中文关键词黑名单声称已经验证全部自然语言因果关系。

单侧无效则该侧未评级，保留另一侧、原回复及错误。比较缺理由、引用无效、与等级次序矛盾，或任一侧无效时，仅关闭相对比较并显示原因。无效不伪装成 C，不因语义错误追加请求。

## 4. 调用与迁移边界

正常每卡仍一次 DeepSeek 综合评审，不增加数据源、调用或模型配置改动。传输与格式恢复共用最多两次 HTTP；低等级、语义问题、比较未采纳不是重试条件。

升级枚举所有已支持 Prompt 的持久尝试状态。已完成结果继续复用；旧未完成状态冻结，不因升级产生新额度；多个版本状态并存时停止自动请求并提示核查。冻结包、响应、预算、锁及历史自动排除清单一起迁移。

正式升级前先停止旧 timer，等待正在运行的 oneshot 结束，再备份和替换。正常 runner 沿用同一文件锁，禁止部署交界时绕过 runner 并发运行旧、新 Python 入口。不得强杀请求后删除 reservation 重获额度。升级后恢复原有服务器定时配置；不恢复已取消的 Codex 跟进任务。

回退成套恢复代码和对应阅读投影，保留新版数据、尝试和预算，不删除新结果，也不让旧代码批量重评历史卡。
