# 决策约简层设计（最小闭环 v1）

日期：2026-10-13　状态：v1 已实现（见第 11 节），页面待确认　适用：承保台 v3，每侧候选（Put / Call）

## 1. 目标与一句话定义

在 Q1（风险质量）与 Q2（风险价格）之后加一层"约简"，不是"综合"：

- 系统把**无论用户怎样加权都不改变决策**的信息消化掉（规则已定、重复、项目规则下不投票、只是对证据效力的通用限定）；
- 剩下的、必须依赖用户信念或偏好才能回答的，写成最多 3 个固定格式的**剩余问题**，每题附程序算出的分界。

用户读完约简块后，脑中需要处理的是"规则状态 + 至多 3 个问题"，Q1/Q2 退为可展开的依据。

判据：约简层**删除任何一条信息都必须有可校验的理由码**；给不出理由码的，一律留给用户。错误方向不对称：误删的代价远大于多留一条。

## 2. 设计原则

1. **不引入新权重。** 只做四类操作：规则收束、归并到封闭变量、按项目既有规则折叠、把剩余转成问题。不排序重要性，不净额化相反证据，不打分。
2. **不给结论。** 不出现"值得/不值得、建议、做/不做、偏多/偏空总体"。页面不下单这一常量也不再重复。
3. **轻量，不加新鲜度门。** 约简层原样消费当前快照。某个数字缺失或过期，只在该数字处写"暂缺"或标注其时点，不让整块消失；不影响推理与决策质量的过期一律只标注、不拦截。约简层自身不新增任何时效规则。
4. **第一版零 LLM。** 现有复核已经是"程序生成主张目录、LLM 按编号挑选"，约简所需的映射全部可以由静态表完成，不需要判断。零 LLM 意味着零权重风险、零预算、可确定性测试。
5. **只读、可加性。** 新增读视图字段，不改任何金额、门、Q1/Q2 生成和复核链路；删掉该字段即回滚。

## 4. 可以安全消化的信息（无需新权重）

每一行的"依据"都是已有字段或项目已定规则，不是约简层新加的判断。

| # | 信息 | 消化方式 | 理由码 | 依据 |
|---|---|---|---|---|
| 1 | 空间门、结构门状态 | 收为一行"规则状态" | `rule_gate` | 项目硬门；门关时结论由规则决定，不进入权衡 |
| 2 | 数据缺口原因码（报价、费用、时间差、可复核性） | 不单列；只在受影响的数字处写"暂缺" | `shown_at_number` | 原则 3：不影响推理的不拦截、不占注意力 |
| 3 | 合同责任方向说明 | 并入剩余问题 R1 的分界（短腿/保护腿位置） | `in_boundary` | 合同事实，不是待权衡项 |
| 4 | 慢背景：`information_increment = CONTEXT_ONLY`（TMV、资金费、偏度、ETF、链上、外部资本） | 折叠为"背景 N 项，不投票"，可展开 | `non_voting_context` | 项目规则：背景不投票；TMV/CVD/EDB 无校准概率含义 |
| 5 | 同源重复：`CONFIRMING_SAME_BLOCK`、`REDUNDANT` | 折叠 | `same_block_repeat` | 生产端已标为同块确认或重复、非独立证据 |
| 6 | 无结论：`INCONCLUSIVE`（如宏观）、`MISSING` | 折叠 | `no_direction` | 无方向，任何加权下都不移动 R1 |
| 6b | 只用于来源资格：`QUALIFICATION_ONLY` | 折叠 | `qualification_only` | 不提供方向 |
| 7（v2） | 证据效力的通用限定：`*.not_realtime_confirmation`、`*_not_quantified`、`counter.q1.competing_context_explanation`、`counter.map.qualitative_only` | 合并为一条通用限定句，不逐条重复 | `evidence_caveat` | 它们说明证据效力的边界，不是独立风险 |
| 8 | 路径不足：`INSUFFICIENT_WINDOW`、路径 `gap` | 折叠为一行"路径证据不足，不参与本轮" | `no_path_signal` | 不提供方向，不移动任何分界 |
| 9 | 执行未授权 `counter.execution.permission_closed` | 不展示 | `constant` | 页面从不下单，是常量 |
| 10 | 补偿与风险参照缺口（`compensation_gap`、`risk_reference_gap`、μ/M 为空） | 转为 R2 的前提句 | `in_question_premise` | 正是 R2 必须留给用户的原因 |
| 11 | Call 侧深尾：BTC 计赔付在保护腿以上随价格上升而减少 | 并入 R2 的最大亏损数字，不单独成题 | `bounded_tail` | 合同数学：Call 价差的 BTC 赔付有界且递减 |

不消化、**原样保留为证据指针**的只有一类：带方向的增量证据（`information_increment = NOVEL` 或 `COUNTER_EVIDENCE`、流向 `adverse/favorable`、锚点翻转位、EDB 倾向）。它们挂在 R1 下，只标方向（靠近/远离短腿），**方向相反的并列显示、不合并**。

第一版**不做**"程序扰动后不敏感"这类折叠：它需要新计算，留给后续。

## 5. 消化后剩余的问题（系统无权替用户回答）

固定顺序：落点 → 补偿 → 深尾。不按重要性排序。

### R1【信念】到期时价格会不会进入短腿责任区？
- **分界（来自市场与合同）：** 短腿、保护腿相对现价的距离；与到期前隐含预期波动之比（与页面地图同源）；短腿 \|Δ\| 作为市场原始事实并列。
- **证据指针：** 第 4 节保留的方向证据，逐条只写"靠近短腿 / 远离短腿"及其 Q1 位置；相反方向并列，注明"未合并"。
- **系统无权回答的原因：** 方向证据无校准概率，项目非目标明确"不给概率"；系统不能把"已观察到的"写成"全部重要因素"。

### R2【判断】这份补偿够不够？
- **数字：** 扣费后净信用（BTC / USD）、保护腿处亏损（Put；BTC 口径下更深处继续增加，见 R3）或最大亏损（Call）、信用占宽度比例；任一缺失写"暂缺"并注明缺什么。
- **前提句：** "系统没有独立的风险参照（μ_ref 无生产者），这里的唯一参照是市场价格本身。"
- **系统无权回答的原因：** 没有 μ_ref 就没有 M_ref，系统无法在自己的口径内判断补偿是否充分。
- **后续收缩：** 一旦 μ_ref 有合格生产者，M_ref 的正负成为程序事实，R2 退回第 1 行"规则状态"，剩余问题减为 2 个。

### R3【偏好】是否接受保护腿以下按 BTC 计赔付继续增加？（仅 Put）
- **数字：** 赔付表中保护腿处与深尾处的 BTC 赔付（例：81,500 → 0.0245 BTC；40,750 → 0.0491 BTC）。
- **系统无权回答的原因：** 这是承受度偏好，不是事实问题。

### 模型外（固定清单，不计入问题数）
人工维护、静态文本，不由程序或 LLM 生成：到期前已知事件（宏观、监管、交易所公告）、交易所与结算风险、你自己的整体仓位与承受度。只写"请自行核对"，不写"已覆盖"。

## 7. 最小闭环实现范围（待授权后实施）

| 部分 | 内容 | 规模 |
|---|---|---|
| 后端 | 新模块 `tools/astra_decision_reduction_v1.py`：纯函数 `reduce(candidate)`，只读现有字段（预期波动倍数由页面用地图同源数值计算） + 第 4 节静态映射表；在读视图组装时挂到每侧候选。不采集、不调 LLM、不写状态。 | 约 150 行 |
| 前端 | `deploy/astra_workbench_v3/` 每侧卡片顶部渲染一个约简块，复用现有样式与 `glossary.js`。 | 约 80 行 |
| 测试 | 见第 8 节，固定夹具。 | 约 8 个用例 |

**不改：** Q1/Q2 生成、LLM 复核与回执、硬门、新鲜度规则、任何金额、锁定与采样。

**唯一可调的旋钮：** 第 4 节的静态映射表。使用中发现误折叠，就改表并补一个回归用例；不加新逻辑。

## 8. 验收

自动化（确定性）：
1. **覆盖不变量：** Q1/Q2 的每个输入条目恰好落在一处：规则状态、某个折叠理由码，或某个剩余问题的引用。不允许凭空消失。
2. 剩余问题不超过 3 个，顺序固定；Call 侧不出现 R3。
3. 输出中的数字都带字段引用，没有约简层自造的数字。
4. 文案不含结论词（值得、不值得、建议、做、不做、总体偏多、总体偏空）。
5. 方向相反的证据同时出现时，`conflict = true` 且两条都保留。
6. 报价或费用缺失时，R2 显示"暂缺"，整块仍渲染。
7. 门关闭时，`rule_state.status = blocked`，问题仍显示并标"仅供观察"。
8. 打乱输入条目顺序，输出不变。

人工（试用一周）：
- 每次决策后记一行：是否需要展开 Q1/Q2 才能做决定；是否有被折叠的条目事后看会改变决定。
- 后者即"误折叠"，是本层最重要的质量指标；出现即改映射表。
- 页面改动仍按发布门，需"当前本地页面可推送"。

## 9. 明确不做（v1）

- 不调用 LLM，不让 LLM 生成剩余问题、权重、排序或"其他风险"清单。
- 不做敏感度折叠，不算概率，不给分数。
- 不新增任何新鲜度或时效门。
- 不替代 Q1/Q2，不改复核链路。

## 10. 后续可选（只在 v1 证明有用后）

1. μ_ref 有合格生产者后，R2 自动退为规则状态。
2. 程序扰动下的"不敏感"折叠（需新计算，单独评估）。
3. 允许 LLM 只对 R1 的证据指针做措辞润色，且只能引用复核回执里已选中的目录编号。

## 附：关联观察（不在本设计范围）

现有报价规则 `MAX_BOOK_SKEW_MS = 2000`（`tools/astra_underwriting_v20.py`）把两腿订单簿时间差超过 2 秒的报价判为不可用，信用与净额随之为空。实测同一侧几分钟内在 0.33–2.08 秒之间波动；原因是冷门期权订单簿的时间戳是"最后一次变动"的时间，并非请求时间。按"不影响推理即可放行"的原则，可另起一轮评估：两腿各自都在 5 秒新鲜度内时，时间差只作标注而不清空数字。
