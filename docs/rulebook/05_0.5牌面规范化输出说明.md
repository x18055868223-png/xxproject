# 0.5 牌面规范化输出说明

版本：0.5配套说明 · 2026-11-14。沿用 structural_player_view@0.1，不增加Schema字段。

补齐前没有完整配套：已有双侧Player View与Schema，但缺TMV运动句；单独发送旧JSON不能视为满足0.5。现在提供可直接发送的完整文本示例及兼容现有Schema的JSON示例；自动生成器尚未接入TMV。

## 一次发送什么

发送「0.5规则正文 + 本局上下文 + 5–7条现象」。上下文写明模拟/实盘、截止、未下注/持仓、市场与标的、到期与数量，并附现有合同核算的双侧补偿和摩擦口径。不要把历史评估或预选答案混入输入。机器接入可用完整Player View JSON替代现象列表，无需两份重复发送。

## 字段与规则对应

|沿用字段或上下文|内容|0.5对应条款|
|---|---|---|
|cutoff_ms；sides.*.boundary|同一截止；双侧短腿、保护腿、到期、数量、币种及责任区间|定位责任|
|position.measurements；description|现价、责任区位置、距离；句内追加TMV24h/48h相对短腿运动|读当前运动|
|structures.measurements.groups；description|库存范围与口径；区分现价至短腿上的位置及更远位置，将测试事实绑定具体位置|定位责任、看位置是否被测试|
|flow（可省略）|成交所在空间与窗口；期权流不充当标的动量|辅助确认|
|critical_gaps；coverage；sides.*.status|仅关键阻塞；assessable表示可判断，不表示acceptable|何时接受|
|随局合同核算上下文|两侧权利金、费用/滑点预算、资格和成交前提，同数量同币种同截止|补偿覆盖摩擦|
|持仓时附冻结入场记录|原条件、有效破坏标准、基准时间；对照同责任新牌面|连续跟踪|

## 最小生成读法

1. 仍用现有build(put, call)生成双侧Player View。库存与测试位置细节从原始board读取，聚合到现有structures.description；不能用组内总穿越数代替入区前位置反馈，组OI合计不能冒充入区前库存。
2. 从同标的、匹配截止的TMV24h/48h价格分量分别取运动含义，追加到各侧position.description。在责任外侧，价格上行对应Put远离、Call靠近；下行相反。横盘只接受来源明确的价格横盘状态，缺失与窗间分歧不可填横盘；不得自行设阈值或用综合分替代。
3. 已入责任时保留index_zone，说明向短腿返回还是深入责任；越过保护腿后的几何远离不能写成安全远离。两窗相反则分别保留。缺失只说明其实际阻塞，不自动Reject。
4. 合并后仍为5–7条，不新增动量票数或结论。新增TMV来源留在底层关联记录，原board引用不可冒充TMV来源。

配套文件：examples/player_input_v05/hand_001.player_view.json（完整JSON）、hand_001.ai_input.md（完整规则与短牌面，一次发送）、README.md（模拟来源）。示例中的价格运动与经济数据为明确补入的模拟条件，未验证实盘生成链路。
