## 3. 牌面由什么组成

`build(put, call)` 接收两份现有 `structural_board@0.1`，输出 `structural_player_view@0.1`：

- 共同责任与时间范围：1 条。
- Put 与 Call 各自的指数/责任位置：各 1 条。
- Put 与 Call 各自的空间—OI—已观测路径聚合：各 1 条。
- 若有合格成交配对，分别增加辅助成交：各最多 1 条。

正常共 5–7 条，Schema 限制最多 8 条。候选或主事实缺失时可以更短，不用 Unknown 句子补足数量。

每条现象关联相应侧别、boundary_id 和原始 observation 引用；原始 board 的哈希保留在侧别元数据中。提取层不输出 decision、selected_side 或 at_least_one_acceptable。

### 3.1 空间与义务的聚合

按“边界附近 / 短腿责任外侧 / 短腿责任内侧”互斥分组。附近半径为腿宽的 10%，只定义展示分组，**不参与接受/拒绝条件**。

每组保留结构位数量、价格范围、距短腿最近距离、指数到短腿之间的结构位数量、越过保护腿的数量，以及 OI 集中位/派生结构位数量。由此区分真正位于入区路径上的结构和位于指数背后的结构。

Call/Put OI 分开汇总已读数量，并保留各自覆盖了多少结构位；缺失不补零。路径按可读结构位数量与其中出现过穿越的位置数量表达，不能当作穿越概率。来自同价位多个角色的观察只计一次，不跨 Put/Call 两张责任牌面重复累加。

### 3.2 成交的聚合

按同样的空间分组，汇总普通 Call/Put 主动买量、卖量与净主动买量；强度直接使用 BTC 原始数量与总成交量，不转换成高低评分。

净主动卖出只描述相应期权类别，不推导标的下跌或上涨。只有原有同行权价路径配对、且窗口均为本次冻结截止之前 24 小时的成交才纳入。成交始终是辅助，不能单独作为评估证据。

市场级净 GEX、跨期解读、历史结果、源端自由文本及旧评分不进入这个短视图；底层原始证据并未被删除。

## 4. Unknown 如何降低

从短牌面中移除默认展开的 dealer_gamma、stability、movement、causal confirmation 等一般不可识别项，也不因 OI 或辅助成交缺失就阻塞空间判断。原始证据层保留这些限制，不能将未显示误读为已知。

仅有三类关键缺口进入 `critical_gaps`：候选缺失、指数位置缺失、合格空间几何缺失。每项明确：

| 字段 | 含义 |
|---|---|
| side | 影响 Put 还是 Call |
| blocks_this_side | 是否阻止该侧形成空间判断；当前列出的关键缺口均为 true |
| blocks_all_sides | 合并全部缺口后是否已无任何可评估侧；另一侧仍清晰时为 false |

`coverage.at_least_one_side_assessable` 表达数据是否足够评估至少一侧，**不等于判断该侧可接受**。后者只存在于独立评估。

输入身份、截止、到期或指数互相冲突时，接口拒绝拼接，不生成假 Reject。不同截止的旧牌面不能仅改元数据硬凑成同一局，必须从同一观察批次冻结构建。

## 5. 积极决策如何落入协议

每侧评估状态为：acceptable、unfavorable、unassessable、no_qualified_vertical。

| Put/Call 的判断组合 | 整体输出 | at_least_one_acceptable |
|---|---|---|
| 任意一侧 acceptable，另一侧任意合法状态 | Accept，必须选择可接受侧 | true |
| 两侧均 unfavorable | Reject | false |
| 两侧均有资格失败证据，或一侧资格失败、另一侧明确不利 | Reject | false |
| 没有已可接受侧，且仍有关键缺口使某侧 unassessable | Unknown | null |

正常空间可评估的侧不能仅因一般性未知填写 unassessable，必须积极给出 acceptable/unfavorable 及该侧空间证据。接受条件由牌手陈述，程序没有新增“某个距离或 OI 数值达到阈值就 Accept”的规则。

整体 Accept 与选边是交易意图的评估结果，本原型不自动下单。`scope=structure_only` 与 `execution_authorized=false` 保持当前执行链路边界，不改变用户要求的积极决策倾向。

### 5.1 校验实际做了什么

`validate_assessment(assessment, view)` 校验：

- 评估绑定本次完整 view 的哈希；
- 必须同时说明两侧状态；
- 引用确属该侧，且不能只引用成交；
- 至少一侧 acceptable 时，不能输出 Unknown/Reject；
- selected_side 必须选 acceptable 侧；
- 缺数据不能被伪装成明确不利或市场不存在合格合同；
- 整体三态与 at_least_one_acceptable 一致；
- 不允许额外评分/动作字段或执行授权为 true。

校验检查协议与引用，不证明 AI 的自然语言推理一定正确，也不证明其空间判断有收益优势。真实模型语义审查与实际牌局归因仍是后续工作。

### 5.2 无合格价差与资料缺失的区别

`unavailable` 是可选的同侧资格失败证据输入，需要 reason、side、venue、underlying、expiry_ms、asof_ms、evidence_ref 和 source_sha256。两侧/已有候选的市场、标的、到期必须一致，证据时钟不得晚于 cutoff 且不超过 5 分钟。

允许的来源原因：无匹配 instrument、无共同到期、无合法垂直构型、无正信用。这里提供的是资格失败消费接口，尚未新增生产扫描器；来源应由已有合同资格检查生成。来源引用与哈希不等于已经在本原型中独立验证了市场搜索完整性。

未提供候选也未提供资格失败证据时，只能记为 candidate_missing，不能升级为 no_qualified_vertical。

## 6. 两个可复现示例

所有示例为合成近真实量级数据，调用现有 level card producer 与原 structural_board 提取器构造。它们不是实际模型调用或真实成交记录。

### 6.1 至少一侧可接受：Accept

Put 短腿76000、保护腿74000；Call 短腿84000、保护腿86000；同一指数80600、同一到期与截止。两侧均有可读空间结构，示例独立评估认为两侧都可接受，并选择 Put。

- 原始双侧共 84 条观察，压成 7 条核心现象。
- 短牌面关键缺口为 0；原始做市商/因果等未知项不进入主体。
- 即使剔除 OI、路径和成交，只保留原有位置与结构，测试仍允许形成 5 条牌面并接受；它们不是强制等待条件。
- 结论只在 `accept_assessment.json` 中，未写入 `accept_view.json`。

### 6.2 两侧均有具体反证：Reject

Put 短腿81000、保护腿79000；Call 短腿80000、保护腿82000；同一指数80600。两侧短腿都已进入责任区间，并有相应已观测路径穿越。

本示范独立评估采用“新承保时尚未进入责任区间”这一具体条件，两侧都不符合，因此 Reject。**这一示范条件没有写成全局提取门控，也没有规定所有实值价差必然 Reject。**

- 原始双侧共 56 条观察，压成 5 条核心现象。
- 两侧结构与位置可读，Reject 来自双侧具体判断，而不是 Unknown 太多。
- 没有合格成交时省略辅助成交，不补假成交，不因此 Unknown。
- 原始输入、短牌面、示例评估分别存放。

## 7. 使用方式

在实现工作树运行：

```powershell
uv run --no-project --python 3.12 python tools/astra_structural_player_view_v1.py --put put_board.json --call call_board.json --out player_view.json
```

输入是两份原生 board；`--out` 不得已存在。仅有一侧时只传对应参数；双方都缺时须传 `--cutoff-ms`。资格失败输入通过 `--unavailable qualification.json` 提供，不能自行用缺少文件模拟资格失败。

函数接口：

```python
from tools.astra_structural_player_view_v1 import build, validate_assessment
view = build(put_board, call_board)
# assessment 应由独立牌手读取规则书与 view 后产生；build 不产生评估。
validate_assessment(assessment, view)
```

## 9. 后续迭代原则

目标是积极但有边界的参与，再用大量真实牌局分别归因空间读取、义务解释、条件选择、执行成本和结果偏差。默认不交易不能被当作避免犯错的优化目标。

正式接入时应冻结 board、view、规则/模型版本与独立评估；实际订单/成交与事后结果另行记录。结果不能写回当时现象，参考候选不能冒充真实持仓盈亏。

优先检查实际模型是否仍以普遍 Unknown 弃权、是否给出双侧明确依据、是否把成交或结构数量变相当因子。协议校验和回放测试不能替代这一真实牌局归因步骤。
