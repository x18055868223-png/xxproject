# 现象提取与降维说明

> 2026-11-14 收束更新：本文描述的是保留不变的原始 structural_board 证据层。主要 AI 输入现在使用双侧 Player View；其中的通用 Unknown 不再逐项展开，决策倾向以规则书 0.2 与《02_牌手视图与积极决策收束说明》为准。旧单侧评估协议只作历史兼容。

版本 0.1 · 2026-11-13。依据当前 `claude/astra` 工作树代码；实现入口 `tools/astra_structural_board_v1.py:build`。本文区分已接入与暂不纳入，不能把设计映射当作运行事实。

## 1. 现有链路与新增位置

`astra_underwriting_v20` 的合同事实 → `astra_case_file_v1.build` 的 `case_file@0.1` → 新增提取层。

`astra_expiry_structure_v1` 的同到期 OI/成交、归档指数路径 → `astra_level_behaviour_v1.build_card` 的 `level_card@0.1` → 新增提取层。

两者按同一 case、两腿、到期、侧别和冻结截止绑定，输出 `structural_board@0.1`。提取层复用 `levels_for` 选择结构角色；不重算墙、Gamma、OI、成交或合同赔付。新增计算仅为相对两腿的价格距离与内容哈希。

## 2. 实际纳入的字段

| 来源与原字段 | 新牌面 | 降维及解释边界 |
|---|---|---|
| `L1.contract`: side、underlying、settlement_currency、两腿 instrument/strike、quantity_btc、expiry_ms | `boundary`、`boundary_id`、责任区间 | 明确 BTC 标的和结算；Put 保护腿低于短腿，Call 相反；不能拿其他候选拼接 |
| `L1.liability`: starts_at_usd、protection_at_usd、usd_intrinsic_cap、btc_contract_cap | `contract_terms` | 前两项必须与合同边界一致；复用上界，不计算新收益、评分或安全余量 |
| `L3.expiry_walls`: expiry_ms、top.oi_put/oi_call/gamma_put/gamma_call[].strike、walls.pin | `space`、roles、相对两腿距离 | 只取本合同到期，角色来自已有 `levels_for`；OI/Gamma 排序是源端规模排序，不是因子评分 |
| `L3.gex.structure`: flip_point、total_net_gex | `market_structure` | 只保留数值与市场口径；Flip 有两腿距离，净 GEX 无局部价位；两者都不声称本期局部净义务已识别 |
| `level_card.index_usd` | `position` | 冻结读取的指数；相对两腿位置。不把 forward、mark 或宏观价格混作指数 |
| `level_card.levels[].oi`: c、p | `obligation_inventory` | 同行权价 Call/Put OI，原生 BTC 数量；不能识别多空主体/做市商 Gamma；缺失仍 null |
| `oi_change.24h`: c、p、gap | `inventory_change` | 完整可用端点才保留差值；不把 OI 变化叫作墙位迁移、稳定性或交易方向 |
| `before_24h`: crossings、closest_usd | `path` | 只保留观测路径穿越与最近距离；不推断吸附/加速/释放 |
| `flow.24h`: c_buy、c_sell、p_buy、p_sell、gap、truncated | `flow_at_structure` | 只保留普通期权主动成交 BTC 数量；同到期、同行权价、同窗配对路径；缺口、截断、无路径时不输出 |

`flow_sum` 已把普通、block、combo 分开；本版只用普通主动成交。期权 Put/Call 买卖不等于标的买卖，不能直接映射成现货攻击流。

合同核算的 USD 内在值上界不等于 BTC 净损失上界。现有逆向 Put 源端 `btc_contract_cap=null` 表示没有有限的 BTC 合同赔付上界；不能用腿宽/当前价格补成固定上界。Call 有限上界沿用源值。本版不宣称费用/实际成交/账户风险完整。

每条描述都从模板生成，明确短腿、保护腿。`source_ref` 定位源字段，`source_sha256` 定位冻结条目或卡；provenance 哈希可连接输入归档。全市场 GEX 与局部义务关系未知时，描述必须保留该限定，不能独立成为条件结论。

## 4. 缺口、时钟与义务状态

合同、责任核算和本期墙条目要求原 `quality=ok`、源条目时钟不晚于 cutoff，条目年龄最多 5 分钟；市场 GEX 最多 60 分钟。这是本原型明示的数据资格限制，不是盈利阈值，不改现行生产模块的时间策略。

合同不合格直接抛出 `ValueError`；可选条目过期/未来/异期则退出观察并记录缺口。level card 必须为 `level_card@0.1`、`level_rules@0.1`，绑定条件任一不符都拒绝拼接。

原生 `build_card` 已拒绝未来点、未来 OI 快照和未来 flow 窗；它的输出没有保留每个底层点的源时钟。因此本版不伪造时钟，相关 `observed_at_ms=null`，记录 `level_source_clocks_not_exported`。应把原冻结输入与源归档一起保存；卡片哈希是可追溯标识，不是对数据真实性的签名验证。

原生 OI 两端容许各自在窗口端点之前 40 分钟以内的快照；本版保留既有差值，不称精确同秒变化。路径覆盖资格沿用原生端点检查，不能证明内部一分钟不漏。故本版不使用驻留分钟数，不输出“稳定”结论。flow 完整性沿用 `flow_sum` 的端点/连续窗口/截断检查。

`obligation_state.inventory_coverage` 仅相对于本次纳入的腿位和本期结构位；全部 c/p 都可读为 observed，部分为 partial，无完整项为 unknown。它不表示全市场覆盖。dealer_gamma、stability、movement、path_feedback 始终明确 unknown，未来有合格数据适配后才能扩展版本。

## 5. 协议与可复现性

- `structural_board_0.1.schema.json`：封闭观察协议；8 类观察各有独立数值白名单与来源枚举，背景当前只能为空。
- `structural_assessment_0.1.schema.json`：独立三态评估协议；Unknown 需要缺口，Accept/Reject 需要证据引用与结构条件；执行授权固定 false。
- 原型只提取观察，不自动生成评估。JSON Schema 无法证明中文没有预测含义，也不能校验跨对象证据引用/哈希是否真实；这些是未来 AI 接入器必须校验的义务。
- 两个近真实量级、明确合成的样例输入/牌面见 `examples/`；不是生产快照。输入真实调用现有 `build_card` 构建，测试逐字节语义重放输出并验证 Schema。
- 脚本不访问网络、不读凭证、不调用模型、不写交易状态；CLI 采用独占创建，不覆盖已冻结的输出。

最低验收包括：Put/Call 均锚定正确、合同输入错误、跨 case/腿/到期/截止拒绝、过期/未来墙排除、辅助成交需完整同窗路径、缺失保持 Unknown、结果/自由文本不泄漏、Schema 禁止额外评分及执行授权，以及样例重放。
