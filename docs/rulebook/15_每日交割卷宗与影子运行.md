# 每日交割卷宗与影子运行

在 `xxproject` 工作树根目录运行。正式计划 `daily-deribit-btc-r2@1` 从 **2026-11-16 14:00 UTC** 生效。每日固定一局，目标同一交易所原生次日 08:00 UTC 到期，由现有引擎的 r2 双侧候选和 Deribit 原生四腿核实。计划和首次启动观察单独计数。[冻结计划](examples/player_dossier/schedule.json)

```powershell
$store = '.artifacts/player-dossier/forward'
$cli = 'tools/astra_player_dossier_v1.py'
$plan = 'docs/rulebook/examples/player_dossier/schedule.json'
python $cli --root $store tick --plan $plan --archive LOCAL_COPY_OF_NATIVE_RESEARCH_ARCHIVE --settle-due
```

`--archive` 指本地只读证据副本，保留现有 `cases/`、`levels/`、`structure/` 布局。正式局等待既有归档的 r2 双侧位置卡。计划发牌窗口为 14:00 起 20 分钟，回复窗口为冻结后 20 分钟，且不得跨到期。窗口内可按同一个身份重试数据缺口。跨过窗口只记缺失。人工交接时，把 `evidence/input.md` **整份原文**交给模型。记录真实请求与完成时间，存整份回复，最后导入。

```powershell
python $cli --root $store response --expiry-ms EXPIRY_MS --hand HAND_ID --attempt REQUEST_ID --raw answer.md --annotation excerpts.json --model MODEL_ID --requested-ms REQUEST_MS --decided-ms DECISION_MS
python $cli --root $store freeze --expiry-ms EXPIRY_MS --hand HAND_ID --condition condition.json --entry-path entry_path.json
python $cli --root $store check --expiry-ms EXPIRY_MS --episode EPISODE_ID --path path.json --check-ms CHECK_MS --available-ms AVAILABLE_MS
python $cli --root $store settle --expiry-ms EXPIRY_MS
```

`excerpts.json` 五个键 `put`、`call`、`put_counter`、`call_counter`、`comparison` 指向答复中的原样文本。另可标 `depends_on_ard`。回复采用明确的 `Accept / Put`、`Accept / Call`、`Reject` 或 `Unknown` 小标题。此要求仅让导入器定位结论，原模型可见规则全文由现有生成器提供。格式错误的原文照存。`reparse` 追加勘误并指向同一原文，正式决策身份由第一次时效内有效回复稳定确定。超时和请求失败用 `response --status TIMEOUT` 或 `REQUEST_FAILED` 导入，未知时钟或档位留空。`freeze` 使用原 `freeze_condition` 格式和首个可用的决策后指数采样，只有正式选中的有效 Accept 能冻结影子 episode。它仍按原短腿进入与回收规则续查。

`event` 可追加源观察时钟、可用时钟、判断时钟和写入时钟。`check` 区分确认触发、未触发和数据不足，可给出 `REVIEW_REQUIRED` 单独记录。人工导入的 AI 建议带原答复。WPEM 实盘运行过程没有接线，本地工具读取同一期路径和原冻结条件。它没有下单接口。`review` 引用已存 Outcome，勘误追加原版本身份和原因。

调度交付为可幂等执行的命令。等待授权后，可由单个操作端在 14:00 UTC 到 14:20 UTC 之间周期执行同一命令，并让同一任务随后执行 `--settle-due`。交接人工照常。在本地停止调用即可暂停。恢复时执行同一计划，它补记已过窗口的 `MISSED`，不会补发旧局。调整时间、候选或运行配置要从新生效日使用新配置和 `plan_id`。本轮没有安装、启用任何后台任务或迁移 writer。

## 核对与复用

生产归档 `astra-research-archive.service` 以 `bitnami` 运行，定时器每 10 分钟触发，现有 `_state/tick.lock` 保护旧归档。正式采样依赖这个 writer。启动观察通过工作台正常 `/case-file` 入口读取当前双侧案卷。首次读取触发既有工作台保存流程，卷宗写入本地独立目录。`astra_research_archive_v1.py` 已提供案卷、位置卡、Deribit 分钟指数和官方交割读取。本轮生成器继续用 `astra_player_input_v1.build_input`，候选绑定 `case_id`、两腿、`snapshot_id`、原生到期和读取时钟。启动探索在无对应 r2 位置卡时重用 `astra_level_behaviour_v1.build_card`，记录本地派生与缺口。原生腿资格按 `get_instruments` 校验。[Deribit 原生合约接口](https://docs.deribit.com/api-reference/market-data/public-get_instruments)

旧 `astra_player_v1` / `astra_player_rulebook.md` 由旧 tick 的可选牌手、`player-canary` 和旧回测调用。新版仍使用 2026-11-15 ARD 收口后的完整正文。本轮复用 `freeze_condition`、`compare_ard_basis`、`check_condition` 和 `astra_commercial_math_v17.inverse_*`。生产 WPEM、FMZ、归档及规则源文件保留现状。

本地卷宗按 `Deribit_BTC_到期UTC` 定位。正式 hand ID 由到期和计划槽生成，重试只在同一 hand 增加记录。探索与历史回放要求独立引用标识。episode ID 绑定 hand、正式回复和原合约。原文与本地源证据快照按字节哈希冻结，记录生成器、规则、完整输入及可得时钟。原始回复和结构化决定分别持久化。入口使用本地进程锁，崩溃后由 OS 释放，原文及证据同目录原子发布，追加事件采用独立不可覆盖的 JSON 文件。`summary.md` 和 `manifest.json` 是可重建索引。

正式到期后，`settle` 和 `tick --settle-due` 读取 Deribit 官方交割结果并保留原响应。路径、币本位终值责任、持有到期对照和实际成交各自记录。报价案卷里的顺序双腿盘口只是估计，执行净收益留空。短腿买回的会计演示在独立 fixture 中保留原买腿，分别计算短腿买回成本、买腿交割、费用和原价差持有到期。官方结算无记录时是 `UNVERIFIED`。已得到官方价格也可能缺少完整分钟路径。[Deribit 官方交割接口](https://docs.deribit.com/api-reference/market-data/public-get_delivery_prices)
