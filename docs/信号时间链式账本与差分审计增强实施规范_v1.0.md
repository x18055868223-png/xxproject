# 信号时间链式账本与差分审计增强实施规范

**版本**：v1.0
**日期**：2026-06-24
**适用工程**：`x18055868223-png/xxproject`
**交付对象**：工作 Agent、研究 Agent、审计 Agent
**当前信号层基线**：`demo/最新交付物/neutral_regulation_demo_fmz.py`，`demo_version=1.4.1`
**当前审计链路**：

```text
signal_review.jsonl
→ tools/materialize_signal_cards.py
→ signal_cards/*.json
→ 静态审计前端
→ tools/gemini_signal_llm_review.py
→ signal_llm_reviews.jsonl sidecar
```

**本轮目标**：在不改变现有信号决策、不重算因子权重、不引入交易权限的前提下，把当前“每张卡片彼此孤立”的审计模式升级为：

```text
不可变原始卡片
+
按时间链接的差分账本
+
多时间尺度趋势与异常识别
+
LLM 变化链解释 sidecar
```

从而利用已有数据获得低成本的信息增益，并为后续信号层—执行层的 `SignalContextUpdate` / `ThesisContinuity` 提供更可靠的变化上下文。

# 0. 执行摘要

## 0.1 是否值得实施

**值得，而且属于当前已有审计资产的高性价比增强。**

当前每张 `signal_review` 卡能够回答：

> 当前这一刻各传感器分别是什么状态？

但不能直接回答：

> 与上一状态相比，究竟什么发生了材料级变化？
> 变化是瞬时跳变、持续恶化，还是单次噪声？
> 系统由偏多转中性/阻断时，哪些原始变量真正重写了前提？
> 某个不投票或已排除因子，其原始状态是否正在快速恶化？
> 多个不同回路是否在时间上形成一致的风险升级链？

对于复杂多传感器系统，信息往往不仅存在于绝对值，也存在于：

\[
\Delta X_t = X_t - X_{t-1}
\]

以及：

\[
Trajectory(X) =
\{\Delta X_{t-k},\ldots,\Delta X_t\}
\]

因此，将审计卡按时间建立链接并计算结构化差分，能够显著提高：

- 状态转折识别；
- 前提持续性判断；
- 因子冲突解释；
- 风险升级预警；
- 人工阅读效率；
- 后续执行层论证连续性输入质量。

## 0.2 必须收紧的表述

时间先后和变量共同变化能够支持：

```text
状态转移链
风险传导假设
候选因果机制
```

但不能自动证明：

```text
某个因子导致了后续行情
```

例如：

```text
宏观压力暴增
→ 信号由偏多转为中性/阻断
→ 随后市场踩踏
```

这是一个有价值的候选机制链，但也可能存在：

- 共同上游冲击；
- 数据发布时间重叠；
- 宏观指标与市场同步反应；
- 信号采样间隔过长；
- 事后选择偏差。

所以所有 LLM 和前端文案必须区分：

```text
OBSERVED：已观测变化
INFERRED：基于机制的解释
HYPOTHESIS：尚未验证的因果假设
UNKNOWN：数据不足
```

## 0.3 上一条还是最近 X 条

不建议二选一。

推荐采用 **“1 + N + T + A” 四参考模型**：

```text
1：立即上一条关联记录
N：最近 5 条关联记录的轨迹
T：最近 24h / 7d 的时间窗口稳健基线
A：当前 episode 的起点锚，或最近一次材料级决策锚
```

具体作用：

| 参考 | 作用 |
|---|---|
| 立即上一条 | 识别突变和状态切换 |
| 最近 5 条 | 识别连续恶化、改善和振荡 |
| 24h / 7d | 判断当前变化是否异常，而非普通噪声 |
| episode 起点 | 衡量原始论证累计漂移了多少 |

因此不是“只比较上一条”，也不是“把最近 X 张全交给 LLM”。

正确做法是：

> 程序先计算上述四个参考的精确差异，再只把最材料的变化摘要交给 LLM。

## 0.4 推荐最终形态

新增两个独立 sidecar：

```text
signal_transition_ledger.jsonl
signal_transition_llm_reviews.jsonl
```

原始卡片保持不可变。

前端每张卡增加：

```text
变化摘要
上一状态 → 当前状态
最材料的 3—8 个字段变化
最近趋势
异常提醒
LLM 变化链解释
```

初期全部为：

```text
AUDIT_ONLY
```

不得修改：

- EDB；
- confidence；
- blocking；
- trade_allowed；
- 执行权限。

后续若验证有效，只允许将**确定性变化状态**输入执行层；LLM 文本仍保持审计参考。

# 1. 当前问题

## 1.1 单卡审计的优势

当前单卡已经提供：

- 决策；
- 支持强度；
- 置信刻度；
- 冲突比例；
- 阻断状态；
- TMV；
- 微观流；
- Macro；
- Funding；
- Gamma/GEX；
- Skew；
- 时区前提耐久度；
- LLM 盲审与复核。

这使每个时间点都可独立解释。

## 1.2 单卡审计的盲点

每张卡都是一个新页面，用户必须肉眼来回切换，才能发现：

```text
macro_score 0.0309 → 0.4588
VOLQ 150.5bp → 592.9bp
DXY 7.6bp → 14.7bp
US10Y -1.8bp → 6.2bp
Funding 0.0015% → 0.0054%
BULLISH_STRONG → NO_TRADE_BLOCKED
```

而当前系统不会主动告诉用户：

- 宏观压力累计增加了多少；
- US10Y 是否发生符号反转；
- Funding 虽未投票，但拥挤是否持续增加；
- Macro 虽被 EDB 排除，原始风险压力是否异常；
- 多个回路是否同时朝不利方向变化；
- 该变化相对于最近 24 小时是否异常；
- 这是单次跳变还是连续趋势。

## 1.3 “不投票”不等于“没有信息”

当前收口主链将部分要素降级为：

```text
NON_VOTING
EXCLUDED
GATE_ONLY
```

这是为了避免重复计权或角色越权，方向正确。

但审计层仍应比较这些原始数据。

例如：

- Macro 本轮不参与 EDB 投票；
- Funding 本轮不直接改变方向；
- GGR_SPATIAL 只作为结构门。

它们仍可能对：

```text
风险环境是否恶化
原论证是否脆弱
执行层是否应停止继续建仓
```

提供重要信息。

因此差分层必须同时记录：

```text
raw_state_change
decision_role_change
vote_change
gate_change
```

不能只比较 `vote` 或 `contrib`。

# 2. 理论依据

## 2.1 状态值和状态变化是两类信息

设目标状态为 \(Y\)，当前截面为 \(X_t\)。

单卡提供：

\[
P(Y \mid X_t)
\]

时间差分增加：

\[
P(Y \mid X_t, \Delta X_t, Trajectory(X))
\]

其中：

\[
\Delta X_t = X_t - X_{t-1}
\]

即使两个时点的绝对值都未触发硬阈值，连续变化仍可能说明：

- 风险正在积累；
- 前提正在被逐步重写；
- 多个调节回路正在趋同；
- 原本弱反证正在变成材料反证。

## 2.2 多回路系统尤其需要变化链

本项目各域对应不同机制：

| 域 | 变化链意义 |
|---|---|
| DIE + Anchor | 位移是否减弱、锚是否修复或重新受损 |
| TMV | 慢背景是否持续、减弱或反转 |
| Flow/CVD | 主动流是否被吸收、确认或背离 |
| Macro | 外生压力是否突然上升 |
| Funding | 杠杆拥挤和潜在清算燃料是否积累 |
| Gamma/GEX | 路径是否从稳定转向放大 |
| Skew | 期权尾部需求是否发生方向和强度变化 |
| 时区 | 同一变化发生在何种前提耐久环境 |

单独看每个时点容易遗漏：

```text
A 回路先恶化
B 回路随后确认
C 回路最后放大
```

而链式审计可以把它们排列为候选传导路径。

## 2.3 差分信息不能被 LLM 直接“猜”

LLM 不应自己从两张复杂 JSON 中做算术比较。

原因：

- 容易漏字段；
- 容易算错；
- 容易把显示文本当原始值；
- 容易受系统结论锚定；
- 难以保证每轮标准一致。

正确职责分工：

```text
程序：
精确取值、对齐、计算 delta、标准化、判断材料性

LLM：
解释变化可能意味着什么
指出多回路交互
列出反证和替代解释
给出后续人工观察重点
```

## 3.3 低频上下文检查点

仅依赖信号事件卡存在一个现实问题：

> 信号是稀疏、非等间隔的。

截图示例中的两张关键卡约相隔 12 小时以上。可以看出前后状态差异，但不能准确判断：


材料级触发包括：

- EDB sign/support 改变；

这使时间链更接近连续状态，而成本仍很低。

# 4. 关联规则

## 4.1 关联主键

优先使用：

```text
symbol
episode_id
strategy_version
schema_version
```

当前部分历史卡可能没有 `episode_id`，兼容期可以使用：

```text
symbol + confirmed_at 顺序
```

## 4.2 四类参考

### R1：IMMEDIATE_PREDECESSOR

同一 symbol 时间上最近的前一条记录。

用途：

- 突变；
- 决策切换；
- 符号反转；
- 新阻断。

### R2：SAME_EPISODE_PREDECESSOR

同一 episode 的前一条记录。

用途：

- 论证持续性；
- episode 内部弱化和恢复；
- 排除新 episode 的结构重置。

### R3：EPISODE_ANCHOR

当前 episode 第一条有效记录，或最近一次：

```text
TRADE_SUPPORT_STRONG
TRADE_SUPPORT_WEAK
```

的入场候选锚。

用途：

- 衡量累计漂移；
- 判断原始论证被重写了多少。

### R4：ROLLING_BASELINE

按真实时间窗口计算：

```text
6h
24h
7d
```

采用稳健统计：

```text
median
MAD
IQR
min/max
sign persistence
categorical occupancy
```

用途：

- 异常检测；
- 避免上一条本身就是异常；
- 判断当前是否处于持续趋势。

# 5. “1 + N + T + A”推荐参数

## 5.1 前端即时对比

```text
1 条 immediate predecessor
```

## 5.2 短轨迹

```text
最近 N=5 条关联事件
```

显示：

- 连续方向；
- 连续恶化次数；
- 最近 5 条的 slope；
- 反复振荡次数。

## 5.3 时间窗口

```text
6h：短期状态切换
24h：日内背景
7d：当前相对近期是否异常
```

## 5.4 LLM 输入上限

不要向 LLM发送最近 20 张完整卡。

建议只发送：

```text
当前卡摘要
上一条卡摘要
episode anchor 摘要
最近 5 条趋势统计
24h / 7d 异常统计
Top 8 材料变化
```

这样：

- 成本低；
- 信息密度高；
- 不易超上下文；
- LLM 更聚焦。

# 7. 差分计算

## 7.1 连续变量

每个字段至少输出：

```text
previous
current
delta_abs
delta_relative
sign_before
sign_after
sign_flip
elapsed_ms
```

### 相对变化限制

当 previous 接近 0 时，不使用百分比变化，避免：

```text
0.001 → 0.01 = 900%
```

造成误导。

使用：

```text
absolute delta
robust z-score
range-normalized delta
```

## 7.2 稳健异常分

\[
z_{robust}
=
\frac{x_t - median(X)}
     {1.4826 \cdot MAD(X)}
\]

若 MAD 太小，则使用：

```text
IQR / 1.349
```

仍太小时退化到绝对阈值。

## 7.3 类别变量

类别变化使用显式状态矩阵。

例如 Macro：

```text
Tailwind
→ Neutral
→ Mild Headwind
→ Headwind
```

GGR：

```text
POSITIVE_GAMMA_PINNING
→ TRANSITION
→ NEGATIVE_GAMMA_AMPLIFYING
```

不能将类别字符串简单排序。

## 7.4 距离字段

Flip、Pin、Wall 应比较：

```text
distance_to_*_pct
```

而不是只比较绝对价格，因为 BTC 价格水平会变化。

## 7.5 角色变化

每个因子同时记录：

```text
ACTIVE
NON_VOTING
EXCLUDED
GATE_ONLY
MISSING
```

示例：

```text
MACRO:
role ACTIVE → EXCLUDED
raw score 0.0309 → 0.4588
```

这不等于“Macro 没有信息”，而是：

```text
方向投票被关闭
但原始宏观压力显著增加
```

# 8. 材料性评分

## 8.1 单字段材料性

```python
field_materiality =
    absolute_threshold_component
    + robust_anomaly_component
    + sign_flip_component
    + categorical_transition_component
    + freshness_component
```

输出：

```text
NONE
LOW
MEDIUM
HIGH
CRITICAL
```

## 8.2 域级材料性

同一域多个字段合成：

```text
MACRO_SHOCK
FUNDING_CROWDING_ESCALATION
FLOW_CONFIRMATION_LOSS
GAMMA_REGIME_SHIFT
SKEW_REVERSAL
ANCHOR_REBREAK
```

## 8.3 跨域趋同

当至少两个独立回路同时朝同一风险方向变化：

```text
MULTI_DOMAIN_CONVERGENCE
```

例如：

```text
Macro 压力大幅上升
+
Funding 多头拥挤增加
+
GGR 从稳定转 Transition
```

比单一字段变化更值得人工关注。

## 8.4 初始阈值政策

第一版阈值只用于：

```text
审计排序
LLM 调用触发
前端提醒
```

不得用于交易门。

阈值应满足：

```text
绝对下限
OR
近期 robust z 异常
```

避免只用固定数值，也避免只用样本标准化。

## 11.2 后一状态

约 2026-06-23 02:09：

```text

NO_TRADE_BLOCKED

regime Mild Headwind
score 0.4588
VOLQ 592.9 bp
DXY 14.7 bp
US10Y 6.2 bp

0.0054%
```

## 11.3 确定性差分

```text

+0.4279

VOLQ:
+442.4 bp

DXY:
+7.1 bp

US10Y:
+8.0 bp
并发生 -1.8 → +6.2 的符号反转

Funding:
+0.0039 个百分点
仍未跨越 0.01% threshold

Decision:
BULLISH_STRONG → NEUTRAL
TRADE_SUPPORT_STRONG → NO_TRADE_BLOCKED
```

## 11.4 合理审计结论

可以说：

> 在约 12 小时的事件间隔内，宏观压力从接近中性跃迁到 Mild Headwind，其中 VOLQ 是最大增量来源，DXY 和 US10Y 同向增加，US10Y 还发生压力方向反转；同期系统由强偏多转为中性阻断。Funding 拥挤有所抬升，但仍低于直接投票阈值。

不能直接说：

> VOLQ 导致了后续崩盘。

更准确的候选机制：

```text
外生波动压力快速抬升
+
美元/利率压力转强
→ 原偏多论证的前提耐久性下降
→ 系统停止支持交易
→ 后续市场出现与风险压力一致的下行重定价
```

替代解释：

- 宏观代理和 BTC 同时响应共同冲击；
- 两张卡间隔较长；
- 中间转折未被现有信号卡捕捉；
- Macro role 被排除，系统阻断可能还来自其他因素。

## 11.5 对系统建设的直接启示

若有 15 分钟紧凑检查点，系统可以进一步回答：

```text
VOLQ 是何时开始加速？
DXY/US10Y 是否同步？
Funding 是领先、同步还是滞后？
GGR 是否在价格下跌前进入 Transition？

```

这正是链式审计相比单卡审计的增量。

# 24. 最终建议

这项增强值得实施，但应当理解为：

> **从“截面审计”升级为“状态转移审计”，而不是让 LLM 代替因果研究。**

推荐第一版立即做：

```text
上一条关联记录
+
最近 5 条轨迹
+
24h 稳健基线
+
episode 起点
+
确定性差分
+
材料事件 LLM 解释
```

不要只比较上一条，因为：

- 上一条可能本身异常；
- 信号间隔不固定；
- 无法判断趋势。

也不要直接把最近 X 张完整卡交给 LLM，因为：

- 成本高；
- 噪声大；
- 数值计算不可靠；
- 容易结论漂移。

最优结构是：

```text
程序将时间序列压缩成精确的变化事实
→ LLM解释这些事实的机制含义
→ 人工在前端阅读
→ 后续通过事后结果标注验证增量价值
```

截图中的 6 月 22 日至 6 月 23 日变化，正是该设计能够捕捉的典型案例：

```text
原偏多论证
→ 宏观压力显著跃迁
→ 多个外生压力项同向变化
→ 系统支持坍塌并进入阻断
→ 后续市场出现风险重定价
```

当前单卡审计只能分别展示前后两张卡；时间链审计能够主动把它们组织成一个可检查、可验证、可继续研究的状态转移过程。

**建议将本模块命名为 `Signal Trajectory Audit`，第一阶段严格保持审计旁路，验证后再把确定性连续性状态接入执行层。**
